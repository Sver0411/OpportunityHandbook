## 三、P0：交叉链接全部失效（最该先改的一件）

### 现象

正文里大量出现这种写法：

```
- [认识你面前的几条主要路线](#01-先决定下一步往哪里走)
- [继续读书](#paths-continue-study-default)        ← 指回自己
- [竞赛](#03-做项目、打比赛、进实验室)
```

`#01-先决定下一步往哪里走` 用的是**文件名**，而章节标题的 H1 是「先决定下一步往哪里走」。构建产物里从头到尾不存在 `id="01-先决定下一步往哪里走"`，所以这些链接全部落空。

### 点下去会发生什么

`site/app.js` 的点击处理只在锚点存在时才拦截：

```js
var target = document.getElementById(name);
if (target && main.contains(target)) { event.preventDefault(); jumpToHeading(target); }
```

锚点不存在 → 不拦截 → 浏览器改写 `location.hash` → 触发 `hashchange` → `route()` → `parts[0]` 既不是 `browse` 也不是 `doc` → 落到兜底分支 `readerUI.handle(["guide","missing"])` → `site/reader.js` 渲染：

```
找不到这个入口 / 从目录继续查找 / 这个分组可能已经调整。
```

**也就是说：读者正在读一篇，点了一个「相关内容」，直接被踢到错误页。** 这不是「点了没反应」，是比没反应更差的结果。

### 规模

| 失效锚点 | 源文件出现 | 线上渲染 |
| --- | ---: | ---: |
| `#04-升学、就业还是出国` | 18 | 54 |
| `#03-做项目、打比赛、进实验室` | 11 | 33 |
| `#02-在学校里先把基础打好` | 10 | 30 |
| `#06-从学校走向第一份工作` | 8 | 24 |
| `#01-先决定下一步往哪里走` | 8 | 24 |
| `#08-晋升、跳槽还是转行` | 7 | 21 |
| `#07-从新人到能独立负责` | 4 | 12 |
| `#05-备考与应试` | 1 | 3 |
| `#09-自由职业、副业与创业` | 1 | 3 |
| **合计** | **68** | **204** |

出现在 19 个页面文件上（章节页 + 条目页）。平均下来，**每两个条目就有一个「相关」区块含失效链接**。

顺带确认：**「本章分组」锚点表是好的**。`## 本章分组` 里的链接全部指向章内真实分组标题（如 `#认识你面前的几条主要路线` 确实存在于产物里），17 章 × 数十条，没有一条失效。**失效的只有「相关」区块和正文里"见 […]"这类章节级跳转。**

### 正确的目标是什么

两种改法，取决于想要的交互：

1. **想跳到章内某个分组** → 用分组标题锚点，例如 `#01-先决定下一步往哪里走` → `#认识你面前的几条主要路线`；`#03-做项目、打比赛、进实验室` → 对应分组名。
2. **想跳到整章** → 用路由地址 `#/doc/book/01-先决定下一步往哪里走` 或 `#/chapter/…`，交由前端解析。

同一轮要补的门禁：`tools/check_html_ids.py` 目前只查重复 id 与条目前缀，**应加一条「页内 `#锚点` 必须能在同页找到目标」**，否则这次的错会再犯一次。

### 同型候选 14 条（结构一致，建议逐条确认）

判定依据：后半段的若干小标题与前半段某个小标题用词高度重合（自动比对，阈值 0.5），例如「什么时候应该退出」对「什么时候值得深入投入」、「报考资格要逐校核实」对「报考条件（逐条核对）」、「三个信号」对「四个时机信号」。

**这不是「内容不够」，而是「同一份内容存了两版」**：读者读到一半会以为翻回了上一页，信任感是往下走的。修法通常是二选一——保留信息更全、格式更好的一版，把另一版里独有的信息点并进去；不要两版都留。

## 六、P2：体例与篇幅

### 收尾小节命名有 290 种

内容导语里把「哪些情况下应该谨慎」当成卖点写进了 `guide-how-to-use`（「『哪些情况下应该谨慎』往往比『怎么做』更值得先读」）。但实际命名是：

| 收尾小节名 | 条目数 |
| --- | ---: |
| 什么时候要谨慎 | 90 |
| 常见误区 | 22 |
| 一个提醒 / 边界 / 成本与边界 / 两个边界 / 什么时候该停 / 几个容易踩的坑 / 三个容易被忽略的点 … | 其余约 305 条，几乎一条一个名字 |

读者没法形成「翻到篇末就看边界」的扫读习惯。建议统一到一个主名字（「什么时候要谨慎」），把「常见误区」等并入或固定为它的二级。

### 偏薄条目约 25 条

正文去空白字符数 < 560 的有 25 条。其中多数是**概念型条目**，短是合理的（`opensource-pr` 514、`project-code-review` 440、`career-management-track` 488、`overseas-sop-ps` 499、`research-ra` 360）。真正值得补的是判断型条目：

- `overseas-research-proposal`（428）、`research-recommendation-letter`（416）、`study-retake-exam`（494）——都是需要读者做判断的题，篇幅偏紧。

## 七、P2：门禁缺口

`tools/run_tests.py` 76 项全绿，`tools/check_links.py` 外链 FAIL 0 —— 但 204 处断链一个都没被拦住，原因很明确：

| 工具 | 查什么 | 是否覆盖页内锚点 |
| --- | --- | --- |
| `check_links.py` | 外链可达性 | 否（只查 http(s)） |
| `check_html_ids.py` | 重复 id、条目 heading 前缀 | 否（不查 `#锚点` 是否有目标） |
| `check_semantic_links.py` / `check_ia.py` | IA 挂载与条目归属 | 否 |

**建议补一条构建期校验**：扫描 `site/**/*.html` 里所有 `href="#xxx"`（排除 `#/` 路由），要求同页或全站存在 `id="xxx"`；不达标即失败。本轮扫描脚本的逻辑可直接复用，成本很低。

## 八、对四个审查维度的直接回答

### 1. 实用性——合格，个别条目偏薄

抽查的每一条都给了可执行动作与可核对的门槛，例如：

- 「在招聘平台抽二三十条目标岗位，统计『学历要求』一栏」（`paths-continue-study-default`）
- 「不超 X，且不借贷」「连续两个月睡眠与情绪明显受损」（`decide-when-to-stop` 的四条止损线）
- 「每天两小时通勤，一年约 500 小时」（`choose-city`）
- 「连续 20 份无任何回复：先补一个可展示的项目，再继续投」（`internship-how-to-find`）
- 「状态不好连续两周以上，且已影响睡眠、吃饭、上课/上班」（`health-mental-support` 的求助判断线）

这些不是「要多思考」「要努力」式的表述，是可以当天动手或当天核实的。**结论：不是大道理，是操作手册式的内容。**

### 2. 动线——入口做得足，链接断了

入口层做得相当完整：README 的「你可以直接从这些问题开始」（约 50 个问句）、00 章的「先花 30 秒」分流表（17 种处境 → 读哪两篇 → 读完做一件事）、18 章内容地图、以及各章章首的「本章分组」锚点表。**这四层入口本身都是通的。**

问题出在**第四条边**：条目之间互相串联的链接是断的。读者顺着「相关」往下走的时候会掉出去，而这本书的定位恰恰是「地图」——地图上的路标指错，比少几个路标更伤。

### 3. 完整度——覆盖面足够，缺的是「内部一致性」

417 条覆盖了升学（含中职/专科/专升本/保研/考研/出国/读博/工作后再读书）、科研、项目与竞赛、开源、实习求职、考公考编、职场成长、转行、自由职业与创业、钱与社保、身体与心理、劳动权益、避坑 15 类；`docs/` 另有 106 个按类型查阅的独立入口，11 个国家和地区的「制度 + 申请」双页，18 条时间线。

**没有发现明显的内容空洞**。更值得处理的是上面的 P0/P1：链接断、内容重。也就是说，**这本书现在缺的不是新条目，是把已有条目的重复与断链清掉。**

### 4. 是不是空话——不是

空话句式全库仅 3 处命中，且多为否定式使用。相对最抽象的是 00 章的两篇导语（`guide-how-to-use`、`guide-no-single-path`），其中「人生并不是只有一条标准路线」最接近「大道理」；但它在文内立刻把话题拉回可操作处（「非标准路线的真实代价：解释成本更高、试错时间更长、有些制度性安排还会真的卡住时间」），并给了 A/B 对照。放在方法章的语境里可以接受，若要再收紧，可把「为什么时间表不可靠」的抽象表述换成一条可核对的制度约束（如应届身份的时限）。

## 九、建议的修改顺序（本轮不执行）

1. **修 68 处章节级交叉链接**（对应线上 204 处）——改锚点或改路由，同时补页内锚点校验门禁。这是唯一一个「读者每次使用都会撞到」的问题。
2. **清掉 10 处自链接**。
3. **合并 6 条确认的双稿条目**，并逐条确认 14 条同型候选。合并时注意保留信息量更大的一版，把另一版独有的事实并进去（例如 ATS 的「一页 / 两页」与「一分钟 / 30 秒」两处数字冲突必须在合并时定稿）。
