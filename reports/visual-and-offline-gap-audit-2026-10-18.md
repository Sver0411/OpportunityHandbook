## 三、视觉：0 张图，缺的位置很具体

### 3.1 现状

- 全书没有一张图。不是「图少」，是**一张都没有**。
- 站点没有 `og:image`。转发到微信 / 小红书 / QQ 时是一张纯文字卡片，没有缩略图；浏览器标签页没有图标。
- 全库出现「截图」45 处，但**全部是让读者自己去截图留证**（报名截图、缴费凭证、学历学籍截图），没有一处是给读者看的图。

### 3.2 哪些内容真的需要图（不是装饰）

按「文字已经写得很清楚，但读者仍要在大脑里做空间推理」来筛，只有三类：

**① 分流与决策（最该先做）**
00 章第一屏就是一张 26 行的分流表，18 章内容地图是 13 个栏目 × 每栏一张表。读者要在表里逐行找自己像哪一行。
这类内容的天生形态是**判断树**：先问「你现在是在校还是在工作」，再问「你手上有没有已经到手的 offer」，两三个问题落到具体条目。表格是判断树压扁之后的产物，读者要自己做还原。

**② 时序与流程**
「从报名到上岸的完整流程」「秋招时间线」「留学申请排期」现在都是「阶段 / 时间 / 要做什么 / 从哪确认」的四列表。
时间这件事，一条横轴比四列表好读得多——尤其是「哪几件事在同一周撞车」这种信息，表格里根本看不出来。

**③ 结构对比**
「判断一个选择值不值得」的四步框架、「实习的四种关系差别很大」、「Offer 怎么比较」的四列——都是 4–6 列的多维对比。
全库 52 行落在 ≥5 列的表格里，手机端表格 `min-width: 540px`，靠横滑 + 一行「左右滑动查看完整表格」的提示。在手机上读 5 列表是最难受的阅读姿势，这类内容更适合做成并排卡片或矩阵图。

### 3.3 不建议做的

- **装饰性插画 / AI 生成的「大学生在图书馆」配图**：与这本书「不承诺、不煽动」的调性相反，还会拖慢首屏。
- **官方页面原始截图**（研招网、学信网、省考试院）：页面会改版，截图一过期就变成错误信息，和「会过期就标日期」的约定冲突；还有版权与反爬（`nhc.gov.cn` 已实测 412）。
- 如果确实要解决「那个按钮在哪」，正确做法是**重绘示意 + 编号标注 + 附官方链接 + 标注核实日期**，而不是截图。

## 四、引导：不缺「入口」，缺「被问一句」

### 4.1 已经有的

| 已有 | 规模 | 形态 |
| --- | --- | --- |
| 00 章「先花 30 秒」 | 26 行 | 表格：你现在的情况 → 先读这两篇 → 读完做一件事 |
| 18 章内容地图 | 13 个栏目 | 每栏一张「情况 → 入口 → 动作」表 |
| `reader/overviews/` | 20 篇 / 108KB | 文字导读，内嵌 `#/guide/` 与 `#/doc/` 链接 |
| `#/browse` | 431 条 | 按阶段 / 方向筛选 |
| 每条 meta | 431 条 | 证据类型、投入、最后核实日期 |

这套东西比大多数同类项目完整。问题不在「有没有」，在**形态**。

### 4.2 具体的三个断点

**断点一：第一屏是一张 26 行的表。**
新读者打开首页，看到的是一张需要自己逐行匹配的表。26 行里找「我像哪一行」，比回答两个问题难。这正是「只给一个表格」这种感觉的来源——不是内容不够，是**入口要求读者先自我归类**。

**断点二：没有「下一步」按钮。**
条目内部有大量交叉链接（284 处官方外链、成百的章内锚点），但读者读完一条之后，没有「这条读完了，接下来该做哪件事 / 读哪条」的显式出口。00 章给了「读完做一件事」，但只覆盖分流表里的 26 种情况，其余 400 多条没有对应的下一步。

**断点三：没有进度与收藏。**
754k 字、1500 分钟的量级，读者一定是分多次回来读的。现在关掉页面再回来，只能靠搜索或重新翻目录。没有「我读过哪些」「我标了哪三条」。

## 五、可带走：0 下载物，且不能打印

### 5.1 现状

- 仓库内没有任何 pdf / epub / docx / xlsx / zip。
- 站点没有任何 `@media print` 规则。直接按 Ctrl/Cmd+P，会把顶栏、页脚、可能的左栏一起打出来，没有分页控制、没有页码、没有「链接地址展开」。
- 46 个模板（`docs/tools/`）全部是 Markdown 空表格。在网页上渲染出来就是**一堆不能输入的空单元格**——这正是你说的「只给一个表格」。

### 5.2 这件事在真实场景里损失什么

| 场景 | 现在会怎样 |
| --- | --- |
| 打印下来带去和家长 / 老师谈 | 排版失控，长表格被切断，页脚跟着每一页 |
| 地铁 / 飞机上没网 | 完全读不了 |
| 发到班级群 / 给同学 | 只能发链接，对方点进来还是要在站里找 |
| 面试前想打印一张 checklist | 得自己复制粘贴再排版 |
| 想填「机会价值判断表」 | 只能自己新建一个文档重新画表 |

### 5.3 成本其实不高

`site/chapters/` 里 68 个章节页已经是**服务端渲染的完整全文**（116–168KB/页，含 `<p>` 与表格）。也就是说，「打印这一章 / 存成 PDF」不缺内容源，缺的只是一段 print 样式和入口。同理，46 个模板转成 xlsx / docx 是纯格式转换，不需要重写内容。

## 六、优先级

按「读者真的会用到」而不是「看起来完整」排序：

| 级别 | 事项 | 为什么排这个位置 | 改动面 |
| --- | --- | --- | --- |
| P0 | 打印样式 + 「打印 / 存 PDF」入口（先做单条与单章） | 一次性解决纸质、离线、转发三个场景；内容源已存在 | 一个 CSS + 一个按钮 |
| P0 | 46 个模板给出可填版本（xlsx 优先，docx 次之） | 直接消灭「只给一个表格」的观感；模板本来就是给人填的 | 纯格式转换 |
| P1 | 分流入口从「26 行表」改成「两三个问题」 | 决定新读者 30 秒内走不走 | 需要一层交互与文案重写 |
| P1 | 三类图：判断树、时序轴、多维对比矩阵（各 3–5 张，优先 00/04/05/06 章） | 图只放在文字确实吃力的地方，不做图库 | 需要设计与校对，容易做歪 |
| P1 | `og:image` + favicon | 转发无图的损失是每天都在发生的，且几乎零维护 | 一张 1200×630 静态图 |
| P2 | 阅读进度与收藏（本地存储即可，不需要账号） | 1500 分钟的量级下，回访成本高 | 前端状态 |
| P2 | 每条末尾给「下一步」出口 | 431 条逐条写，工作量大，可先覆盖高频 50 条 | 编辑工作 |
| — | 装饰性插画、官方页面原始截图 | 与调性冲突 / 会过期 | 不建议 |
