# 标题层级修复（2026-10-12）

问题（用户反馈）：标题不够大、不够明显，**有些标题比正文字号还小**。

用无头 Chrome 实测计算字号后确认，问题有两处，都是真实的：

| 元素 | 修复前（桌面 / 移动） | 问题 |
| --- | --- | --- |
| 文档标题 h1 | 34 / 27 px | 与分组标题差距偏小 |
| 章节分组 h2 | 24 / 21 px | 与正文 17 px 拉开了，但与条目内小节同级 |
| **条目标题 h3** | **20 / 18 px** | **比自己条目内的小节还小** |
| **条目内小节 h2** | **24 / 21 px** | **比条目标题大 → 层级倒挂** |
| 正文 | 17 / 16.5 px | — |
| 条目内 `###`（h4） | **16 px** | **比正文还小** |

## 修复后的阶梯

| 元素 | 桌面 | 移动 | 说明 |
| --- | --- | --- | --- |
| 文档标题 h1 | 36 px | 28 px | 字重 700 |
| 章节分组 h2 | 27 px | 22 px | 字重 700，保留上方分隔线 |
| 条目标题 h3 | 23 px | 20 px | 字重 700，保留左侧强调线，间距加大到 48 px |
| 条目内小节 h2 | 20 px | 18.5 px | 字重 680，去掉分组分隔线（视觉上明确低一档） |
| 条目内 `###`（h4） | 17.5 px | 17 px | 不再小于正文 |
| 正文 | 17 px | 16.5 px | 不变 |

做法：把字号提为 CSS 变量（`--fs-h1 / --fs-h2 / --fs-entry / --fs-h3 / --fs-h4`），
分组标题与条目内小节用不同选择器区分（`.doc > h2` vs `.doc .entry h2`），
并在 ≤900px 断点整体缩小一档但保证任何标题都不小于正文。

## 验证（不是目测，是实测）

新增 `tools/probe_typography.py`：用无头 Chrome 打开真实页面，读
`getComputedStyle().fontSize`，覆盖「书章条目页」与「文档页」× 「桌面 1280×900」
与「移动 390×844」四种组合，并断言：

- 任何标题 ≥ 正文；
- 正文 < 条目内小节 < 条目标题 < 分组标题 < 文档标题。

实测结果（四种组合全部通过）：

```
书章条目页 · 桌面：正文 17px < 条目内 ## 20px < 条目标题 23px < 分组 27px < h1 36px
书章条目页 · 移动：正文 16.5px < 条目内 ## 18.5px < 条目标题 20px < 分组 22px < h1 28px
文档页 · 桌面：  正文 17px < ### 小节 20px < h2 27px < h1 36px
文档页 · 移动：  正文 16.5px < ### 小节 18.5px < h2 22px < h1 28px
```

改前 / 改后对比截图见 [`reports/evidence/`](evidence/)：
`typography-before.png`（可见「两种作用：门槛与信号」比条目标题还大）、
`typography-after.png`（层级恢复：分组 > 条目标题 > 条目内小节 > 正文）。
