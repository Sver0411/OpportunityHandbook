# 元数据规范

正文只以 Markdown 为准，不另外维护第二份正文。筛选与搜索需要的结构化信息，通过两处元数据表达：

1. **文件级**：文件开头的 YAML front matter（章节、专题文档、规范文档）。
2. **条目级**：`### 标题` 下的 ```meta 代码块。

构建工具读取这两处，生成 `site/data/index.json` 与静态 HTML。Markdown 改完重新构建，页面即更新。

## 文件级 front matter

```yaml
---
id: chapter-03-further-study   # 全仓库唯一
title: 升学                     # 与文件名语义一致
type: chapter                  # intro | chapter | doc
section: countries             # type=doc 时的所属专题目录；meta/ 下的规范文档填 meta
order: 3                       # 章序号或专题内排序
stages: [undergraduate, new_grad]
topics: [study]
summary: 一句话说明这一章/这篇文档解决什么问题
last_verified: 2026-09-21
---
```

## 条目级 meta 块

```meta
id: grad-school-worth-it
status: complete
stages: [undergraduate, new_grad, work_1_3]
topics: [study]
outputs: [degree, qualification, optionality]
effort: high
evidence: [official, industry_data, experience_based]
last_verified: 2026-09-21
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 必填 | 条目锚点，全仓库唯一。小写字母、数字、连字符。站内链接用它，例如 `03-升学.md#grad-school-worth-it`。 |
| `status` | 必填 | `complete` 已写完 / `todo` 仅占位 / `needs_review` 待复核。只有 `complete` 进入搜索索引。 |
| `title` | 可选 | 默认取 `### ` 标题文本。若填写必须与标题完全一致（构建时校验）。 |
| `stages` | `complete` 必填 | 人生阶段，见下表。可以多选。 |
| `topics` | `complete` 必填 | 方向分类，见下表。 |
| `outputs` | `complete` 必填 | 能换回什么。 |
| `effort` | `complete` 必填 | 投入强度：`low` / `medium` / `high`。 |
| `evidence` | `complete` 必填 | 证据类型，见《证据与来源规范》。 |
| `last_verified` | `complete` 必填 | `YYYY-MM-DD`。 |
| `kind` | 可选 | `entry`（默认）或 `question`。`question` 用于《从这里开始》的问题入口。 |
| `link` | `kind=question` 必填 | 指向被引条目的 `id`，构建时校验其存在。 |
| `aliases` | 可选 | 额外搜索词，例如 `[“读研”, “考研”, “研究生”]`。 |

## 取值枚举

### stages 人生阶段

| 值 | 显示 |
| --- | --- |
| `highschool` | 高中 |
| `secondary_vocational` | 中专 / 职校 |
| `college` | 专科 |
| `undergraduate` | 本科 |
| `master` | 研究生 |
| `phd` | 博士 |
| `new_grad` | 应届 |
| `work_1_3` | 工作 1–3 年 |
| `work_3_5` | 工作 3–5 年 |
| `senior` | 资深 |
| `career_change` | 转行 |

### topics 方向

`study` 升学 · `job` 工作 · `research` 科研 · `competition` 竞赛 · `project` 项目 · `skill` 技能 · `funding` 资助 · `community` 社群 · `startup` 创业 · `explore` 探索

### outputs 能换回什么

`degree` 学历 · `qualification` 资格 · `income` 收入 · `work_experience` 工作经历 · `research_experience` 科研经历 · `portfolio` 作品 · `project` 项目 · `paper` 论文 · `recommendation` 推荐信 · `award` 奖项 · `public_contribution` 公开贡献 · `network` 人脉 · `reputation` 声誉 · `leadership` 领导力 · `optionality` 选择权

### effort 投入

`low` 低 · `medium` 中 · `high` 高

### evidence 证据类型

`official` · `research_backed` · `industry_data` · `experience_based` · `uncertain`，定义见《证据与来源规范》。

## 术语表与显示名

枚举的显示名（中文标签、排序）集中定义在 `tools/meta.py` 的 `FACETS` 中，构建时写入 `site/data/index.json` 的 `facets` 字段。网页只读取这份定义，不在前端重复维护一份映射。

## 为什么不把元数据写进正文可见字段

条目格式里的「能换回什么」「要付出什么」是写给读者的人话（含细节、条件、例外），而 meta 块里的 `outputs`、`effort` 是给机器筛选用的枚举。两者有意分开：写正文时不必迁就枚举，筛选时也不依赖自然语言的解析。
