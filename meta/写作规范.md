# 写作规范

## 语气

直接、清晰、中立、具体、克制。

- 直接：第一句就给结论。
- 中立：不推销任何一条路。考公和创业、读博和工作，都要写清各自的适用条件。
- 具体：写“给 20 个目标岗位的招聘页截图存档”，不写“做好职业规划”。
- 克制：不夸张、不用力过猛、不站在道德高地上教育读者。

## 禁止表述清单

开头套话：

```
在当今快速发展的时代
随着社会不断发展
这是一个非常重要的问题
众所周知
不可否认
```

推销式措辞：

```
毫无疑问
强烈推荐
绝对应该
必须
改变命运
逆天改命
弯道超车
人生赢家
```

空洞动词：

```
赋能
闭环
抓手
打法
升维
破圈
```

模糊量词：

```
很多人
大多数情况下
一般来说
大幅提升
显著改善
性价比极高
```

（最后三类的替代方案：给出具体条件、具体数量或明确标注“经验判断”。）

## 排版约定

- 正文文件从 `# 一级标题` 开始，下属 `### 三级标题` 就是条目，条目之间不再插 `##` 二级标题，除非确实需要分组。
- 中文与英文、数字之间加一个空格：`2–3 年`、`GitHub 项目`、`Offer 比较`。
- 数字范围用短横线 `2–3`，年份与日期用 `2026-09-21`。
- 列表用 `-`，不用 `*`。有序步骤用 `1.`。
- 代码块不用于装饰；引用原文时才用引用块。

## 内部链接

跨文件引用条目时，链接格式为「相对路径 + 条目 id 锚点」，并且链接文字本身就是目标标题：

```markdown
见 [怎么判断"读研值不值得"](03-升学.md#grad-school-worth-it)
```

规则：

1. 锚点用条目的 `id`，不要用中文标题（中文标题改一次，锚点就断一次）。
2. 链接文字必须能独立读懂：即使在不支持锚点的地方（例如 GitHub 的 Markdown 预览），读者也知道指的是哪一条。
3. 构建工具会校验目标文件存在、锚点存在，并在站点中把链接重写为站内路由。
4. 引用同一条目两次以上，说明它应该被拆出来或合并，先检查是否重复。

## 反重复

同一个结论只在一个地方详细写，其他地方引用它：

- 判断框架写在第 02 章。
- 证据状态定义写在《证据与来源规范》。
- 证书五分类写在第 11 章。

交叉引用优于复制粘贴：复制出来的内容会随时间分叉，引用不会。
