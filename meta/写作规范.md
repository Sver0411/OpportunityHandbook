# 写作规范

## 语气

直接、清晰、中立、具体、克制。

- 直接：第一句就给结论。
- 中立：不推销任何一条路。考公和创业、读博和工作，都要写清各自的适用条件。
- 具体：写“给 20 个目标岗位的招聘页截图存档”，不写“做好职业规划”。
- 克制：不夸张、不用力过猛、不站在道德高地上教育读者。

## 禁止表述清单

开头套话：

```
在当今快速发展的时代
随着社会不断发展
这是一个非常重要的问题
众所周知
不可否认
```

推销式措辞：

```
毫无疑问
强烈推荐
绝对应该
必须
改变命运
逆天改命
弯道超车
人生赢家
```

空洞动词：

```
赋能
闭环
抓手
打法
升维
破圈
```

模糊量词：

```
很多人
大多数情况下
一般来说
大幅提升
显著改善
性价比极高
```

（最后三类的替代方案：给出具体条件、具体数量或明确标注“经验判断”。）

## 排版约定

- 正文文件从 `# 一级标题` 开始，下属 `### 三级标题` 就是条目，条目之间不再插 `##` 二级标题，除非确实需要分组。
- 中文与英文、数字之间加一个空格：`2–3 年`、`GitHub 项目`、`Offer 比较`。
- 数字范围用短横线 `2–3`，年份与日期用 `2026-09-21`。
- 列表用 `-`，不用 `*`。有序步骤用 `1.`。
- 代码块不用于装饰；引用原文时才用引用块。

## 内部链接

跨文件引用条目时，链接格式为「相对路径 + 条目 id 锚点」，并且链接文字本身就是目标标题：

```markdown
见 [怎么判断"读研值不值得"](04-当你开始面对第一次重要分流.md#grad-school-worth-it)
```

规则：

1. 锚点用条目的 `id`，不要用中文标题（中文标题改一次，锚点就断一次）。
2. 链接文字必须能独立读懂：即使在不支持锚点的地方（例如 GitHub 的 Markdown 预览），读者也知道指的是哪一条。
3. 构建工具会校验目标文件存在、锚点存在，并在站点中把链接重写为站内路由。
4. 引用同一条目两次以上，说明它应该被拆出来或合并，先检查是否重复。

## 反重复

同一个结论只在一个地方详细写，其他地方引用它：

- 判断框架写在第 02 章。
- 证据状态定义写在《证据与来源规范》。
- 证书五分类写在第 11 章。

交叉引用优于复制粘贴：复制出来的内容会随时间分叉，引用不会。

## book 与 docs 的分工

- `book/` 只写**判断、方法、路线与决策框架**：这类内容存在版本差异时按人写（“适合谁 / 不适合谁”）。
- `docs/` 只写**参考资料与专题细化**：时间线、国家与地区、行业、模板与工具。
- `docs/` 里不要重复 `book/` 已经给出的判断；需要时引用主指南条目，并在页面开头注明“本页是专题资料，判断与方法见主指南”。
- 尚未撰写的文档用 `status: planned` 标记：它们不进导航、搜索与筛选，只在 `docs/ROADMAP.md` 里汇总。

## 文章结构（2026-09 更新）

正文不再是「十个固定字段」，而是**按问题组织的文章**：

- 开头一段说清这篇在回答什么问题，以及为什么它值得先算清楚。
- 中间的小标题由内容决定：可以是判断步骤、可以是分类、可以是「哪些情况下应该谨慎」。
- 结尾统一写 `## 来源与更新`：`最后核实：YYYY-MM-DD`，然后逐条列出来源并标注证据类型。
- 「不太适合谁」这类信息继续写，但写成文章里的段落或小标题，不再要求固定栏目名。
- 判断必须能被反驳；事实必须能给出来源；两者不要混在一句话里。

## 标题层级约定（重要）

正文里有两层「二级标题」，用途不同，必须区分：

| 写在哪 | 作用 | 判别方式 |
| --- | --- | --- |
| `## 分组标题`，**后面直接跟条目**（`### 标题`）或另一个分组 | 章节内的分组，决定左栏与页内目录的第二层 | 它的下一个非空行是 `### ` 或 `## ` |
| `## 小节标题`，**后面写正文** | 文章内部的小节，由作者按问题自己组织 | 它的下一个非空行是段落、列表或引用 |

反过来说：**文章小节后面一定要有正文**，否则构建工具会把它当成章节分组，后面的内容就会被切出去。
`### 标题` + ```meta 块是文章的唯一开始标记，文章内部的 `##` 不会结束这篇文章。

## 结尾与来源

每篇文章结尾统一写：

```markdown
## 来源与更新

最后核实：2026-09-21

- 来源名称：链接或说明 （Official / Research-backed / Industry-data / Experience-based / Uncertain）
```
