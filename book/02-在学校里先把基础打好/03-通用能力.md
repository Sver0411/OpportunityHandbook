# 通用能力

### 信息检索

```meta

status: complete

effort: low

summary: 信息检索怎么练：先分清要找什么类型的信息、常用检索语法、判断来源可靠性的方法与保存习惯。
last_verified: 2026-09-21
```

检索能力的差别不在「会不会用搜索框」，而在**能不能在十分钟内定位到权威答案并判断它是否可信**。

## 先分类：你要找的是哪种信息
| 类型 | 例子 | 优先去的地方 |
| --- | --- | --- |
| 规则与政策 | 报名条件、签证要求、资助义务 | 主管部门官网、官方系统 |
| 原始数据 | 统计数字、行业规模 | 统计局、行业协会、官方报告 |
| 学术事实 | 某方法的效果、某现象的机制 | 论文与综述（看预印本时注意未评审） |
| 现状与经验 | 岗位日常、团队氛围 | 从业者访谈、招聘 JD、社区讨论 |
| 操作方法 | 某个工具怎么用 | 官方文档（教程容易过期） |

**先分类能避免一个大坑**：用社区帖子回答规则问题，或用官方文件回答体验问题。

## 检索的具体技巧
- **关键词用术语而不是口语**：「学生签证 打工 时数 限制」比「留学能不能打工」更容易命中官方页面；
- **限定站点**：在搜索框里加 `site:gov.cn`、`site:edu.cn` 或用搜索引擎的站点筛选，直接过滤掉营销内容；
- **限定文件类型**：加入 `filetype:pdf` 常能直接找到官方文件；
- **中英双语试**：技术类问题用英文术语通常命中更快、更准；
- **顺着引用找**：找到一篇好材料，去看它引用的原始来源。

## 判断来源是否可信
1. **谁发布的**：机构全称、域名是否与机构匹配；
2. **什么时候**：政策与数据必须看发布日期与生效日期；
3. **口径是什么**：数据要问样本、范围、统计方式；
4. **有没有利益关系**：培训机构、中介、厂商的内容要打折看；
5. **能否交叉验证**：至少两个独立来源（其中一个最好官方）。

## 保存与复用
- 收藏时**同时记下「它回答了什么」**，否则一周后仍然要重读；
- 保留链接 + 查看日期，方便下次核对是否更新；
- 用过的好来源按主题归到一处（笔记或书签文件夹），形成自己的常用入口；
- 官方入口清单见 [常用官方来源清单](../../docs/sources/常用官方来源清单.md)。

## 三个习惯
- **先问「谁发布」**：招生政策找教育考试院与学校官网，考试规则找主办方，统计数据找统计部门。搜到任何二手文章，都顺手找出它引用的原始出处；
- **看时间**：政策文件每年都在变，两年前的攻略可能已经失效，发布日期是第一道过滤器；
- **看适用范围**：很多文件只适用于特定省份、特定年份、特定批次，套错对象是常见错误。

## 一个实用动作
重要决定（报考、签证、缴费）之前，用「关键词 + 官方站点」再查一遍原始文件，确认你拿到的信息来自发布方本身。这个习惯在升学、求职、办签证时反复有用，也直接决定你写出来的材料可不可信。

```meta
last_verified: 2026-09-27
```

写作能力在职场里的作用常被低估：**大部分工作的成果最终要通过文字被确认**——方案、汇报、邮件、文档、复盘。可练的部分不是「文采」，而是三件事：把结论放前面、把依据写清、让读者能行动。

## 三种常用结构
| 场景 | 结构 |
| --- | --- |
| 汇报/方案 | 结论 → 三条依据 → 需要什么 → 风险 |
| 说明文档 | 背景（一句话）→ 目标 → 步骤 → 常见问题 |
| 复盘 | 发生了什么 → 为什么 → 下次怎么做 |

**共同点**：读者可以只看第一段就抓到重点。

## 一次写作的固定动作
1. **写一句结论**：这篇要对方知道/决定什么？写不出说明还没想清；
2. **列提纲**：三到五个要点，每个要点配一个证据（数据、例子、对比）；
3. **先写完再改**：初稿不考虑措辞，避免卡在第一段；
4. **改稿三遍**：
   - 第一遍删掉不影响意思的句子（通常能删 20%）；
   - 第二遍把被动句与名词化改成人话（「进行了优化」→「把 X 从 3 天缩到 1 天」）；
   - 第三遍检查数字、口径、链接是否准确；
5. **换读者视角读一遍**：假设对方不了解背景，能否看懂。

## 常见问题清单
- 结论在最后一段；
- 用形容词代替数据（「显著提升」）；
- 一段写多个主题，读者抓不住；
- 术语前后不一致；
- 大量「进行、相关、一定的、基本上」这类无信息词；
- 只讲过程不讲结论（「我做了 A、B、C」但没说结果）。

## 怎么练（低成本、可累积）
- **每周写一段 200 字的总结**（读完的文章、做完的事、开过的会），坚持八周；
- **改写别人的文字**：找一篇冗长的说明，压缩到一半，再看自己保留了哪些信息；
- **公开输出**：写技术笔记、项目复盘、行业观察——被真实读者看过，更容易发现自己哪里没写清楚；
- **请人改**：让同事或同行指出「哪里没看懂」，比自己反复读有效。

## 怎么判断写得够好了
- 对方读完能复述你的结论；
- 不需要追问「所以你的建议是什么」；
- 没有需要解释的数字与术语；
- 你自己的上一个版本，现在读起来有明显问题（说明进步了）。

## 怎么练：从三百字复盘开始
每做完一件事——一次实验、一个项目节点、一场活动——写三百字：目标是什么、做了什么、结果与预期的差距、下次怎么改。坚持十次，你会明显感到「讲清楚」变容易了。

## 三条基本纪律
- **先想读者要什么**：他关心结论还是过程？先给结论；
- **一段只说一件事**：段首第一句就是这段的中心；
- **删掉形容词**：「非常显著地提升」不如「从 12% 提升到 19%」。

## 攒成作品
写得好的复盘和说明文档本身就是可展示的成果——把每次的复盘收进一个公开文档或博客，它同时是 [作品集](../03-做项目、打比赛、进实验室/01-项目与作品.md#project-portfolio) 的一部分。

### 表达与演讲

```meta

effort: low

summary: 表达与演讲怎么练：一次讲一个点、先给结论、用证据支撑，以及准备一次汇报的具体流程。
last_verified: 2026-09-21
```

表达能力的核心不是口才，而是**把结论放前面、用证据支撑、只讲对方需要的部分**。这三条都能通过固定流程练出来。

## 准备一次汇报的四步
1. **写一句结论**：这次汇报要让对方知道或决定什么？（写不出说明还没想清楚）
2. **列三条支撑**：每条一个证据（数据、案例、对比）；
3. **预判两个问题**：对方最可能问什么（通常是「数据怎么来的」「成本多少」「风险在哪」）；
4. **排练一次**：掐时间，砍掉多余内容。**多数汇报的问题是内容太多，不是太少**。

## 结构模板（可套用）
结论：我们建议 <做什么>
理由：三条，每条一句话 + 一个证据
方案：怎么做，需要什么资源
风险与应对：最可能出问题的地方
请求：需要对方做什么决定

## 三条实践原则
- **一次讲一个点**：讲十个点，听众记不住任何一个；
- **先讲对方关心的**：对业务方先讲结果与影响，对技术方先讲约束与方案；
- **图表少而清**：一页一个结论，坐标轴与单位写全。

## 面对提问时
- **先确认问题**：「你问的是 X 还是 Y？」——避免答错方向；
- **不知道就说不确定**，并给出「我什么时候能给答案」；
- **不要在台上辩论**：记录分歧，会后单独沟通。

## 怎么练
- 每次汇报后记一句「哪里听众走神了」，下次改掉那一处；
- 录一次音回听，通常能发现口头语与语速问题；
- 在小场合先练（组会、社团、朋友），不要第一次就上大场。

## 常见失败
- 上来讲背景三分钟，结论在最后一页；
- 用形容词代替数据（「提升明显」）；
- 讲完自己的过程，没有回答「所以呢」。

## 三个做法
- **备一个五分钟版本**：把你最熟悉的一个主题讲五分钟——自我介绍、项目介绍都行。它会被反复用到，值得打磨到能脱稿；
- **预演**：对着朋友或手机录像讲一遍，你会立刻发现哪里卡顿、哪里信息过载。卡顿的地方多半是你自己还没想清楚的地方；
- **控制信息量**：一次只讲一个核心观点，佐证不超过三条。听众记住一个点，胜过听完十个点什么都没记住。

## 紧张怎么办
紧张来自不确定。把开头两句话背熟——顺利开场之后，后面的状态会自然好很多。讲完留出提问时间，被问到时先复述问题再回答，也给自己几秒钟组织语言。

### 沟通协作

```meta

status: complete

effort: low
evidence: [experience_based]
summary: 沟通协作怎么练：把预期写出来、约定检查点、处理分歧的具体话术，以及协作失败的常见原因。
last_verified: 2026-09-21
```

协作失败大多不是态度问题，而是**预期没有对齐**：你以为要 A，对方以为要 B，做到一半才发现。可练的部分就是把对齐变成固定动作。

## 三个固定动作
1. **开工前写下三件事**：目标（做完是什么样）、分工（谁负责哪部分）、接口（交付什么格式、给谁、什么时候）。写进群里或文档，不用长；
2. **设中间检查点**：不要只在最后碰一次。哪怕一次 10 分钟的对齐，也能省掉几天返工；
3. **结束时留记录**：决定、变更、遗留问题各一行。下次开会不用重新回忆。

## 处理分歧的话术
- **先确认共同目标**：「我们的目标是不是 X？如果是，那 A 和 B 哪个更接近它？」
- **分开事实与偏好**：「你说的是数据是这样，还是你倾向于这样？」
- **给选项而不是结论**：「我倾向于 A，理由是……如果你更在意 B，我们可以选 C」；
- **限时决策**：「我们先按 A 做两天，两天后看结果再定」——避免在讨论里无限循环。

## 拿到信息的方式
新手常见错误是**靠追问**：一遍遍问对方要什么。更好的做法是**先给一个自己的版本**（草稿、草图、假设清单），让对方在你的版本上修改——纠错比从零开始描述容易得多。

## 常见失败与对应动作
| 失败 | 表现 | 动作 |
| --- | --- | --- |
| 接口不清 | 两人做的东西拼不起来 | 开工时写清数据结构或文件命名 |
| 沉默同意 | 会上不说，事后抱怨 | 明确问「有异议吗」，并记录反对意见 |
| 依赖单点 | 一个人卡住全组停 | 关键部分两人互为备份 |
| 只同步进度不同步风险 | 直到截止日才发现延期 | 每次同步必须包含「风险」一项 |

## 怎么知道自己进步了
- 你负责的部分很少需要返工重构；
- 别人能直接使用你的交付，不用再问你；
- 出现分歧时，你能把它变成一次具体的决策而不是争论。

## 三个习惯
- **写下来**：合作开始时用几句话确认目标、分工与截止时间，发在群里。十分钟的确认省掉几天返工；
- **提前暴露风险**：发现可能延期，第一时间说，而不是拖到截止日。坏消息不会因为晚说变好，但早说给所有人留了应对时间；
- **同步有节奏**：约定固定的进展同步频率，别让合作方靠追问获取信息。

## 小组作业是最好的练习场
课程小组项目里出现的推诿、摸鱼、临时变卦，职场里同样会出现。趁便宜的时候把这些坑踩一遍，练习怎么分工、怎么催、怎么兜底——这正是 [Ownership](../07-从新人到能独立负责/02-从执行到独立负责.md#work-ownership) 的雏形。

### 数据能力

```meta
id: skill-data
status: complete
stages: [college, undergraduate, work_1_3]

outputs: [portfolio]
effort: medium
evidence: [experience_based]
summary: 数据能力不是画图：从自己的问题出发走完整流程、核对口径、解释不确定性，并给出口径自检清单。
last_verified: 2026-09-27
```

数据能力的核心不是会用工具画图，而是**能设计指标、核对口径、诚实地解释结论的边界**。

## 从自己的问题开始学
挑一个你真的想知道答案的问题（自己专业的就业去向、某个社团活动的参与变化、某平台公开数据），走一遍完整流程：

定义要衡量什么（指标 + 口径）
→ 找数据（公开数据、自己收集、平台导出）
→ 清洗（缺失、异常、重复、单位）
→ 分析（对比、分组、趋势；不做无依据的因果推断）
→ 写结论（含不确定性与限制）

工具在过程中顺便学会，不必先学工具再找问题。

## 口径是数据能力的分水岭
同一个现象用不同口径会得到相反结论。常见口径问题：

- **范围**：样本是谁、排除了谁（只统计活跃用户会让留存看起来很好）；
- **时间**：自然月还是滚动 30 天、是否含节假日；
- **定义**：「活跃」「完成」「有效」各自怎么定义；
- **单位与币种**：是否统一、是否含税。

**自检清单**：写出结论时，至少能回答「这个数字怎么算出来的、覆盖哪些人、和谁比较」。

## 常见误区
| 错误 | 表现 | 改法 |
| --- | --- | --- |
| 只画图不说结论 | 做了一堆图表，没有判断 | 每张图配一句结论 |
| 相关性当因果 | 「A 上升 B 也上升，所以 A 导致 B」 | 明确说明无法推断因果，或设计对照 |
| 忽略样本偏差 | 用论坛样本代表全体 | 说明样本来源与局限 |
| 小数点误导 | 精确到小数后两位但样本很小 | 用区间或「约」 |

## 怎么展示
把一次完整分析写成一篇报告：问题、数据来源、口径、方法、结论、限制。**这就是可验证的成果**（见 [什么叫可验证成果](../00-从这里开始.md#judge-verifiable-outcomes)），比「熟悉 Excel/Python」有力得多。

```meta
evidence: [experience_based]
summary: 项目管理入门：把不确定性摊到明面上——一页目标、分工与接口、检查点、风险清单，四件事就够。
last_verified: 2026-09-28
```

项目管理不需要复杂工具，需要的是把不确定性摊到明面上：目标是什么、谁负责、什么时候检查、哪里可能出问题。

## 最小可用流程：四件事

- **一页目标**：做完是什么样、什么时候要、谁验收。写在共享文档里，不用长；
- **分工与接口**：谁负责哪块、交付什么格式、什么时候交给谁。接口不清是协作失败最常见的原因；
- **检查点**：不要只在最后碰一次。设两到四个中间节点，每个节点要求「能运行 / 能演示 / 能评审」；
- **风险清单**：两列表——可能出什么问题、到时怎么办。做过一次你会发现，多数风险早有预兆。

## 三种常用节奏

| 场景 | 节奏 | 典型场合 |
| --- | --- | --- |
| 短期任务（一到两周） | 每日或隔日同步 + 最后演示 | 比赛、作业、活动 |
| 中期项目（一到三个月） | 每周同步 + 里程碑评审 | 课程项目、实习项目 |
| 长期项目（半年以上） | 双周迭代 + 季度复盘 | 产品、论文、开源 |

## 同步会上问什么

每次同步只问四个问题：上次承诺的事做完了吗、没做完的原因是什么；下一步做什么、什么时候完成；有没有卡住的地方、需要什么支持；有没有新出现的风险。这样问的好处是让延期在第一周就暴露，而不是截止前一晚。

## 常见失败模式

| 失败 | 表现 | 预防 |
| --- | --- | --- |
| 范围膨胀 | 不断加需求，永远完不成 | 明确「不做什么」，新需求排队 |
| 接口不清 | 各做一块拼不起来 | 定格式与时间点，先做一次端到端联调 |
| 只在最后一刻检查 | 发现严重问题时来不及 | 早设检查点，每点要求可演示 |
| 没有决策者 | 讨论很久没有结论 | 指定一个人拍板 |
| 不做记录 | 反复讨论同一个问题 | 一页决策日志 |

## 怎么练

课程小组项目、社团活动、开源协作都是免费练习场。主动当一次组织者，完整走一遍那四件事，体验「没人主动汇报时怎么办」，比读十篇方法论有用。

这项能力在职场直接对应「能不能独立负责一件事」，见 [Ownership](../07-从新人到能独立负责/02-从执行到独立负责.md#work-ownership) 与 [怎么承担更大的项目](../07-从新人到能独立负责/02-从执行到独立负责.md#work-bigger-projects)。

### AI 与数字工具

```meta
id: skill-ai-tools
status: complete
stages: [college, undergraduate, work_1_3]
topics: [skill]
outputs: [optionality]
effort: low
evidence: [official, experience_based]
summary: AI 与数字工具怎么用：把工具当协作者而不是答案、四类可靠用法、必须自己核对的边界。
last_verified: 2026-09-27
```

AI 工具改变的是**初稿与检索的成本**，不改变「谁对结果负责」。用得好的关键是把它们放在流程里的正确位置。

## 四类可靠用法
| 用法 | 适合做什么 | 不适合做什么 |
| --- | --- | --- |
| 起草 | 邮件、提纲、注释、模板 | 直接交付的事实性内容 |
| 改写与压缩 | 让文字更清楚、更短 | 改技术结论与数据 |
| 解释与学习 | 解释概念、给例子、生成练习 | 当作权威来源（可能编造） |
| 代码与脚本 | 生成样板代码、正则、转换脚本 | 未经测试直接上线 |

**共同点**：把它当「起草与加速」，而不是「最终答案」。

## 五条使用纪律
1. **事实必须回到原始来源**：政策、法规、数字、引用一律核对官方或原论文；
2. **代码必须自己跑一遍**：包括边界条件与失败情况；
3. **不要让工具替代判断**：方案取舍、优先级、风险，仍由你负责；
4. **注意数据边界**：公司内部资料、个人信息与未公开数据不要粘贴进外部工具（先看公司政策）；
5. **保留你的思路**：用工具提速，但你要能解释每个决定的理由。

## 常见的三种错误
- **把生成内容直接交出去**：出现事实错误或风格不符，代价由你承担；
- **用工具替代学习**：能生成但看不懂，遇到追问就崩（见 [怎么判断自己真的掌握了](04-专业技能.md#skill-mastery-check)）；
- **用它回避真正的难题**：把该自己判断的问题外包，长期会弱化能力。

## 什么样的用法算「会用工具」
- 你能说出在哪个环节用它、省了多少时间；
- 你能判断它给的答案哪里不对；
- 你有自己的检查清单（事实核验、测试、格式统一）；
- 你把重复劳动（格式化、转换、批量处理）交给它，把判断留给自己。

## 与求职的关系
会用工具本身不是优势（几乎人人会用），**能把它接进工作流并产出更好结果**才是。面试里讲一个具体案例（用它把某件事从 X 小时降到 Y 分钟，并且你做了什么校验），比说「熟练使用 AI 工具」有力得多。

## 适合交给 AI 的活
初稿与改写（把要点扩成段落、把啰嗦改简洁）；整理与总结（长文档的要点提取、会议记录结构化）；检索起步——用 AI 快速定位「该去哪个官方来源查」，而不是直接采信它给出的答案。

## 不能交给 AI 的部分
关键事实的核实。模型会生成看似可信但并不存在的细节，引用、数据、政策条款都必须回到原始来源确认，见 [信息检索](03-通用能力.md#skill-information-retrieval)。涉及申报、签证、缴费这类决定的信息尤其不能只靠模型的回答。

## 越用越重要的能力
恰恰是「判断输出好不好」的能力：你自己没有判断力时，AI 只会高效地生产平庸。所以基础功（写作、数据、领域知识）不但不过时，反而更值钱。

### 设备与文件的整理与备份

```meta
id: digital-device-and-files
status: complete
stages: [highschool, college, undergraduate, new_grad, work_1_3, work_3_5, senior]
topics: [digital, skill]
outputs: [optionality]
effort: low
evidence: [experience_based]
summary: 设备与文件的整理备份：目录只分四层、命名带日期、重要文件双备份、换机与交接有清单——目标是半年后还能找到东西。
last_verified: 2026-10-14
```

文件管理的目的不是「整洁」，而是**半年后你还能在 30 秒内找到它，并且它还在**。

| 动作 | 具体做法 | 解决什么问题 |
| --- | --- | --- |
| 目录只分四层 | 领域 → 项目 → 类别 → 文件，例如「工作/2026-XX 项目/文档」 | 减少决策成本，避免散落 |
| 命名带日期与版本 | `2026-10-14 方案 v2`，不用「最终版」「新版」 | 排序可读，避免找不到最新版 |
| 重要文件双备份 | 本地 + 云端（两个不同服务），每季度检查一次 | 防丢失与设备损坏 |
| 归档而非删除 | 项目结束后移入「归档」目录 | 保留可追溯性，减少误删风险 |
| 换机/交接清单 | 账号、二次验证、密钥、资料目录各一份清单 | 换设备、离职交接时不漏项 |

## 三个低成本习惯

1. **当下就归档**：下载完立即改名并归位，比「以后统一整理」可靠；
2. **重要资料不放桌面**：桌面等于临时区，随时可能被清理；
3. **每年做一次全量检查**：备份是否可用、账号是否还能登录（尤其是只靠短信验证的旧账号）。

## 什么时候要谨慎

- 公司资料与个人资料分开：公司文件不放到个人云盘，个人文件不留在公司设备（涉及保密与离职交接，见 [劳动合同要看哪些条款](03-通用能力.md)）；
- 密钥、证件照片、扫描件等高敏感文件单独加密保存，不要和其他资料混在一起；
- 备份服务的选择以能否导出、是否有加密为准；本项目不推荐具体产品。

### 个人公开痕迹怎么管理

```meta
id: digital-online-identity
status: complete
stages: [undergraduate, new_grad, work_1_3, work_3_5]
topics: [digital, job]
outputs: [reputation, optionality]
effort: low
evidence: [experience_based]
summary: 公开痕迹的管理：先搜一次自己、让作品与简历对得上、把长期内容放在可导出可迁移的地方、隐私设置按内容分层。
last_verified: 2026-10-14
```

招聘方与合作伙伴了解你的第一步，通常是**搜你的名字**。管理公开痕迹不是「删掉一切」，而是让搜到的内容与你想呈现的一致。

## 先做一次自我检索

| 搜什么 | 看什么 | 常见问题 |
| --- | --- | --- |
| 姓名 + 学校/公司 | 前几页会出现什么 | 无关的同名内容、过期信息 |
| 常用昵称/ID | 早年发帖与评论 | 情绪化发言、与专业形象冲突的内容 |
| 作品与账号 | 链接是否还能打开 | 作品链接失效、仓库无说明 |
| 邮箱/手机号 | 是否出现在公开页面 | 被收录的简历、论坛信息 |

## 四个动作

1. **让公开内容与简历对得上**：简历里写了的项目，最好有可点开的链接或可查的说明（见 [什么才算真正的项目](../03-做项目、打比赛、进实验室/01-项目与作品.md#project-what-is-real)）；
2. **把长期内容放在可迁移的地方**：优先选支持导出、有稳定链接的平台；重要内容本地留一份；
3. **按内容分层设置可见性**：专业内容公开、生活内容半公开或仅好友可见；
4. **处理历史内容**：与专业形象明显冲突的旧内容，改为仅自己可见；不必追求删除一切。

## 什么时候要谨慎

- 不要在公开平台发布公司内部信息、客户信息、未公开数据（也涉及合规，见 [劳动合同要看哪些条款](../../docs/rights/劳动合同要看哪些条款.md)）；
- 简历中的手机号与邮箱尽量用专用邮箱，减少垃圾信息与骚扰；
- 被冒名、被恶意搬运或涉及信息泄露时，按 [遇到纠纷找谁](../../docs/rights/遇到纠纷找谁.md) 处理并保留证据。
