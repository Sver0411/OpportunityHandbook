# 从学校走向第一份工作

## 校招是怎么运作的

### 提前批

```meta
last_verified: 2026-10-06
```

提前批指部分企业在正式秋招之前启动的招聘批次，通常集中在**毕业前一年的暑期前后**。它更像一次带反馈的练习，而不是必得的机会：意义在于让你在正式秋招之前走完一轮完整流程，把简历、笔试与面试表达上的问题提前暴露出来。

## 与正式批的关系
| | 提前批 | 正式秋招 |
| --- | --- | --- |
| 时间 | 较早（暑期前后，各公司不同） | 秋季为主 |
| 规模 | 相对小、流程快 | 大规模、批次完整 |
| 是否影响后续 | 通常不影响（**以各公司说明为准**） | — |
| 适合 | 想先练手、想提前锁定 | 主战场 |

**注意**：有些公司的提前批与正式批是同一批岗位（提前批没过可能不能再投该岗位），也有公司明确说明互不影响。**投递前看官方说明**。

## 暑期有整块时间的人更适合
- 想提前熟悉流程、积累面试经验的人（第一次面试几乎都会讲不好）；
- 已经有明确目标公司、想提前锁定的人；
- 暑假有整块时间可以参加笔试面试的人。

## 怎么准备
1. 提前两周更新简历（重点：可到岗时间与实习经历）；
2. 准备在线测评（不少公司有，见 [在线测评](05-从学校走向第一份工作.md#job-hunting-written-test)）；
3. 练习项目讲法（做到能被追问三层）；
4. 记录每次面试被问倒的问题（下一场立刻用上）。

## 没拿到时的安排
**这是常态，不是失败**。有效的做法是：

- 把提前批的面试记录整理成一份「问题清单」，针对性补短板；
- 调整简历与投递方向（如果连续几场都卡在同一环节，问题多半在定位或表达）；
- 保持正式秋招的节奏（提前批的结束就是正式批的开始）。

## 常见误区
- 以为提前批过了就不能再投更好的岗位（**看公司规则**）；
- 把提前批当唯一机会，失败后长时间停滞；
- 只投头部公司（参与度高但竞争最激烈），忽略同期开放的其他企业；
- 只投一两家，被拒后没有可比较的反馈，无法判断是定位问题还是表达问题。

秋招是校招的主战场，但它**没有全国统一日历**：每个公司的启动时间、批次划分与截止日期差异很大，必须以官方公告为准。

## 三个阶段与各自的作用
| 阶段（常见范围） | 企业在做什么 | 你该做什么 |
| --- | --- | --- |
| 暑期前后 | 提前批、部分岗位先发 offer | 练手：熟悉流程、补简历与项目表达 |
| 秋季（9–11 月） | 集中网申、笔试、多轮面试 | 主战场：批量投递 + 用追踪表管理 |
| 冬季到次年春 | 补录、签约、部分岗位二次开放 | 收尾：比较 Offer、签约与补录 |

**为什么这样安排**：企业希望在校招高峰期前锁定一部分候选人；学生的机会集中在秋季的 8–12 周里，因此准备必须前置到暑假。

## 硬截止与软节奏
**硬截止（错过就没有）**：网申截止、笔试确认、面试到场、三方签约期限、体检与入职材料提交。

**软节奏（可调整）**：简历修改、投递批次、面试顺序。

**处置原则**：把硬截止全部写进日历并提前提醒；软节奏按自己的准备情况调整，不要因为「别人都投了」就仓促投递。

## 前一步没完成怎么补救
- **简历没准备好**：先投两三家非首选公司练手，用真实反馈改简历，比闭门修改快；
- **没拿到提前批**：正常，直接准备秋招，把提前批的经验（被问倒的问题）用上；
- **秋招拿到的 Offer 不理想**：先签约保底（看清违约条款），同时准备春招与考研后补录；
- **笔试连续被刷**：通常是简历与岗位不匹配（改定位）或笔试训练不足（按题型补）；
- **面试总在终面失败**：多为岗位匹配度或薪资预期问题，重新校准目标岗位。

## 必须去官方确认的信息
- 目标公司的招聘公告与批次划分（官网/官方公众号）；
- 三方协议的条款、违约处理与报到时间（学校就业中心）；
- 毕业与派遣相关的政策（学校就业部门，每年可能调整）；
- 落户与档案事项（目标城市人社部门与学校）。

## 三段怎么打
- **准备**：毕业前一年的暑假之前，把简历和一份能当场展示的作品准备好，拖到秋招开始就晚了；笔试是很多行业的硬筛选，无法临时抱佛脚；
- **提前批**：投两三家练手，每次面试后记录问题，形成自己的题库；
- **秋招**：建一张进度表（公司/岗位/当前环节/下次跟进时间/复盘），同时投递多家，别把结果押在少数机会上；
- **春招**：不要放弃，很多岗位属于补录，竞争者数量通常少于秋招。

拿到 offer 后看清三方协议条款（违约金与解约流程），见 [三方](05-从学校走向第一份工作.md#job-hunting-tripartite-agreement)。

## 时间上的主动权，代价是提前一年的准备
秋招换到的是**时间上的主动权**、结构化的求职策略，以及避免「错过窗口」这类不可逆损失。

代价是提前半年到一年的准备、秋招期间密集的笔试与面试，以及被拒后重新调整的过程。要记住校招不是唯一通道：社招、内推、考公考编、升学都在并行。

春招是秋招之后的补充批次，岗位通常来自三类：**秋招未招满的岗位、新释放的岗位、以及针对考研后转入就业的安排**。

## 岗位来源与特点
| 来源 | 特点 |
| --- | --- |
| 秋招剩余名额 | 数量有限、流程快 |
| 新业务/新编制 | 岗位真实但分布不均 |
| 考研后转入 | 时间窗口较短，需要提前准备 |

**整体选择面小于秋招**，但对两类人仍然关键：秋招结果不理想的人、以及考研/考公出分后转入就业的人。

## 时间窗口
春招通常集中在上半年，各公司节奏差异很大，有的岗位只开放一两周。**因此准备必须前置**：不要把简历更新留到出分之后。

## 怎么准备
1. **在秋招结束时就更新好简历**（复盘秋招的反馈，改掉反复被问倒的点）；
2. 关注目标公司官网与学校就业网（见 [公司官网](05-从学校走向第一份工作.md#job-channel-company-site)）；
3. 把「出分时间」写进日历，出分后尽快完成第一轮投递（这段窗口不长，拖几天就会错过一批岗位）；
4. 用 [求职追踪表](../docs/tools/求职追踪表.md) 管理多线并行。

## 与考研结果的衔接
- **过线进复试**：复试与春招可以并行，但优先保复试（机会成本更低）；
- **没过线**：立刻转入春招与社招（应届岗位仍开放），同时决定是否二战——**建议在拿到春招结果后再决定**；
- **二战**：提前问清应届身份与择业期的规定、档案与户口安排（见 [空窗期怎么处理](05-从学校走向第一份工作.md#job-gap-period)）。

## 常见误区
- 等出分后才准备简历，错过第一批投递；
- 只在综合平台投递，忽略公司官网与学校就业网；
- 拿到 Offer 后立刻放弃其他机会（**先看清条款与报到时间**）；
- 把春招当成「补一个就行」，降低标准到无法接受的程度（判断标准见 [要不要降低岗位要求](05-从学校走向第一份工作.md#job-lower-requirements)）。

## 春招适合谁
秋招结果不理想、考研或考公出分后转向就业、以及秋招拿到 offer 但想再比较的人。对考研转就业的同学尤其重要：它是当年最后一段完整的校招窗口。

## 复用秋招复盘，盯紧官方渠道
1. 秋招的材料与复盘直接复用：把秋招挂掉的环节列出来针对性改进，见 [简历](05-从学校走向第一份工作.md#job-hunting-resume) 与 [面试](05-从学校走向第一份工作.md#job-hunting-interview)；
2. 关注目标企业官方招聘渠道——补录的发布时间分散、窗口短，靠第三方汇总容易错过；
3. 同时保留多条路径：社招岗位、内推、实习转正（见 [留用实习](04-当你开始面对第一次重要分流.md#internship-return-offer)）。

## 时间预期
各企业与行业的时间差异很大，不存在统一时间表；以目标企业的官方公告为准，见 [秋招](05-从学校走向第一份工作.md#campus-recruiting-timeline)。

补录（春招）岗位数量通常少于秋招，但对两类人特别关键：**考研/考公出分后转入就业的人**，以及**秋招没拿到合适 Offer 的人**。

## 谁适合走这一批
- 考研或考公结果不理想，需要尽快就业；
- 秋招拿到但不满意，想再试一次（注意签约与违约成本）；
- 毕业时间与秋招错开（如延毕、留学回国）；
- 秋招节奏没跟上（错过网申或多轮被拒）。

## 时间窗口与节奏
补录集中在上半年，**窗口比秋招短**：企业通常在出分前后集中启动，有的岗位只开放一两周。可操作的做法：

1. 提前把简历与作品更新好（别等出分才动手）；
2. 关注目标公司的官方招聘渠道与学校就业网通知；
3. 把「出分时间」写进日历，出分后尽快完成第一轮投递（这段窗口不长，拖几天就会错过一批岗位）；
4. 用 [求职追踪表](../docs/tools/求职追踪表.md) 管理多线并行。

## 准备什么
- **简历**：突出能与岗位直接对应的经历；应届生按 [简历怎么写](05-从学校走向第一份工作.md#job-hunting-resume) 调整；
- **项目与实习**：准备一段能讲三分钟的案例；
- **笔试准备**：多数补录仍有在线测评，别把复习完全停下；
- **三方与报到时间**：确认毕业时间与企业报到要求是否匹配。

## 与考研结果衔接
- **过线进复试**：复试与补录可以并行准备，但优先保复试（机会成本更低）；
- **没过线**：立刻转入补录与社招（应届岗位仍开放），同时决定是否二战——这个决定最好在拿到补录结果后做；
- **二战**：把「是否保留应届身份」「档案与户口怎么处理」提前问清学校就业中心。

## 常见误区
- 等出分后才开始准备简历，错过第一批投递；
- 只在综合平台投递，忽略公司官网与学校就业网；
- 拿到补录 Offer 后立刻放弃其他机会（先看清条款与报到时间再决定）。

## 怎么抓住
- 持续关注目标企业的官方招聘渠道（官网、官方招聘号），补录通常不会像正式批次那样大规模宣传；
- 让内推人帮你留意——很多补录名额先在内部传开，见 [内推](05-从学校走向第一份工作.md#job-hunting-referral)；
- 保持简历与作品集随时可投的状态：补录的响应时间常常只有几天；
- 已投过同一家公司的，可以礼貌地询问是否还有补录机会。

## 预期要合理
补录的岗位结构与正式批次不同（可能集中在特定部门或城市），所以**不能把全部希望押在补录上**——把它当作补充路径，同时推进其他选项，见 [长期找不到工作怎么办](05-从学校走向第一份工作.md#job-hunting-long-search)。

内推的作用是**让简历被人看到并可能被追问**，不是加分券。它改变的是概率，不改变你的材料质量——简历不行，内推只会让拒信来得更快。

## 怎么用好内推
盘点资源：学长学姐、实习同事、行业社群、校友会，优先找**在目标团队或了解团队**的人。请求时给对方三样东西：简历 PDF、目标岗位链接、一句话说明为什么匹配——别让对方替你写推荐语。内推后自己同步跟进官方流程，不要让内推人替你催进度；无论结果如何，告知对方并致谢——这是下次还能开口的原因。

## 两条红线
找根本不认识自己的人硬推，消耗的是关系；「付费内推」更要警惕——正规内推不收费，见 [高价求职辅导与付费内推](14-避坑.md#trap-information-asymmetry)。把内推当群发工具的海投式使用，同样是在烧关系。

## 一次内推请求应该包含什么
不要只发「学长好，能帮我内推一下吗」。一条有效的请求消息包含四部分：

```
1. 我是谁、我们怎么认识的（一句话，帮对方回忆）
2. 目标岗位的链接与岗位编号
3. 简历 PDF + 一句话说明为什么匹配（引用 JD 里的两三条要求）
4. 明确的请求与退出方式：「如果这个岗位不合适，也麻烦告诉我一声，
   我就不占用你更多时间了。」
```

**第 4 点最容易被忽略，也最重要**：给对方一个体面的拒绝出口，他下次才愿意再看你一次。

## 内推之后
- 自己盯官方流程（网申状态、笔试通知），不要让内推人替你催进度；
- 被拒后主动告诉对方结果并致谢——这是下次还能开口的前提；
- 拿到面试回来后给对方一句具体反馈（问了什么、感觉如何），对他判断以后要不要继续帮人有价值。

## 什么时候内推基本没用
- 目标岗位有强硬的学历或专业代码门槛，而你不满足——内推绕不过硬筛选；
- 你与对方没有真实交集，「帮忙」的意愿本来就很低，勉强开口既没结果也伤关系；
- 简历本身有明显缺口（无相关项目、无实习），此时先改材料，再考虑内推。

## 被看到的概率，不是加分券
内推换到的是**简历被人工查看的概率提升**，以及对团队与岗位的真实信息——内推人往往能告诉你这个组实际是什么样。部分公司的内推还带奖励机制，双方受益。

代价是维护关系的时间、请求时的人情成本，以及被拒之后的关系管理。

官网是**信息最准确、更新最及时**的渠道：招聘平台上的岗位常是转载或长期挂岗，官网能直接看到批次、岗位编号与截止时间。

## 官网的四个优势
1. **信息准确**：岗位职责、要求、地点与批次由用人单位自己发布；
2. **状态可判断**：有「已结束」「暂停招聘」标记，或按批次开放；
3. **投递有记录**：内部系统可追踪进度，后续沟通更容易；
4. **可能有额外入口**：实习生专项、内推码、宣讲会报名等只在官网出现。

## 怎么判断岗位是否真实在招
- 看岗位编号与开放时间；部分系统显示「新发布/已开放 X 天」；
- 看是否有明确的截止日期与批次；
- 在同一公司官网搜同类岗位，看是否长期重复发布；
- 用招聘页的联系方式或校招群确认（礼貌且简短）。

## 投递方法
- **逐条核对职责与要求**：把你满足的与不满足的分开列，判断是否值得投；
- **用岗位的术语写简历**：同一件事，用行业通用说法更容易被筛选系统命中；
- **只投最匹配的一个岗位**（同时投多个容易被判定为不严肃）；
- **保存岗位快照**：把 JD 内容与编号存进 [求职追踪表](../docs/tools/求职追踪表.md)，面试前复读。

## 跟进
- 投递后一到两周没有反馈，可按官网公布的渠道礼貌询问进度（**不要反复催促**）；
- 有内推人时，让内推人帮忙看状态（见 [校友与内推](05-从学校走向第一份工作.md#job-channel-alumni)）；
- 被拒之后可以问一句「后续是否建议我关注其他岗位」，多数 HR 会给出方向性回复。

## 什么时候别只依赖官网
- 公司体量大、投递量极高时，官网投递可能被淹没——此时内推与场景化渠道更有效；
- 中小公司可能不会在官网维护招聘页——直接用招聘平台或邮件联系。

## 怎么用
- 锁定十到二十家目标公司，直接在官网投递并记下投递时间；
- 看清每个岗位的要求与所属部门——同一岗位名在不同业务线下差别很大；
- 留意官网上的流程说明（笔试、测评、面试轮次），按它倒排准备时间；
- 已投递的状态以官网/官方系统为准，第三方平台的状态常常不同步。

## 与平台投递的关系
平台适合广撒网与发现机会，官网适合定向攻坚。两者可以并行，但**重要目标建议走官网**——有些岗位只在官网发布，且内推通常也需要官网的岗位编号。渠道组合见 [招聘平台](05-从学校走向第一份工作.md#job-channel-platform)。

招聘平台是最容易被滥用的渠道：投一百份没有回复，往往不是能力问题，而是**渠道与岗位选择的问题**。

## 平台之间的差异
| 渠道类型 | 特点 | 适合 |
| --- | --- | --- |
| 综合招聘平台 | 岗位多、竞争大、部分岗位长期挂着 | 校招与社招的常规投递 |
| 公司官网/官方招聘页 | 信息最准确、更新时间可查 | 有明确目标公司时优先 |
| 校招系统与学校就业网 | 面向应届生、流程规范 | 应届生主战场 |
| 垂直行业社区 | 岗位少但匹配度高 | 技术、设计等有圈子的行业 |
| 猎头与内推 | 有中间人，反馈更快 | 有经验者或有关系时 |

**同一家公司可能在不同渠道发布不同岗位**，也可能只有官网有最新信息。目标公司应至少查两个渠道。

## 怎么筛掉无效岗位
- **看发布时间**：超过一个月的岗位很可能已招到；
- **看职责是否具体**：只写「负责相关业务」的多为模板或长期挂岗；
- **看经验要求与你的差距**：要求 3–5 年经验的岗位投应届简历，大概率被过滤；
- **看是否重复发布**：同一公司同一岗位每周刷新，可能是在收集简历；
- **看薪资区间**：区间极大（如 8k–30k）的岗位通常按最低档给。

## 投递前的核对清单
1. 岗位职责与要求逐条读，标出你满足与不满足的；
2. 简历里的关键词与 JD 对齐（用 JD 的术语，而不是自创说法）；
3. 附件文件名规范（姓名-岗位-学校/年限）；
4. 记录投递日期与渠道（用 [求职追踪表](../docs/tools/求职追踪表.md)）；
5. 两周后统计各渠道回复率，把时间投到回复率高的渠道。

## 提高回复率的做法
- 内推优先（见 [校友与内推](05-从学校走向第一份工作.md#job-channel-alumni)）；
- 同一公司只投一个最匹配的岗位，避免同时投多个被系统标记；
- 投递后跟进不要频繁，一周一次为上限；
- 简历针对岗位微调（改动顺序与关键词，而不是编造经历）。

## 怎么用更有效
- 用明确的筛选条件（岗位名、城市、经验要求），不要靠推荐流被动刷；
- 看到合适的岗位后，尽量回到公司官网核实JD与投递（见 [公司官网](05-从学校走向第一份工作.md#job-channel-company-site)）；
- 记录投递结果：投了哪些、有没有回音、挂在哪一轮——两周复盘一次；
- 多个平台并用但不要重复投递同一岗位。

## 甄别要点
平台上「收费内推」「保证录用」「付费实习」一律不碰——正规内推不收费，见 [内推](05-从学校走向第一份工作.md#job-hunting-referral) 与 [付费实习与假科研](14-避坑.md#trap-fake-internships-and-paid-research)。要求先交钱培训再上岗的，风险很高。

内推的真实作用是**让你的简历进入人工筛选的视野**，不是跳过面试。理解这一点，就不会把内推当成捷径，也不会因为「发不出请求」而放弃这条最有效的渠道。

## 谁能真正帮到你
按有效程度排序：

1. **同部门、同岗位的人**（他知道岗位真实要求，也最可能拿到内推额度）；
2. **同公司的校友**（有共同身份，回复概率高于陌生人）；
3. **招聘 HR**（能确认岗位是否还在招）；
4. **猎头**（适合有经验者，了解薪资区间）。

**优先级判断**：目标公司里与你背景最接近的人，回复率最高。

## 怎么开口
一封 3–5 行的信息，包含四要素：

```
我是谁（学校/专业/工作年限 + 一句话背景）
为什么找你（看到你在 X 团队做 Y，我在准备同类岗位）
我准备了什么（简历 + 一段匹配说明，附件或链接）
请求什么（能否帮忙内推 / 或告诉我在官网哪个入口投递更合适）
```

**不要**：一上来问「你们公司还招人吗」、发一段自我介绍长文、要求对方帮改简历。

## 内推之后
- 按对方给的链接投递，**不要同时用其他渠道重复投同一岗位**；
- 投递后一周内告知对方已投，并附上岗位编号；
- 无论结果如何，一个月后给对方一句结果反馈（**这是维护关系的关键一步**）；
- 如果被拒，问一句「哪方面差距最大」——多数人愿意给一句具体反馈。

## 三种常见误用
| 误用 | 后果 |
| --- | --- |
| 群发消息给所有校友 | 回复率极低，且消耗关系 |
| 只求内推不做功课 | 内推后被快速淘汰，对方也不愿再帮 |
| 拿到内推就停止准备 | 内推只解决「被看到」，不解决「被录取」 |

## 没有校友怎么办
从公开渠道建立联系：行业社群、技术社区、开源项目、招聘宣讲会。做法见 [Networking](06-进入职场以后继续积累.md#community-networking) 与 [社群与行业组织](../docs/manuals/社群与行业组织.md)。

## 怎么用
1. 盘点资源：学长学姐、老师、院系群、校友会；优先找在目标团队或了解该团队的人；
2. 请求时给对方三样东西：简历 PDF、目标岗位链接、一句话说明为什么匹配——别让对方替你写推荐语；
3. 内推后自己跟进官方流程，不要让内推人替你催进度；
4. 无论结果如何都告知对方并致谢，这是下次还能开口的原因。

## 边界
内推不改变评价标准，它只提高被看到的概率；简历不行，内推只会让拒信来得更快。付费买内推是在买本来免费的东西，见 [信息差与高价辅导](14-避坑.md#trap-information-asymmetry)。

招聘会的价值是**用两小时拿到几十次真实的初步判断**：你可以直接问岗位内容与要求，比网申的不确定性低很多。

## 会前准备
1. **拿到参会名单**，标出 5–8 家最相关的公司（不是越多越好）；
2. **准备 30 秒自我介绍**（背景 + 与岗位最相关的一件事 + 你想要的岗位）；
3. **准备 2–3 个具体问题**（不要问「你们招什么」，名单上写了）；
4. 带上简历（纸质 5–10 份 + 电子版/链接）；
5. 查清到场的岗位是否匹配你的可到岗时间（实习时间是最常被问的问题）。

## 现场三步
```
第一步：听宣讲/看展位，确认岗位与你的匹配度
第二步：问一个具体问题（例如「这个岗位第一年主要交付什么」）
第三步：留下联系方式并确认招聘流程（是现场初筛还是后续网申）
```

**不要**：排队两小时只投一份简历、把所有公司都问一遍同样的问题、只拿宣传册就走。

## 会后跟进
- 给聊过的人发一条简短信息（提到你们聊的内容 + 你的岗位意向）；
- 按对方说明的渠道完成正式投递（**不少公司仍要走系统网申**，现场只是加分）；
- 记录每家公司的岗位名称与要求（后续面试有用，用 [求职追踪表](../docs/tools/求职追踪表.md)）。

## 适合与不适合
**适合**：校招专场与学院双选会（岗位真实、匹配度高）、行业专场（同行业内多家公司可比较）、需要现场初筛的岗位。

**不太适合**：希望直接谈薪或定岗的场景（招聘会通常只是初步接触）、规模极大且以发资料为主的活动。

## 常见误区
- 以为现场投了简历就不用网申（多数仍要走官方渠道）；
- 只盯着大公司，忽略到场的中型公司（后者参与度更高、机会更多）；
- 没有准备自我介绍，现场临时组织导致表达混乱；
- 不记录，一周后完全想不起和谁聊过什么。

## 带着目标公司清单进场
- 提前拿到参会企业名单，圈出五到十家目标公司，查清它们的岗位与业务；
- 准备一个三十秒的自我介绍，说明你能做什么、想做什么；
- 带上简历（纸质与电子版）和作品链接（作品集页面或二维码）。

## 现场怎么做
直接问具体问题：这个岗位入职后前三个月做什么、团队规模与汇报线、招聘流程的下一步是什么。这些问题比「你们招什么人」有用得多，也更容易让对方记住你。记下聊过的人的名字与要点，当天或第二天发一条跟进消息。

## 预期
招聘会更多是建立联系与获取信息的场合，最终录用通常仍走正式流程。把重点放在「让对方记住你」和「拿到下一步的入口」，而不是现场等结果。

JD 是求职市场里最容易获得的真实材料，一份 JD 至少有六层信息，读法各不相同。

## 逐项怎么读
- **岗位职责**：判断「这个工作每天做什么」的主要依据，也是区分模板话术的关键；
- **硬性要求（必须）**：筛选线。学历、专业、年限、证书里写「必须」的就是硬门槛；
- **优先条件**：竞争维度，不是筛选线；
- **工作年限**：区分「相关经验」与「总工龄」，前者常可用项目或实习折算；
- **学历**：区分「本科及以上」与专业代码要求，后者更硬；
- **技能关键词**：反复出现的工具与方法就是行业的通用语言。

## 怎么区分模板话术与真实要求
同一公司同类岗位 JD 高度雷同的部分通常是模板；具体到这个岗位的那几行（特殊工具、特定业务、明确年限）才是真实要求。判断不了就问在职者，见 [怎么找到真实从业者](02-在学校里先把基础打好.md#find-practitioners)。

## 用 10–20 份 JD 找共性
统计高频要求：反复出现的是行业共识，只出现一次的多半是某家公司的特殊偏好。然后对照自己分三类——已具备、一学期内能补、短期无解；第二类就是接下来几个月的准备清单，见 [怎么从岗位要求反推技能](02-在学校里先把基础打好.md#skill-reverse-engineer)。

## 一个例子
某岗位写着「熟悉分布式系统，有高并发经验者优先」。如果这是**优先项**而你没有相关经验，它不该劝退你——把它归入「一学期内能补」：先做一个能说明问题的项目，规模可以小，但要能讲清取舍。反过来，如果写的是「必须持有 XX 证书」，而你没有，那就是硬门槛，投递前先降低期望值，或先解决门槛。

**判断标准只有一条**：这条要求是筛选线（必须），还是竞争维度（优先）。前者决定能不能投，后者决定怎么排准备顺序。

## 常见误区
- **只看公司名气，不看岗位职责**：同一家公司不同岗位差别很大；
- **把「优先」当「必须」**：自我筛掉本可以争取的机会；
- **只读一份 JD 就下结论**：单份 JD 里既有模板话术，也有这家公司的特殊偏好；
- **读了却不改简历**：看出高频要求却不调整材料，等于白读。

## 简历与作品

### 简历怎么写

```meta
id: job-hunting-resume
status: complete
stages: [college, undergraduate, new_grad, work_1_3]
topics: [job]
outputs: [work_experience]
effort: medium
evidence: [official, industry_data, experience_based]
summary: 简历怎么写：不同阶段的写法差异、各段经历写几条、没数字怎么办、技术岗与非技术岗的侧重、ATS 与链接、失败示例与修改顺序。
last_verified: 2026-09-27
```

简历的目标不是「介绍你」，而是**让筛选者在一分钟内找到留下你的理由**。因此它是一份按岗位定制的材料，不是一份自传。

## 先看清不同阶段的差异
| 阶段 | 简历重点 | 常见误区 |
| --- | --- | --- |
| 大一/大二（找第一段实习） | 课程项目、技能、可到岗时间 | 因为经历少而堆无关内容 |
| 大三/研一（找暑期实习） | 相关项目、成绩（如岗位看）、实习经历 | 只罗列技术栈 |
| 应届秋招 | 实习 + 项目 + 与岗位直接相关的产出 | 把经历写成职责描述 |
| 社招 | 交付成果与可迁移能力，按结果组织 | 仍按时间顺序堆经历 |

**同一份简历不能投所有岗位**：至少准备一个基础版，再按 JD 调整顺序与关键词。

## 一段经历写几条
通常每段经历写 2–4 条，核心项目可以 4–5 条。每条按三段写：

```
做了什么（动作，不是职责）
怎么做的（方法/约束/你的取舍）
结果如何（数字或可核对的事实）
```

**只写一条的经历**通常说明你没有展开它——要么补，要么删。

## 没有数字怎么办
数字最有说服力，但不是必须。替代品按可信度排序：

1. 可核对的事实（上线状态、使用范围、覆盖范围、通过率）；
2. 明确的对比（优化前 1.2s → 优化后 0.4s，同机同数据）；
3. 规模描述（团队人数、你的模块、用户量级）；
4. 方法与限制（说清你在什么约束下解决了什么问题）。

**不要编数字**：面试追问一层就会露底（见 [背调](05-从学校走向第一份工作.md#job-hunting-background-check)）。

## 技术岗怎么写技术深度
- 写**取舍**而不是工具清单：为什么选这个方案、放弃了什么；
- 写**瓶颈与解决**：卡顿在哪、你怎么定位、结果如何；
- 给出**链接**（仓库、文档、演示），可点开比描述有力；
- 写清你的角色（几人团队、你负责哪部分）。

## ATS 与格式
部分公司用系统初筛（ATS），因此：

- 用常见的结构（教育/经历/项目/技能），不要把内容拆进复杂表格；
- 关键词用 JD 里的术语（同一件事用行业通用说法）；
- 不要放照片、身高体重、家庭信息（多数场景不需要，且可能引入偏见）；
- 一页（应届）到两页（社招），PDF 优先（除非要求其他格式）。

## 链接与作品集
- 放 2–3 个最相关的链接（代码仓库、演示、报告）；
- **提交前逐个点开检查**，失效链接等于没有；
- 需要登录才能看的内容，改提供截图与说明。

## 失败示例与改法
| 失败写法 | 问题 | 改法 |
| --- | --- | --- |
| 「负责后端开发，参与需求评审」 | 职责描述，没有动作与结果 | 写清你做了哪个模块、结果如何 |
| 「熟悉 Java、Python、Go、SQL…」 | 工具清单，无法验证 | 只保留与岗位相关且能深入解释的 |
| 「提升了系统性能」 | 没有口径 | 补上指标、样本与对比 |
| 「参与国家级项目」 | 归属不清 | 写清团队规模与你的部分 |
| 三页简历，课程占半页 | 重点被稀释 | 应届简历压缩到一页 |

## 修改顺序（比一次写好更重要）
1. 列出目标岗位的 3 个核心要求；
2. 检查简历是否在前三分之一就回应了它们（不够就把最相关的经历上移）；
3. 逐条删掉与岗位无关的内容；
4. 给每条补上结果或方法；
5. 让一个不了解你背景的人读一遍，看能否复述你做过什么。

## 先研究岗位，再动笔
选 2–3 类目标岗位，各看 5 份真实招聘启事，把任职要求里的关键词按重要性列出来。简历的作用是让筛选者在 30 秒内看到“这些关键词我都有”。

## 每段经历写成“动词＋做了什么＋结果”
- 有数字的写数字：负责某模块，上线后日活多少、错误率降了多少。
- 没有数字的写交付物：报告、代码仓库、作品链接、证书名称、公开发布的内容。
- 写清规模和角色：几人团队、你负责哪一部分，避免“我们”盖过“你”。

## 排版与长度
一页为限（经历特别多时最多两页）；倒序排列；用 PDF；文件名包含姓名与目标方向。排版只服务于可读性，不需要装饰。

## 一份简历投所有岗位是浪费
不同岗位要求不同，关键词也不同。按类改简历，通常每类花一两个小时，回报高于多投几十份。同类岗位可以共用一版，跨类要重写。

## 常见问题
- 写职责不写结果。
- 把跟岗位无关的经历堆满版面。
- 用“参与”“协助”开头，看不出你实际做了什么。

## 投递前自查
找一个做过招聘的人看一遍，只问一个问题：“30 秒内你能说出我是谁、适合什么岗位吗？”

## 三段式写法
```
项目名 + 你的角色（一句话）
做法：用了什么方法、解决了什么具体困难（2 行）
结果：数据或可核对的事实（1 行）
```

示例：

> 校园二手交易平台｜后端负责人（3 人团队）
> 我负责订单与支付模块；为解决并发下单的重复扣减问题，把库存校验放进事务并加幂等键。
> 上线后 3 周内完成 400+ 笔交易，无重复扣款；代码与接口文档在 <链接>。

## 按岗位调整侧重
| 目标岗位 | 侧重写什么 |
| --- | --- |
| 技术岗 | 技术难点、方案取舍、性能/稳定性数据 |
| 产品岗 | 问题来源、用户验证、指标变化 |
| 数据岗 | 数据来源与口径、方法、结论与影响 |
| 运营/内容岗 | 策略、执行规模、增长或转化数据 |
| 研究岗 | 问题、方法、结果、你的独立贡献 |

## 结果怎么量化
- 用**你确定的数字**：用户数、耗时、准确率、覆盖范围；
- 写清**口径**：「日活 200」不如「注册用户 1200、周活跃约 200」；
- 没有数字就写**可核对的事实**：上线状态、被谁使用、评审结论、测试通过率；
- **不要编**：面试追问一层就会露底。

## 没有项目时写什么
- 课程设计（写清问题与你的角色）；
- 竞赛作品（与 [竞赛经历怎么写](05-从学校走向第一份工作.md#resume-competition) 配合）；
- 开源贡献（见 [开源手册](../docs/manuals/开源手册.md)）；
- 自主复现或小工具（写清为什么做、怎么验证有效）；
- 实习中的具体模块（哪怕是支持性工作，也要写清你交付了什么）。

## 常见问题
| 问题 | 改法 |
| --- | --- |
| 只写功能清单 | 改成「解决了什么问题、结果如何」 |
| 用「参与」「协助」 | 写清你的具体动作 |
| 技术栈堆砌 | 保留与岗位相关、且你能深入解释的 |
| 团队成果写成个人成果 | 标注团队规模与你的部分 |
| 链接失效 | 提交前逐个点开检查 |

## 不同岗位的侧重
| 目标岗位 | 侧重写 |
| --- | --- |
| 技术岗 | 技术实现、性能/稳定性数据、你的模块 |
| 数据岗 | 数据来源与口径、方法、结论影响 |
| 产品/运营岗 | 问题来源、方案、指标变化 |
| 研究岗 | 问题、方法、结果、你的独立贡献 |

## 短实习、杂活、远程实习怎么写
- **短实习（1–2 个月）**：写你完成的一件具体的事，不写时长；如果确实只是熟悉环境，就如实简写一行并说明学习到的流程；
- **杂活为主**：写清你交付的部分（数据整理、文档、测试），并说明你如何把它做得可靠（例如把重复流程做成模板）；
- **远程实习**：写清协作方式（同步频率、工具）与交付物，消除「是否真实参与」的疑虑。

## 常见误区
- 只写「协助完成……」——听不出你的动作；
- 把团队成果写得像个人成果（面试追问即露）；
- 时间线与实习证明不符（**以合同与证明为准**）；
- 写的技能与岗位无关，稀释重点；
- 没有留下任何可核对的事实。

## 与项目经历怎么取舍
- 实习有真实交付 → 实习优先，项目作为补充；
- 实习以辅助为主、项目更完整 → 项目放前面，实习写一行交付说明；
- 两者都弱 → 先补一个项目（见 [项目经历怎么写](05-从学校走向第一份工作.md#resume-projects)），再回来改写实习。

## 怎么写才有信息
- 挑一件你**完整负责**的事来写：从接到需求到交付，你做了哪些决定；
- 写结果：产出了什么、带来了什么变化（数字最好，哪怕是「覆盖多少条数据」「节省多少时间」）；
- 写清你的角色边界：独立负责、主导某部分、还是参与执行——诚实比夸大安全，背调与追问都会核实，见 [背调](05-从学校走向第一份工作.md#job-hunting-background-check)。

## 示例结构
「在 XX 团队负责 YY 模块的 Z 项改造：重新设计了 A 流程（说明你的判断），上线后 B 指标从 X 降到 Y；过程中处理了 C 问题（说明难点）。」

## 只有打杂经历怎么办
从日常里挑一件你做得比别人深的事（整理的数据、写过的文档、维护的流程），按上面的结构写；同时用项目经历补上不足，见 [项目经历怎么写](05-从学校走向第一份工作.md#resume-projects)。

### 科研经历怎么写

```meta
id: resume-research
status: complete
stages: [undergraduate, master, phd]
topics: [job, research]
outputs: [work_experience]
effort: low
evidence: [experience_based]
summary: 科研经历怎么写：写清问题与你的具体贡献、用证据代替形容词，以及没有论文时怎么呈现研究经历。
last_verified: 2026-09-21
```

科研经历在简历里的价值不被「发表」决定，而由**你在研究里做了什么、做到什么程度**决定。招聘方与招生委员会看的是这个。

## 三段式写法
每一段科研经历按三段写，每段一到两行：

```
背景：研究什么问题、什么规模的团队/课题（一句话）
我的工作：负责哪一部分、用了什么方法、解决了什么具体困难
结果：可验证的产出（论文/报告/代码/数据/被采纳的方案）+ 你的位次或角色
```

示例（不必有多高的成就，但必须具体）：

> 参与 XX 方向课题组（3 人），负责数据清洗与基线复现。
> 复现两篇论文的关键结果，定位到原实现中未说明的数据预处理差异并整理成复现报告。
> 产出：复现报告与脚本（链接），组内用于后续实验的环境搭建。

## 用证据代替形容词
| 不写 | 改写成 |
| --- | --- |
| 熟悉机器学习 | 复现 X 方法并在 Y 数据集上达到与原论文一致的指标 |
| 参与国家级项目 | 负责其中 Z 模块的实现与测试，代码在组内使用 |
| 有一定的科研能力 | 独立完成文献综述 20 篇、提出并验证一个假设（结果：不成立） |

**「结果不成立」也可以写**：它证明你能设计验证、能接受负结果，这在研究岗里是加分项。

## 没有论文怎么写
- 写**正在进行**的工作，标注状态（在投/在写/数据收集完成）；
- 写**复现报告**与**文献综述**——它们本身就是研究训练的证据；
- 写你在组里承担的**具体模块**（数据、实验、分析、写作），而不是「参与课题」；
- 有代码或数据就放链接；没有就写清可提供的材料清单（面试时展示）。

## 常见问题
- 只写课题名称与导师名字，看不到你做了什么；
- 把团队成果写成个人成果（面试一问就露）；
- 罗列用了多少工具，却不写解决了什么问题；
- 全部写成「参与了……协助了……」——没有动作与结果。

简历的整体写法见 [简历怎么写](05-从学校走向第一份工作.md#job-hunting-resume)；研究经历的深挖见 [科研手册](../docs/manuals/科研手册.md)。

## 投学术/研究岗怎么写
突出四要素：研究问题是什么、你用什么方法、你**具体**贡献了哪部分、结果如何（论文、报告、数据集）。署名位次要如实写，见 [作者位次与署名](04-当你开始面对第一次重要分流.md#research-writing-and-submission)。

## 投产业岗怎么翻译
把科研动作翻译成岗位语言：

- 复现与改进实验 → 工程实现与调优能力；
- 设计对照与指标 → 实验设计与数据分析；
- 写论文与做报告 → 结构化表达；
- 跨组协作取数 → 跨团队沟通。

用「问题—做法—结果」的结构写，避免一整段术语。招生与求职的不同侧重见 [科研到底是什么](03-开始积累真正能留下来的经历.md#research-what-is-research)。

竞赛在简历上的作用取决于你**能不能讲清做过的具体问题**。只写奖项名称，等于把一个可验证的素材浪费掉了。

## 一行奖项 + 三行内容
```
赛事名称 · 奖项/名次（若有）
问题：什么类型的题目/目标
我的角色与动作：负责哪部分、用什么方法、遇到什么问题怎么解决
产出：代码/论文/原型/评测结果（链接）
```

**示例**：

> 全国大学生数学建模竞赛 · 省级二等奖
> 题目为城市交通信号优化；负责建模与编程（3 人队）。
> 用排队论建立路口延误模型，发现原模型未考虑转向比例后加入该因素，使预测误差从 X 降到 Y。
> 产出：论文与代码（链接）。

## 名次不高时怎么写
- 写**过程中的具体判断**（试过什么、为什么放弃、最终选了什么），这比名次更能说明能力；
- 把可展示产出放上去（代码、原型、报告）——**评委与招聘方更信能点开的东西**；
- 如果同方向有更强的证据（实习、项目），竞赛可以只留一行。

## 写法上的三个提示
- **不要写赛事介绍**：招聘方不会因为你解释比赛规模而加分；
- **不要堆参赛数量**：三次参赛各写两行，不如一次写透；
- **数字要有口径**：名次（省赛第几/前百分之几）、队伍规模、你的模块占比，写清才有可比性。

## 不同用途的侧重点
| 用途 | 侧重 |
| --- | --- |
| 技术岗 | 你解决的技术问题、方法选择、代码产出 |
| 产品/咨询岗 | 问题拆解、分析框架、团队协作与表达 |
| 升学（研究型） | 与研究方向的相关性、能否转化为研究能力 |
| 升学（授课型） | 体现动机与基础的证据，权重低于成绩与语言 |

## 什么时候可以省略
奖项完全与目标岗位无关、且你只是挂名参与时，可以省略或压缩成一行。把省下的空间给 [项目经历](05-从学校走向第一份工作.md#resume-projects) 通常更划算。

## 三类项目怎么讲
| 类型 | 讲什么 | 适合证明 |
| --- | --- | --- |
| 个人项目 | 问题来源、你的独立贡献、结果与限制 | 主动性、完整交付能力 |
| 团队项目 | 你负责的模块、接口与协作方式 | 协作与工程规范 |
| 真实使用/上线 | 用户量、留存、反馈、迭代记录 | 结果导向、真实场景能力 |

**每一条都要有「你的动作」**，而不是「项目做了什么」。

## 每个条目的结构（一页之内）
```
背景：解决什么问题、给谁用（2 行）
我的角色与关键决策：做了什么、为什么这样选（3 行）
结果：数据、用户反馈、测试结果（带口径）
链接：代码 / 演示 / 报告
限制：已知问题与未完成部分
```

**写清限制反而加分**：它说明你知道边界在哪。

## 排序与数量
- **按目标岗位排序**：投研发把技术深度放前，投产品把问题定义与用户反馈放前；
- **数量**：两到三个打磨完整的项目胜过十个半成品；
- **每个项目都要能点开**：链接失效等于没有。

## 常见误区
- **只有截图没有说明**：看不出你做了什么；
- **罗列技术栈**：不解释为什么用、解决了什么问题；
- **把教程项目当作品**：复刻一遍教程（见 [Demo](03-开始积累真正能留下来的经历.md#project-demo)）；
- **夸大归属**：团队成果写成人成果，面试一追问就露；
- **长期没更新**：一年前的项目链接已失效。

## 检查清单（提交前逐项确认）
1. 每个条目都有：问题、我的动作、结果、链接；
2. 结果有数字或可核对的事实；
3. 链接可访问（代码、演示、报告）；
4. 没有需要登录才能看的材料（除非说明申请方式）；
5. 没有与岗位无关的凑数内容；
6. 用目标岗位的语言描述（对齐 JD 术语）。

## 作品集在哪里放
- 简历中放**最相关的两三个**（附链接）；
- 单独做一个可访问的页面或仓库（README 汇总）；
- 面试时准备 3 分钟与 10 分钟两个版本的口头讲法。

## 放什么
选三个最能代表目标岗位能力的项目，宁缺毋滥；每个项目写统一结构：问题 → 方案 → 关键难点 → 结果（数字或演示）→ 链接；再配一个三十秒能看完的演示（截图或录屏），见 [作品集](03-开始积累真正能留下来的经历.md#project-portfolio)。

## 没有作品怎么办
用一个两到四周的小项目补一个（见 [第一个个人项目怎么开始](03-开始积累真正能留下来的经历.md#project-personal)），或者把课程项目按可展示标准整理出来。

## 笔试与面试

### 在线测评

```meta

effort: medium

last_verified: 2026-09-27
```

在线测评（OT / 网测）是校招里最容易被低估的一关：它通常**自动筛人、按分数排序**，且常常有严格的时间限制与一次机会。

## 三类常见题型
| 类型 | 内容 | 准备方式 |
| --- | --- | --- |
| 能力/认知测试 | 数字推理、图形推理、逻辑、语言 | 熟悉题型 + 限时练习（速度是主要变量） |
| 专业知识测试 | 岗位相关的基础题、代码题、案例分析 | 按岗位要求复习基础，练既往真题类型 |
| 性格与情境判断 | 性格问卷、情境选择题 | 不猜「正确答案」，保持前后一致 |

**性格测评的建议**：如实作答、前后一致。刻意伪装会在一致性检验里出问题（同类题反复出现，答案矛盾会被标记）。情境题按「专业判断 + 合规 + 沟通」的优先级选，通常比「迎合」更稳。

## 规则陷阱（务必先看清）
- **时间限制**：有的按整卷计时，有的每题单独限时，中途离开可能作废；
- **机会次数**：多数只给一次，重考有冷却期（几个月到半年）；
- **环境要求**：可能需要摄像头监考、禁止切换窗口、断网是否算提交；
- **成绩有效期**：不少企业共享测评结果（同一集团或同一测评服务商），一次成绩会被多家使用。

## 准备方法
1. 找目标题型的公开模拟题做两三套，熟悉节奏（不必刷几百题）；
2. 数字与图形题练「先扫再算」的策略：先看选项再定位计算，而不是从头推；
3. 专业题按 JD 列清单，补「半会」的部分；
4. 考前检查设备、网络与备用热点，提前 15 分钟进入页面。

## 成绩不理想怎么办
- **不要慌**：不同公司的分数线与权重不同，很多企业是笔试 + 简历 + 面试综合排序；
- **看冷却期**：如果目标公司允许几个月后重测，用这段时间补短板；
- **换渠道**：内推与官网投递有时走不同流程，可以再确认（见 [校友与内推](05-从学校走向第一份工作.md#job-channel-alumni)）；
- **别用他人账号或代考**：这属于违规，且会被企业记录。

## 什么时候该改变策略
如果连续多次卡在测评环节（而不是面试环节），说明问题在「基础与速度」而不是简历：把主要精力放到限时练习上，而不是继续扩大投递量。

## 四步准备
1. **确认题型**：看目标公司往年笔试说明（官方渠道、学长回忆）——技术岗通常是编程题或基础题；非技术岗常见行测风格（言语、数量、逻辑、资料分析）；
2. **摸底**：先做一套完整的真题或模拟题，再决定练什么，不要盲目开刷；
3. **分题型限时练**：技术岗按题型分类练、重点是限时完成；非技术岗练限时与正确率的平衡；
4. **环境合规**：在线测评前检查设备、网络、身份证件与安静环境——多数测评全程监考，环境不合规会被判无效。

## 答题策略
做不出来的题先跳过并标记，最后统一处理——测评考的是整体得分，别在一道题上耗尽时间。目标岗位没有笔试环节的，别为不存在的环节焦虑。

### 专业面

```meta

status: complete

effort: medium

last_verified: 2026-09-27
```

专业面考的是**你能不能在压力下把会的东西讲清楚，以及不会的时候怎么处理**。准备方式因此和考试不同：不是刷更多题，而是建立「题型清单 + 项目深挖 + 应对卡壳」三件套。

## 第一步：建立题型清单
从 JD、面经与岗位领域整理一张清单，按三类分：

- **基础题**：领域基础概念与原理（必须答得出）；
- **应用/场景题**：给定条件做设计或分析（考思路，不考背诵）；
- **深挖题**：针对你简历里的项目追问（最容易失分）。

**做法**：把清单写成表格，每题标注「我会 / 半会 / 不会」。优先补「半会」——那是性价比最高的部分。

## 第二步：把项目讲到能被追问的深度
面试官会用三层追问检验真实性：

```
第一层：你做了什么？（能答出的很多）
第二层：为什么这样做？有没有别的方案？（开始筛人）
第三层：如果条件变成 X，你会怎么改？（区分是否真做过）
```

准备方法：每个项目准备两页笔记——问题与约束、你的方案与取舍、结果与口径、失败与改进。**能被追问三层的项目，比三个只能讲表面的项目更有价值**。

## 第三步：动手练，而不是只看
- 手写关键推导或代码片段（三到五道典型题，练到能解释每一步）；
- 录音复述一个项目，回听时删掉「然后、就是、这个」；
- 找同学互相刁难提问（扮演「不友好的面试官」）。

## 卡壳时的正确反应
- **先确认题意**：「你问的是 X 还是 Y？」避免答错方向；
- **说出思路再动手**：即使结果不对，过程能被评分；
- **明确说不会**，然后给一个可推导的近似答案或相关经验；
- **不要编造**：面试官通常一问细节就能识别。

## 面试后的 24 小时
立刻记录被问倒的问题与当时的回答（用 [求职追踪表](../docs/tools/求职追踪表.md)），并补上正确解法。同一批面试里，第二场通常比第一场好，原因就是记录与修正。

## 常见误区
| 失败 | 表现 | 改进 |
| --- | --- | --- |
| 背题不解原理 | 换个问法就答不出 | 每题追问自己「为什么」 |
| 项目讲不清 | 只说功能不说取舍 | 按「问题—动作—结果」重写 |
| 抢答不确认 | 答非所问 | 先复述题目 |
| 不会硬编 | 被追问就崩 | 承认边界 + 给近似方案 |
| 只看技术不理岗位 | 与岗位要求脱节 | 逐条对照 JD 准备 |

## 准备清单
1. 把简历上每段经历写成 STAR 结构（情境、任务、行动、结果），重点在「你**具体**做了什么」；
2. 准备三类必考题：一分钟自我介绍、最大的挑战、为什么是我们/这个岗位；
3. 对目标公司做基本功课：业务、产品、近期公开信息；面试中至少问出一个有质量的问题；
4. 技术或专业岗：核心知识与常见题型按清单过一遍，能当场推导的不要背结论；
5. 每场面试后 24 小时内复盘：哪道题答得不好、下次怎么改——面三到五场后效率会显著提升。

## 常见翻车点
背标准答案一追问就崩；说不出具体数字与结果；对目标公司一无所知；贬低前雇主或学校；不懂装懂——话术包装掩盖不了经历空洞，追问两层就露馅。技术面、Case 面、行为面、HR 面的具体差异见本章对应条目。


技术面考察的是**你在这个专业方向上能不能独立解决问题**。准备的核心不是背题，而是把核心知识过一遍并能当场推导。

## 列题型清单并练到能推导
1. 列一张题型清单：目标岗位常考的知识块（数据结构与算法、语言特性、系统设计、领域基础），逐项确认自己能讲清楚；
2. 能当场推导的不要背结论——面试官更在意你如何得出答案；
3. 把简历上的项目按「背景—我做了什么—难点—结果」准备，技术面通常会顺着你写的东西追问；
4. 每场面试后 24 小时内复盘：哪道题答得不好、下次怎么改（结构化面试的预测效度研究也支持：按统一标准准备与复盘能显著提升表现）。

## 答不上来怎么办
说清你的思路卡在哪、你会怎么查——这比硬编答案好得多。遇到不会的问题，可以先复述问题确认理解，再给出你知道的部分。

## 一道题该怎么讲
面试官问「为什么这个接口在高并发下会变慢」，两种回答的差别：

- **背结论**：「因为锁竞争。」——如果追问「哪把锁、竞争发生在哪一步」，通常就答不上来了；
- **展示推导**：「先看调用链里有几次共享写入……锁的持有时长会随下游延迟上升……所以我怀疑瓶颈在 X。验证方式是做一次压测，并在 Y 处打点。」——即使结论不完整，推理过程本身就是被考察的对象。

**面试官评估的是你的推理路径，不是你记得多少结论。**

## 什么时候该停
如果连续多场都在同一类题上失败，缺的是系统知识而不是刷题量——这时应该回去补那一个知识块，而不是继续刷更多题。反过来，如果只是偶尔某道题不会，不必因此扩大准备范围。

## 常见误区
- **只刷热点题不补基础**：换一种问法就不会；
- **项目细节讲不清**：简历里写了，却在追问两层后开始含糊；
- **把他人的方案当成自己的经历讲**：追问两层就会暴露；
- **只说结论不说推导**：无法判断你是理解还是背过；
- **复盘拖到一周后**：细节已经忘了。

### Case Interview


Case Interview（案例面试）常见于咨询与部分商业分析、产品经理岗位。它考的不是答案对错，而是**你如何把一个模糊问题拆开**。

## 常见题型
| 类型 | 例子 | 考什么 |
| --- | --- | --- |
| 市场规模估算 | 「某城市有多少家奶茶店」 | 结构化拆解 + 数值合理性 |
| 商业问题 | 「某产品销量下降，为什么」 | 假设驱动 + 数据验证 |
| 进入/投资决策 | 「要不要进入某市场」 | 收益成本与风险评估 |
| 运营优化 | 「如何提升某指标」 | 归因与优先级判断 |

## 通用解题结构
```
1. 澄清问题（目标、范围、约束、成功标准）
2. 提出框架（把问题拆成 2–4 个互斥且完整的维度）
3. 逐项分析（每项给出假设与需要的验证数据）
4. 收口（结论 + 关键理由 + 风险 + 下一步）
```

**框架要互斥且完整（MECE）**，但不要硬套现成框架：好的做法是根据问题现场构建，并说明为什么这样拆。

## 估算题怎么做
- **先定拆解路径**：总量 = 人群 × 渗透率 × 频次（或其他合理的乘法结构）；
- **每一步给出假设并说明依据**（人口、收入、替代品）；
- **快速算到量级**（重点是数量级正确，不是精确到个位）；
- **做合理性检查**（结果是否与实际观察冲突）；
- **说明敏感性**：哪个假设最影响结果。

## 它到底在考什么
- 能否在信息不足时形成结构化判断；
- 能否说明假设并主动验证；
- 能否处理面试官的反驳（给出新假设而不是争辩）；
- 数字计算是否准确且快速。

## 常见误区
- 急着算，不澄清问题；
- 套框架却不解释为什么；
- 假设不说明依据；
- 被反驳时改口却不说原因；
- 没有收口（分析完没有结论）。

## 怎么练
1. 找 5–8 个公开案例题，按上面的结构各练一遍；
2. 每次练习录音，回听是否有「先澄清、后拆解、最后收口」；
3. 找同伴扮演面试官，故意反驳你的假设；
4. 练心算与单位换算（速度会影响整体节奏）。

## 回答的骨架
1. **澄清问题**：先确认目标（要提升收入还是降低成本）、边界（地区、时间、资源约束）与可用的数据。这一步做得好，后面就不容易跑偏；
2. **结构化拆解**：把大问题拆成几个互斥且穷尽的小问题（例如收入 = 客单价 × 客户数；成本 = 固定 + 变动），逐块分析；
3. **给出结论与建议**：先说结论，再给理由与风险，最后说明验证方式。

## 跳过澄清与拆解直接给答案
上来就给答案（跳过了澄清与拆解）；拆解有重叠或遗漏；只分析不给结论；被面试官质疑时立刻放弃自己的判断（合理的做法是解释依据并愿意修正）。

## 计算怎么练
练心算与估算（市场规模、增长率），并**边算边说思路**。数字本身通常不是评分重点，量级合理与过程清晰更重要。常见的题型可以在网上找公开练习材料，限时练。

### 行为面

```meta
effort: medium
evidence: [official, experience_based]

last_verified: 2026-09-27
```

行为面（行为面试 / 结构化面试）考的不是你懂什么，而是**你过去怎么做事**。判断标准是：你的回答有没有具体到可以被追问的细节。

## 回答的基本结构
```
情境（一句话说清背景与约束）
任务（你的目标是什么，谁定的）
行动（你具体做了什么，为什么这样选）
结果（发生了什么，带数字或可核对的结论）
反思（如果重来会改什么）
```

**关键在「行动」**：多数人把时间花在背景介绍上，说不出自己做了什么决定。面试官想听的是取舍，不是流程。

## 六类常见问题与准备方式
| 问题类型 | 例子 | 准备什么 |
| --- | --- | --- |
| 团队冲突 | 「和同事意见不合怎么处理」 | 一个具体冲突 + 你的处理与结果 |
| 失败经历 | 「印象最深的一次失败」 | 一个真实失败 + 归因与改进 |
| 主动性 | 「有没有主动做过没人要求的事」 | 一件你自发推进并落地的事 |
| 压力与多任务 | 「同时几件事怎么排优先级」 | 一次排序依据与取舍 |
| 影响他人 | 「怎么说服别人接受你的方案」 | 一次被采纳的建议与推动方式 |
| 领导力 | 「有没有带过人或组织过事」 | 规模、你的角色、结果 |

**每题准备一到两个真实案例**，不要背标准答案。

## 追问怎么应对
面试官常追问三层：为什么这么做 → 有没有别的方案 → 如果条件变了怎么办。准备时对每个案例自问这三层，答不上说明当时没想清楚，需要换一个更熟悉的案例。

## 常见误区
- **用「我们」代替「我」**：听不出你的贡献；
- **答案太抽象**：讲价值观，没有具体事件；
- **失败经历包装成成功**：面试官一听就知道在回避；
- **背模板**：追问立刻露馅；
- **案例重复**：六个问题都用同一个项目。

## 准备节奏
- 面试前：写 6–8 个案例，每个 150 字左右，标出可量化的结果；
- 模拟一次：找同学按上面的追问链提问；
- 面试后 24 小时内：记录被问倒的问题并补上（见 [求职追踪表](../docs/tools/求职追踪表.md)）。

## STAR 结构怎么讲
**情境**（背景与目标）、**任务**（你要负责什么）、**行动**（你具体做了什么——这是重点，要占到八成篇幅）、**结果**（数字、反馈、后续影响）。准备三类必考题：最大的挑战、一次失败与复盘、一次与他人意见不同的经历。

## 背标准答案，一追问就崩
背标准答案一追问就崩；说不出具体数字；对目标公司一无所知；贬低前雇主或学校；不懂装懂。

### HR 面

HR 面（或业务 HR 面）通常在专业面之后，筛的是**稳定性、动机与成本匹配**，不是专业能力。理解这一点，就不会把它当成技术面试来准备。

## 它通常在看什么
- **动机与匹配**：为什么是这个岗位、这个公司、这个城市；
- **稳定性**：能不能待得住（尤其是异地、跨行业、频繁跳槽的情况）；
- **薪酬与到岗**：预期是否在范围内，到岗时间是否匹配；
- **风险项**：劳动关系、竞业、违规记录等（视岗位而定）。

## 六类必答问题
| 问题 | 回答要点 |
| --- | --- |
| 自我介绍 | 30 秒：背景 + 与岗位最相关的一件事 |
| 为什么选我们 | 具体原因（业务、技术方向、团队），不是夸赞 |
| 为什么离开上一家 | 说「想要什么」，不说「受不了什么」 |
| 职业规划 | 1–3 年的具体方向，避免空洞目标 |
| 手上有没有其他 offer | 如实说，不必透露具体公司（可以说进度与方向） |
| 到岗时间与薪资预期 | 明确、可兑现 |

## 薪酬预期怎么谈
- 先了解市场区间（招聘平台、同行、公开薪酬讨论）；
- 给出**区间**并说明依据（岗位、城市、你的经验），而不是一个死数字；
- 如果对方先问，避免说出低于其预算的低价（后续谈薪会受限）；
- 说明你看重的其他部分（成长、业务、团队）不会削弱你的议价，反而显示判断力。

## 哪些话最容易说错
- 「其实我也不太确定想做什么」——让人担心留存；
- 「上家公司管理很乱」——负面评价自己过去的组织；
- 「主要看钱」——在多数团队里会扣分；
- 「我什么都能做」——缺乏定位；
- 编造离职原因或时间线——可能被背景核实发现（见 [背调](05-从学校走向第一份工作.md#job-hunting-background-check)）。

## 反问环节问什么
挑两三个真正影响你决策的问题：

- 这个岗位第一年主要交付什么？谁评估？
- 团队的规模与人员流动情况？
- 晋升与涨薪的周期？
- 入职后的前三个月如何安排？

## 两条纪律
- **与前面几轮的说法保持一致**：薪资、可入职时间、离职原因，前后不一致会被当成风险信号（「为什么选我们」「职业规划」「薪资期望」这三个问题尤其要对得上之前的回答）；
- **准备一个真正想问的问题**：团队结构、新人前半年做什么、这个岗位为什么开放。提问质量本身就是信号。

薪资先给区间与理由，区间下限要是你真正可接受的数字，见 [谈薪](05-从学校走向第一份工作.md#job-hunting-salary-negotiation)。

## 什么时候可以少花力气
如果这个岗位本来就在你的「陪跑」清单里（用来练手，或已经确定不会去），HR 面不必投入太多时间。但**基本的一致性仍要守住**：同一家公司内部的招聘记录是共享的，前后矛盾的回答会影响你在该公司其他岗位的投递。

## 常见误区
- **把 HR 面当「走过场」而放松**：在这一轮掉以轻心的候选人并不少见；
- **回答与之前几轮矛盾**：薪资、离职原因、时间线对不上；
- **对薪资含糊其辞**：既显得没准备，也容易被压到区间下限；
- **不提问**：容易被解读为对这个岗位没兴趣；
- **负面评价上一家公司**：无论真实与否，都会被当成风险信号。

## Offer

### Offer 怎么比较

```meta

```

比较两个 Offer 时，最容易犯的错误是一上来就比月薪。月薪只是总结构里的一项，而且往往是最容易谈、也最容易被别的东西抵消的一项。

## 第一步：先排除不能接受的条件
有些条件不满足就直接出局，不需要算总分：工作地点无法长期待、岗位内容与你的方向完全无关、合同结构明显异常（不缴社保、试用期过长、要求先交钱）。

先把这类硬条件筛掉，剩下的才值得比较。

## 第二步：把收入拆开
- 月数：不少公司发 12 个月，也有 13–16 个月，按实际发薪月数折算。
- 绩效与年终：问清计算方式与历史兑现情况，不要只按招聘宣传。
- 社保与公积金：缴纳基数与比例会直接改变实际到手与长期积累。
- 股票 / 期权 / 补贴：能折现的、附条件的、可能归零的，分开写。
- 试用期薪资：常见为转正的 80% 左右，按合同写的算。

## 第三步：看这份工作能留下什么
三年后你会带走什么：一段可复述的成果、一种可迁移的能力、一群能合作的同事，还是一段只能写在履历上的时间。这一项没有数字，但它常常是几年后差距最大的地方。

## 第四步：看直属上级与团队
面试是双向的：问团队最近半年在做什么、上一个和你同岗的人去了哪里、日常怎么分工。如果对方回避或含糊，把这一点记下来。

## 第五步：算退出成本
违约条款、竞业限制、落户或服务期约定、租房与搬迁成本，都要提前问清。签之前弄清“如果半年后想走，代价是什么”。

## 最后：把两个 Offer 放进同一张表
同一套字段，逐项填，不留空。填不出来的字段本身就是信息——说明你还没问清楚。

可复制的模板见 [Offer 对比表](../docs/tools/Offer对比表.md)。

- 劳动合同、三方协议的具体条款以文本与法律原文为准；涉及违约金、竞业限制的争议应查阅法律原文或咨询专业人士，本条不给通用结论。 （Official）
- 行业薪酬分布可参考公开招聘信息与行业协会公开报告，但统计口径不一，只能作为区间参考，不能作为结论依据。 （Industry-data）
### 薪资和总包怎么看

```meta

status: complete
stages: [new_grad, work_1_3]
topics: [job]
outputs: [income]
effort: medium
evidence: [official, industry_data]
summary: 薪资和总包怎么看：把现金、浮动、福利与股权拆成同一口径，再算到手金额与真实时薪。
last_verified: 2026-09-27
```

Offer 上的数字不能直接比较：两家公司说「25 万」和「30 万」，到手可能倒过来。差别来自结构。

## 总包要拆成四块
| 部分 | 内容 | 要问清的问题 |
| --- | --- | --- |
| 固定现金 | 月薪 × 发薪月数 | 发几个月？13/14/16 薪是否写进合同？ |
| 浮动现金 | 绩效奖金、项目奖、销售提成 | 怎么算、历史发放比例、是否有下限 |
| 福利与补贴 | 公积金比例、餐补、交通、住房、体检、商业保险 | 公积金按什么基数缴（差额可能上万） |
| 长期激励 | 股票/期权、限制性股票 | 数量、当前估值、归属节奏、离职如何处理 |

**计算方式**：

```
年现金 = 月薪 × 发薪月数 + 有保障的浮动部分
真实福利 = 公积金（公司缴纳部分）+ 补贴合计 + 保险估值
长期激励 = 数量 × 估值，按归属进度折算到每年
```

浮动与股权**要按保守口径算**：绩效奖金按历史平均而非最高值，股权按当前估值的折扣算（上市前公司的股权可能长期无法变现）。

## 一个对照示例（示意）
| 项目 | A 公司 | B 公司 |
| --- | --- | --- |
| 月薪 × 月数 | 18k × 13 | 22k × 12 |
| 绩效奖金（保守估计） | 1 个月 | 0.5 个月 |
| 公积金（公司部分，按 12% / 5% 基数） | 较高 | 较低 |
| 补贴 | 餐补 + 交通 | 无 |
| 股权 | 无 | 部分期权（有归属期） |
| 年现金（保守） | 约 25.2 万 | 约 27.5 万 |
| 综合（含福利差异） | 约 27 万 | 约 28 万 |

这个例子说明：**月薪高不等于总包高，总包高不等于到手多**。

## 建议问出口的六个问题
1. 发薪月数与绩效奖金的计算方式；
2. 社保公积金的缴纳基数与比例；
3. 试用期工资比例与长度；
4. 股权的数量、归属时间表、离职后的处理；
5. 加班与调休、年假与病假的规则；
6. 涨薪与晋升的周期（很多公司一年一次，有的两年一次）。

## 别忽略的三项隐性成本
- **城市生活成本**：同样 25 万，在不同城市的实际生活水平差距明显；
- **通勤与加班时间**：换算成时薪后，差距会非常直观；
- **职业可迁移性**：有的高薪岗位三年后换工作时选择面变窄。

## 逐项核实
- **月数**：13 薪、14 薪还是更多，直接乘进年包；
- **绩效**：比例是多少、考核周期多长、历史上实际发放的比例（问在职者比看制度可靠）；
- **年终**：有些公司年终占比很高但波动大，要按「历史兑现情况」而不是名义数字估算；
- **社保公积金**：缴纳基数按实际工资还是按最低基数，比例多少——这直接影响可支配收入与长期权益；
- **股票期权**：看清算条件、行权价与稀释条款，不要只听口头描述，也不要按当前估值当现金算。

## 怎么用外部数据校准
用国家统计局分行业平均工资、行业薪酬报告等权威数据校准预期，别用个例晒薪帖。谈薪时给出区间与理由，区间下限是你真正可接受的数字；所有承诺以书面 offer 为准，见 [谈薪](05-从学校走向第一份工作.md#job-hunting-salary-negotiation)。

### 股票与奖金

```meta
id: offer-equity-bonus
status: complete
stages: [new_grad, work_1_3, work_3_5]
topics: [job]
outputs: [income]
effort: medium
evidence: [official, industry_data]
summary: 股票与奖金怎么算：四类长期激励的区别、价值怎么折算、常见陷阱，以及谈判时要问清的问题。
last_verified: 2026-09-27
```

Offer 里的股权与奖金是最容易被「看起来很多」误导的部分。判断的第一步是把它拆成**类型、数量、时间与确定性**四项。

## 常见的四类
| 类型 | 含义 | 特点 |
| --- | --- | --- |
| 期权（Option） | 未来以约定价格购买股份的权利 | 有行权价，只有股价高于它才有价值 |
| 限制性股票（RSU/RS） | 满足条件后归属（vesting）的股票 | 通常按时间归属，归属后即为股份 |
| 限制性股票单位（RSU，上市公司） | 归属后可变现 | 价值相对清晰，按股价计算 |
| 虚拟股/分红权 | 只有分红或增值收益，无实际股权 | 取决于公司制度，变现条件要问清 |

**关键区别**：期权的价值取决于「股价 − 行权价」；RSU 的价值取决于股价（归属后通常可直接变现，视公司规则）。

## 怎么折算（保守口径）
```
年度股权价值 ≈ 总授予数量 ÷ 归属年数 × 当前公允价值 − 行权成本
```

三条保守原则：

1. **未上市公司按当前估值打折**（未来融资与上市不确定，且可能有稀释）；
2. **期权要看行权价**：行权价高于当前估值时，纸面价值可能为零；
3. **归属节奏很重要**：四年归属通常有「悬崖期」（第一年不归属，离职则归零）。

## 奖金怎么判断
- **是保障还是浮动**：写进合同的固定奖金与「视绩效而定」差别巨大；
- **历史发放情况**：问「过去两年实际发放比例」比问「几个月」更有信息量；
- **计算方式**：与什么指标挂钩、个人还是团队、有没有下限。

## 常见误区
- **只说数量不说行权价与总股本**（无法判断价值）；
- **按最好情况算价值**（例如按未来估值而非当前）；
- **忽略稀释与优先清算权**（未上市公司尤甚）；
- **忽略离职条款**：未归属部分通常作废，已归属部分是否有回购条款要问清。

## 谈判时要问清的问题
1. 类型是什么？数量多少？行权价多少？
2. 归属节奏（多久一次、有没有悬崖期）？
3. 离职后如何处理（未归属作废、已归属能否保留、是否有回购）？
4. 公司当前估值依据（最近一轮融资价格）与总股本？
5. 奖金的计算方式与历史发放情况？
6. 税费如何处理（行权与卖出时可能有纳税义务）？

## 股票要看什么
- **归属节奏**：分几年归属、有没有悬崖期（满一年才开始归属）；
- **行权与变现**：期权需要行权价，未上市公司还要考虑退出机制；限制性股票看解锁条件；
- **稀释与条款**：后续融资会稀释，回购条款与离职后的处理也要看清。未上市公司的期权按当前估值折算，风险远高于上市公司股票。

## 怎么用它们比较 offer
把股票按归属年限摊平、按可得性打折后，再与固薪相加；奖金按「历史兑现的中位数」估。这样比直接比较名义总包更接近真实，见 [薪资和总包怎么看](05-从学校走向第一份工作.md#offer-total-comp)。

## 奖金要看什么
- 名义比例（例如「两个月」）与历史实际发放情况——问在职者比看制度可靠；
- 考核周期与考核方式（团队/个人、是否强制分布）；
- 发放时间（年终还是次年），影响你的现金流安排。

### 谈薪

```meta
id: job-hunting-salary-negotiation
status: complete
stages: [new_grad, work_1_3, work_3_5]
topics: [job]
outputs: [income]
effort: medium
evidence: [industry_data, experience_based]
summary: 谈薪怎么做：先拿到书面总包、判断议价空间来自哪里、用结构性理由提要求，以及什么时候不该谈。
last_verified: 2026-09-27
```

谈薪不是讨价还价比赛，而是一次**基于信息与理由的沟通**。多数谈不动的情况，问题出在前提：你没有其他选项，或者不知道对方的区间在哪。

## 谈之前必须先做的三件事
1. **把两边的总包按同一口径拆开**（见 [薪资和总包怎么看](05-从学校走向第一份工作.md#offer-total-comp)）：月薪 × 几个月、奖金条件、补贴、公积金比例、股权与归属；
2. **知道自己的替代方案（BATNA）**：手里有第二个 Offer 或能接受先不签，谈的空间完全不同；
3. **查市场区间**：招聘平台、同学与学长、公开薪酬讨论，得到「同类岗位的区间」，而不是一个精确数字。

## 议价空间从哪里来
- **岗位紧急度**：招得急的岗位通常有弹性（从面试节奏能看出）；
- **你的稀缺性**：稀缺技能、项目经验、内推背书；
- **公司类型**：大公司有薪级带宽（空间有限但有规则可依），小公司更灵活；
- **时机**：面试通过、尚未签约时空间最大；签完再谈几乎不可能。

## 怎么开口（可用的句式）
```
谢谢您的 Offer，我对这个岗位很感兴趣。
在确认之前，有两个问题想请教：一是薪酬是否有调整空间；
二是如果薪酬结构固定，签字费或入职时间上是否可以协商？
我这边的情况是：手里另有一个 X 的 Offer / 我的同类岗位市场区间是 Y–Z。
```

三个原则：**给出理由而不是情绪**（用市场区间、其他 Offer、额外职责）；**一次只提一个主要诉求**；**拿到承诺后要求书面确认**。

## 常见的可谈项目（不只是月薪）
- 起薪或薪级（大公司靠职级，职级确定后空间小）；
- 签字费（一次性，公司更容易答应）；
- 职级评估（有时比涨薪更重要，因为影响后续涨幅）；
- 入职时间、试用期长度、年假；
- 地点与远程安排、搬家与安置补贴。

## 什么时候不该硬谈
- 岗位明确按统一薪级招聘，公开说明不议价（国企、部分央企与外企）；此时可谈的是入职时间与职级评估；
- 你的备选方案很弱、且这个机会对你非常重要——此时**先拿到书面 Offer**，把精力放在入职后证明价值；
- 你在面试中已给出明确期望且对方照办——再谈会损害信任。

## 谈崩了怎么办
拿到书面 Offer 再谈，谈不成最坏结果是维持原 Offer。**不要用「如果不涨我就去别家」这类威胁**，除非你真的会走；说出口就必须执行。

## 怎么谈
用权威数据校准预期：国家统计局分行业平均工资、行业薪酬报告，不要只用个例晒薪帖。被问期望薪资时，先给区间后给理由，**区间下限是你真正可接受的数字**。只与有决定权的人谈（HR 或用人负责人），理由基于事实（另一 offer 的结构、市场数据）——不要编造 offer，被识破的代价是丢掉手上这份。所有承诺以书面 offer 为准，口头承诺不算。

## 更准确的比较基础
谈薪换到的是**更准确的比较基础**，有时是真实的薪资提升（社招尤其明显），以及避免入职后才发现结构上的问题。

代价是信息收集的时间与沟通的心理成本。两个提醒：信息不足时硬拉扯容易被识破；把谈薪当博弈游戏，超过合理范围会直接丢掉 offer。

### 三方

```meta

status: complete
stages: [new_grad]
topics: [job]
outputs: [work_experience]
effort: low
evidence: [official]
summary: 三方协议是什么：与劳动合同的区别、签约与违约的规则、档案户口怎么衔接，以及签字前要核对的内容。
last_verified: 2026-09-27
```

三方协议是**毕业生、学校、用人单位**三方签订的就业意向文件，核心作用是确认就业去向并纳入学校派遣计划。它**不是劳动合同**。

## 两者的区别
| | 三方协议 | 劳动合同 |
| --- | --- | --- |
| 签谁 | 学生 + 学校 + 用人单位 | 劳动者 + 用人单位 |
| 作用 | 确认就业意向、办理派遣与档案 | 建立劳动关系、约定岗位薪酬 |
| 内容 | 岗位、地点、报到时间、违约金约定 | 岗位、薪酬、工时、社保、试用期 |
| 签署时点 | 在校期间 | 入职时（通常一个月内） |

**常见误解**：以为签了三方就等于入职。实际入职后必须签劳动合同，且劳动合同的条款才是日常权利的依据。

## 签字前要核对的六项
1. 单位全称（与营业执照一致）、岗位名称与工作地点；
2. 报到时间与是否需要实习期；
3. 薪酬与结构（写进备注或协议，或至少确认书面说明）；
4. **违约金条款**（金额与适用情形）；
5. 是否需要附加协议（服务期、培训、保密）；
6. 学校就业部门对签署流程与时间的要求（有的学校限定办理窗口）。

## 违约与解约
- 违约通常按协议约定处理，**金额应合理**（很多学校对上限有规定）；
- 解约需原单位出具解约函，再向学校申请换发新的三方；
- 入职后离职受《劳动合同法》约束，与三方违约是两件事（见 [毁约](05-从学校走向第一份工作.md#offer-renege)）。

## 档案与户口怎么衔接
- **档案**：通常按三方协议与报到证转递到单位或其委托的人才机构；**档案不能自己保管**；
- **户口**：是否需要迁移取决于单位与城市政策（接收函、落户指标）；
- **报到证 / 就业报到手续**：各地流程与名称可能不同，以学校就业部门与当地人社部门要求为准。

**注意时限**：档案与户口的办理常有时间窗口，毕业离校前务必确认流程与材料。

## 签字前问学校就业中心的四个问题
1. 我们学校三方签署与换发的流程与截止时间是什么？
2. 违约需要哪些材料？是否影响后续办理？
3. 档案与户口由谁负责转递，需要我提交什么？
4. 如果单位不接收档案，应该放哪？（人才中心/生源地）

## 常见踩坑
- 只签三方不签劳动合同（入职后一个月内应签）；
- 口头约定的薪酬没有写进任何文件；
- 没看清违约金条款就签字；
- 离校后才发现档案未转递，导致后续手续补办困难。

## 签之前
读全条款，尤其是违约金数额、解约流程、备注栏——口头承诺的薪资、岗位、base 要写进备注。有把握再签：三方不是「先占坑」工具，毁约有成本。法律上，劳动合同里的违约金**只允许服务期（单位出资培训）与竞业限制两种情形**，超出即无效。

## 确需解约时
第一时间联系公司 HR 走解约流程、拿解约函，再向学校申领新的三方——越早处理代价越小。入职签劳动合同时核对条款与三方及 offer 一致，不一致的当场提出。各校对三方的时间与份数有具体规定，以本校就业中心说明为准。升学、留学、自由职业的毕业生通常不涉及三方。

### 背调

背调（背景调查）通常发生在**面试通过、发 Offer 前后**，用于核实你提供的信息是否真实。它的目的不是找茬，而是降低用人风险。

## 通常核查什么
| 项目 | 核查方式 | 常见差异来源 |
| --- | --- | --- |
| 学历学位 | 学信网/学位网或第三方机构 | 学校名称、专业名称、毕业时间填写错误 |
| 工作经历 | 联系前雇主 HR 或上级 | 任职时间、职位名称、是否在编 |
| 薪酬 | 部分岗位会核实（需你授权） | 夸大薪资与结构 |
| 身份与信用 | 身份信息核验；部分岗位查信用/诉讼记录 | — |
| 竞业与合规 | 是否受竞业限制、是否涉及利益冲突 | 未披露的兼职或竞业协议 |

**多数背调需要你书面授权**，且范围应与岗位相关。

## 提前准备什么
- **准确的时间与名称**：入职离职月份、职位全称、汇报关系。**填写时以劳动合同和离职证明为准**；
- **证明人**：提前和前上级或 HR 打招呼（避免对方接到电话感到意外）；
- **离职证明与社保记录**：能解释任何时间空档；
- **学历材料**：毕业证、学位证、成绩单（部分岗位要求）；
- **海外经历**：境外学历需能提供认证或学校证明。

## 有争议的情况怎么处理
- **有短期空档**：如实说明（备考、家庭、健康、休整），不要编造经历；
- **有短期任职**：说明原因与收获，避免被认为「不稳定」；
- **前公司已倒闭**：提供社保记录、工资流水或同事证明；
- **与前上级关系不好**：可提供其他证明人（同部门同事、客户），并说明情况；
- **有过劳动纠纷**：如实说明，准备好相关材料（仲裁/判决文件）。

**原则：可以解释，不可隐瞒**。被发现隐瞒的代价通常高于事实本身。

## 哪些做法不该有
- 伪造学历、职位、任职时间（属于欺诈，可能被解除劳动合同且无补偿）；
- 提供假证明人或冒充上级；
- 隐瞒竞业限制与利益冲突（入职后可能被追责）。

## 通过之后
- 保存好 Offer、授权书与背调结果通知；
- 若背调出现与你事实不符的结论，及时提供材料更正；
- 入职后核对劳动合同中的岗位、薪酬与地点是否与承诺一致。

## 入职前的核对
提前核对简历与档案的一致性：学历（学信网可查）、任职时间、职位名称，发现笔误尽早更正；空窗期如实说明，一段合理的解释远好过隐瞒；提供的证明人提前打好招呼——前同事或上级，别只留关系紧张的人。

## 你的权利
背调需要你书面授权；未经授权的调查、或超出合理范围收集的与岗位无关的隐私信息，你有权拒绝（《个人信息保护法》的知情同意与最小必要原则）。只有法定机构能出具无犯罪记录等官方证明，公司无权自行调取。正常背调不会翻你全部社交历史，但公开平台的言论确实可能被看到。

### 毁约


毁约（解约）在应届生里并不罕见，但它的代价**取决于你签的是哪份文件**——这一点常被搞混。

## 三方协议与劳动合同是两回事
| | 三方协议 | 劳动合同 |
| --- | --- | --- |
| 主体 | 学生、学校、用人单位 | 劳动者与用人单位 |
| 性质 | 就业意向与约束（含违约责任约定） | 建立劳动关系的法律文件 |
| 违约后果 | 通常按协议约定支付违约金 | 受《劳动合同法》约束（试用期、解除条件等） |
| 何时签 | 校招阶段常见 | 入职时 |

**前者主要约束「来不来」，后者约束「怎么用工」**。

## 违约金怎么算
- 三方协议里的违约金以协议约定为限，**金额应当合理**（多数学校对上限有规定）；
- 劳动合同中，除**专项培训服务期**与**竞业限制**两种情形外，用人单位不能随意约定由劳动者承担违约金；
- 因此「入职后想离职」通常不需要支付违约金，**但要看是否有服务期与培训协议**。

以《劳动合同法》与学校就业管理规定为准，**签字前逐条看清条款**。

## 毁约的实际影响
- **对本人的直接影响**：按约定支付违约金；可能影响该校与该公司后续的合作名额（部分公司会减少该校指标）；
- **对学校的影响**：学校就业部门通常会记录，个别学校对多次毁约有处理措施；
- **对个人信誉**：个别行业圈子小，反复毁约可能被记住。

## 更稳妥的替代做法
1. **延后决定**：在签约前谈一个「考虑期」或「延迟到 X 日前确认」；
2. **先不签三方**：如果还在等更想要的 Offer，可先拖住（注意对方可能撤回）；
3. **入职后正常离职**：受劳动合同法保护，试用期提前 3 天、正式期提前 30 天书面通知即可解除（除服务期与竞业情形），代价通常低于毁约；
4. **和 HR 沟通**：部分公司允许更换入职时间或岗位，比直接毁约损失小。

## 什么情况下应该毁约
- 新机会明显更符合长期方向（例如进入目标行业、目标职能）；
- 原 Offer 存在重大变更（岗位、地点、薪酬与承诺不符）；
- 健康或家庭原因必须调整。

**决策方式**：把违约金与机会价值放在一起算，而不是只因为「不好意思」而放弃更好的选择。

## 确需解约时
1. 第一时间联系公司 HR 说明情况，走正式解约流程并索取**解约函**；
2. 拿到解约函后再向学校就业中心申领新的三方（各校对时间与份数有具体规定，以本校说明为准）；
3. 越早处理代价越小——拖到入职前后再提，既影响公司用人安排，也更容易留下负面记录；
4. 保留所有书面沟通记录与回执。

## 怎么避免走到这一步
有把握再签三方，别把它当「先占坑」工具；同时推进多个 offer 时，按截止时间倒排决策，给每个 offer 留出比较空间；口头承诺的薪资、岗位、base 写进三方备注。见 [Offer 怎么比较](05-从学校走向第一份工作.md#offer-comparison) 与 [三方](05-从学校走向第一份工作.md#job-hunting-tripartite-agreement)。

### 第一份工作最应该换回什么

```meta
id: first-job-what-to-trade-for

topics: [job]
outputs: [work_experience, optionality]
effort: medium
evidence: [industry_data, experience_based]
summary: 第一份工作最应该换回什么：三类可带走的资本、用三年后的简历做判断、五个具体比较项，以及什么情况说明换错了。
last_verified: 2026-10-06
```

第一份工作最该换回的不是薪资本身，而是**三年后能被带走的资本**。判断方法：把两个 Offer 分别放进「三年后的简历」里比较。

## 三类可带走的资本
1. **能力**：能独立完成什么类型的事（不是用过什么工具）；
2. **成果**：可验证的交付（见 [什么叫可验证成果](00-从这里开始.md#judge-verifiable-outcomes)）；
3. **选择权**：三年后能去哪些公司/岗位（选择面是变宽还是变窄）。

**带不走的**：公司内部流程、只对这家公司有效的系统知识、依赖某个人的关系。

## 用三年后的简历做判断
写两份摘要，各三行：

> A：在 X 公司做 B 端产品，独立负责一条产品线，主导过一次从 0 到 1 的功能上线，带来 <指标> 变化。
> B：在 Y 公司做运营支持，负责报表与流程跟进。

哪一份更接近你想成为的人，就选哪一份。

## 五个具体比较项
| 项 | 怎么核实 |
| --- | --- |
| 直属上级 | 面试时问「团队最近一个月在做什么」，看答得具体还是空泛 |
| 岗位内容真实性 | 问「第一年主要交付什么」，与 JD 对照 |
| 业务状况 | 该业务是在扩张还是收缩（招聘量、公开财报） |
| 学习曲线 | 头三个月是否有人带、是否有可参考的现成流程 |
| 收入差距 | 按同一口径拆开比较（见 [薪资和总包怎么看](05-从学校走向第一份工作.md#offer-total-comp)） |

## 什么情况说明换错了
- 半年内发现自己只在做重复性工作、没人给反馈；
- 承诺的成长没有出现（带教、业务参与都没有落地）；
- 岗位内容与面试时说的不一致（这种情况优先内部调整，见 [内部转岗](06-进入职场以后继续积累.md#work-internal-transfer)）；
- 能力不再增长，而你还在「再等一年」。

**信号出现时应尽早处理**，而不是等到三年后才发现这段经历无法写进简历。

## 平台与人的质量：一项滞后的变量
在资源更集中的地方，你更可能遇到复杂问题与能干的人。这一项的影响往往是滞后的：工作前两年不明显，三到五年后才拉开差距。所以它不适合用来解释「为什么第一年该少拿钱」，但值得放进三年的账里一起看。

## 什么时候钱应该排第一
- 处在真实的经济压力下（家庭负担、债务）：先解决现金流没有错，只要清楚自己暂缓了什么；
- 岗位内容接近、平台相近、成长空间相似：此时起薪就是最直接的变量；
- 两个选项的三年后位置差别不大：不必为了想象中的成长，接受一份明显低于同行的薪资。

判断方式很直接：把两家公司三年后的可能位置各写一行，看哪一行更接近你想要的样子。如果两行几乎一样，就按钱选。

## 常见误区
- **为了大厂头衔，接受一个长期做边角工作的岗位**；
- **用「成长」安慰自己**，却说不出具体在积累什么；
- **只看月薪数字，不看结构**：社保与公积金的缴纳基数、调薪机制、奖金兑现方式都要问清，见 [薪资和总包怎么看](05-从学校走向第一份工作.md#offer-total-comp)；
- **把「带不走的」误当成资本**：离职就会归零的那类积累，不该算进「三年后能带走什么」；
- **发现问题却一直等**：明明在做重复工作、没人给反馈，却用「再等一年」拖下去。

### 大公司还是小公司

```meta

last_verified: 2026-09-21
```

大公司换的是流程规范、品牌背书和同行网络；小公司和初创换的是更大的职责范围和更快的决策参与。还没想清楚方向的人更适合先要体系，已经确定方向、愿意承担不确定性的人更适合要职责。

## 怎么比较
大公司要看**部门与汇报线**——同一个岗位名在不同部门差别很大，先问清业务线。小公司与初创要看四件事：现金流与融资阶段、核心业务是否已经跑通、你要负责的模块此前由谁负责、团队里有没有懂这一块的人。涉及期权或股权的，看清算条件、行权价与稀释条款的**书面文件**，不要只听口头描述，也不要把期权当现金算。

## 体系与职责范围，两者不可兼得
大公司换到的是**品牌背书**（在招聘筛选中确实起作用）、规范的工作方法、内部同行网络，以及离职后的行业认知度；代价是职责范围较窄、流程与协调时间多、晋升节奏慢。

小公司换到的是**完整项目的负责经验**、跨职能协作、与决策层近距离工作，有时还包含股权；代价是流程缺失导致的返工、职责不清、资源不足，以及公司层面的生存风险——初创还要额外承担业务转向、裁员与关闭带来的高波动。

对应的判断：需要明确分工和培训的人不适合初创；想做快速决策的人不适合层级深的大组织；对现金收入有硬性要求的，要谨慎对待以股权为主的薪酬结构。

## 一个兜底原则
判断不了时，选那个「行业下滑时也能带走技能」的位置。公司规模不是唯一变量——直属上级和部门的影响通常更大。

- 薪酬结构、期权与股权的法律含义按具体合同与法律文件判断。 （Uncertain）

这三类公司真正不同的不是「好坏」，而是**决策方式、评价标准与成长路径**。选之前先弄清自己更适应哪一套。

## 四个维度的实际差异
| 维度 | 国企 / 央企 | 民企（含互联网） | 外企 |
| --- | --- | --- | --- |
| 决策链 | 层级多、流程规范、周期长 | 层级少、决策快、变化频繁 | 流程清晰、目标与考核书面化 |
| 评价标准 | 综合表现、资历与合规并重 | 结果导向、指标压力大 | 岗位职责明确、过程与结果并重 |
| 成长方式 | 轮岗与资历积累，专业深度靠自驱 | 快速上手、边做边学，强度高 | 体系化培训与标准化流程 |
| 稳定性 | 高（但薪酬天花板相对低） | 波动大（业务调整常见） | 中等（可能受全球业务调整影响） |

**注意**：以上是常见模式，同一类型内部差异可能大于类型之间的差异（例如央企下属科技公司与传统子公司完全不同）。

## 什么情况优先考虑国企/央企
- 想在一座城市长期稳定发展，重视编制、落户与福利的确定性；
- 目标行业本身由国资主导（能源、电网、轨道、部分金融与基建）；
- 能接受相对慢的晋升节奏与较强的流程约束。

**要核实**：是否正式编制或合同制（差异很大）、薪酬结构与涨薪机制、是否要求政审与体检、是否有服务期与违约金。

## 怎么在面试里问出真实情况
- 「团队现在多少人？过去一年有没有明显变化？」
- 「这个岗位的考核指标是什么？谁评估？」
- 「入职后前三个月，我要交付什么？」
- 「团队最近一次业务调整是什么时候？」（判断稳定性）
- 「晋升一般多久一次，最近一次有人晋升是什么时候？」

## 决策不是永久的
第一份工作决定的是**起点与积累方式**，不是终身归属。跨类型流动是常见的（国企→民企、外企→民企、民企→国企都有），但每次转换都要重新适应评价标准与节奏。因此更值得问的是：**这份工作能给我什么三年后带得走的东西**（见 [工资还是成长](05-从学校走向第一份工作.md#first-job-pay-vs-growth)）。

## 三种类型的取舍
- **国企（部分事业单位）**：稳定、社保公积金规范、部分岗位有编制或准编制身份；代价是薪资天花板与晋升速度、部分岗位地域固定；
- **民企（尤其头部）**：更快的职责增长、市场化的薪资与晋升；代价是更高的波动性与强度；
- **外企**：规范的流程、培训体系与工作生活平衡（因公司而异）；近年在华业务调整带来的不确定性是真实成本。

## 怎么判断
先看行业：目标行业里哪种类型是主流，决定了你的大部分选择面（有些行业几乎只有民企，有些国企占绝对多数）。再用**具体公司**而非类型做判断：查它的社保公积金缴纳基数、加班与调休的实际执行、近两年的业务方向；面试时观察与提问团队结构、近一年的离职情况、晋升的实际案例。把应届身份与落户、考公等政策因素一并纳入比较（各地政策不同，以当地官方公告为准）。

## 什么情况优先考虑民企
- 想在短时间内积累真实业务经验、承担更大的责任；
- 目标行业变化快（互联网、跨境电商、新能源）；
- 能接受强度与不确定性，愿意用时间换成长速度。

**要核实**：业务是否健康（招聘量、公开财报、用户口碑）、团队是否稳定（面试时问团队规模变化）、期权条款。

## 什么情况优先考虑外企
- 看重规范的工作方式、明确的职责与国际化环境；
- 目标行业在外企有优势（制造、医药、快消、部分工业软件）；
- 英语工作环境与跨文化协作为你想要的能力。

**要核实**：所在国家/地区的业务是否为核心（决定稳定性）、晋升是否需要外派、薪酬结构（多为固定+奖金，股权较少）。

```meta
last_verified: 2026-10-06
```

选行业还是选岗位，本质是判断**哪一项决定你三年后的选择面**。两者都可迁移，但迁移方式不同：岗位能力在换行时更保值，行业经验在换岗位时更保值。

## 两种资本的可迁移性
| | 换行时 | 换岗位时 |
| --- | --- | --- |
| 行业经验 | 部分失效（行业知识、客户、监管） | 通常保留 |
| 岗位能力 | 通常保留（技能与方法） | 部分失效（需要新技能） |

**结论**：岗位能力在换行时更保值；行业经验在换岗位时更保值。**但行业经验换行业的代价，通常高于岗位能力换岗位的代价**（见 [可迁移行业经验](07-当职业开始出现分岔.md#switch-transferable-domain)）。

## 什么时候行业优先
- 行业处于扩张期（招聘量、投资、政策支持）；
- 你的目标是长期深耕一个领域（行业专家路线）；
- 岗位通用性强（销售、财务、运营、开发），行业知识才是差异所在。

## 三个可以当场核实的维度
1. **直属上级**：带你的人是否愿意教、是否有资源——对前两年体验的影响常大于公司名；
2. **岗位内容真实性**：面试时问「最近一个月团队在做什么」；
3. **跳槽出口**：这个岗位三年后能去哪些公司/岗位？**如果只有一个出口，风险较高**。

## 决策顺序
```
1. 排除硬约束（地点、家庭、健康、签证）
2. 比较「能积累什么」（能力、成果、关系）
3. 比较成长速度（带人的人、业务复杂度）
4. 比较收入与生活成本
5. 看可回退性（做错了能否转）
```

## 先做三步，再决定
1. 各写一份「三年后的简历摘要」：把两个选项分别套进去，看哪一份更接近你的目标；
2. 各找一位在职者问同一个问题：「这个岗位三年后常见去向是什么」，比较两边的出口数量；
3. 检查可回退性：如果选错，哪个选项转回来的代价更低。

## 两个常见误判
- **以为大公司等于好岗位**：大公司的边缘岗位可能长期做支持性工作；
- **以为小公司一定成长快**：取决于是否有真实业务与愿意带人的人。

## 什么时候岗位优先
- 行业整体收缩：行业标签可能变成负担；
- 岗位是核心岗位（能直接接触业务结果与决策）——此时即便行业一般，能力积累也快；
- 岗位专业度极高（算法、芯片、医疗等）：**能力壁垒比行业标签更保值**。

第一份工作的城市选择，本质是**在「机会密度」与「生活成本」之间取舍**，而且这笔账要算到三到五年，而不是入职那一刻。

## 城市真正提供的是什么
- **行业密度**：同类岗位的数量决定你换工作时是否有选择（也决定薪酬水平）；
- **信息与人脉**：行业活动、同行、猎头都在这里；
- **跳槽成本**：同城跳槽不用搬家、不用换社保，机会成本低；
- **生活成本与通勤**：直接影响可支配收入与时间。

**判断方法**：在招聘平台搜你的目标岗位，看招聘数量集中在哪几个城市；再看这些城市的租金与通勤时长。

## 算一笔三年的账
```
三年总收入（按当地同岗位水平）
− 三年生活成本（房租、餐饮、交通、社交）
− 一次性成本（搬家、押金、探亲交通）
− 机会成本（当地岗位的可选择数量）
= 三年净收益
```

**别忽略通勤**：每天通勤 2 小时，一年约 500 小时，相当于多上两个月班。

## 什么情况优先机会
- 目标行业只在少数城市有产业聚集（互联网、金融、影视、部分制造业）；
- 你处于职业生涯早期，需要快速积累经验与网络；
- 你能接受较高的房租与通勤（或愿意合租、住得远一点）。

## 异地工作的实际问题
- **落户与社保**：各城市政策不同，缴费年限影响买房、子女入学与医保待遇（以当地政策为准）；
- **档案与户口**：应届生落户常有时间窗口，错过可能难以补办；
- **家庭因素**：异地意味着探亲成本与情感成本；
- **回流的难度**：在小城市积累的经验，回到大城市可能需要重新证明。

## 什么时候可以改变这个决定
城市选择不是终身的：同行业内换城市通常比换行容易。**降低风险的做法是让能力与成果留在可携带的地方**（公开作品、行业关系、可迁移技能），见 [哪些能力可以跨路线使用](01-先决定下一步往哪里走.md#optionality-transferable)。

## 怎么算
1. 先确认目标行业在哪些城市有密度（在招岗位数量、公司数量）——行业地图比城市排名重要；行业在地理上高度集中而你又不想离开现在的城市，要么换城市要么换行业，两头都要是要付额外代价的；
2. 查目标城市的落户、人才补贴与住房政策（当地政府官网，政策会调整，别以为落户政策永远不变）；
3. 算一笔账：税后收入 − 房租 − 通勤时间的折算，而不是只看名义薪资；
4. 想清楚五年问题：这个行业在这个城市五年后会怎样？家庭因素呢？

## 行业密度与生活成本的取舍
城市换到的是**与目标行业匹配的选择面**、落户与长期生活的政策通道，以及生活成本与家庭距离之间的平衡。

代价在两头：大城市居住成本与通勤更高、离家更远；小城市行业选择面更窄，换工作时可能还要再迁移一次。

**城市可以换，但每次迁移都有成本**。第一份工作选城市时，把「想走随时能走」的行业技能留给自己——这比一开始就选对城市更可靠。

## 什么情况优先生活成本与稳定
- 目标岗位在家乡或二线城市同样存在（教育、医疗、公务员、部分制造与能源）；
- 家庭需要你在附近（照护、经济支持）；
- 你的目标是把生活稳定性放在第一位，而不是职业上升速度。


「工资还是成长」之所以难选，是因为「成长」常被当成无法验证的口号。把它拆开之后，两个选项就变得可比了。

## 把「成长」拆成三项可验证的东西
1. **能带走的成果**：一年后你能说清「我做过什么、结果如何」吗？（不是「参与过」）
2. **能力的增量**：是否在学新东西，还是重复你已经会的事；
3. **下一份工作的选择面**：这个岗位三年后能去哪里？能去的公司/岗位是变多了还是变窄了？

三项里两项为否定，所谓的「成长机会」通常只是忙碌。

## 五个具体判断维度
| 维度 | 怎么核实 |
| --- | --- |
| 直属上级 | 面试时问「团队最近一个月在做什么」，看对方答得具体还是空泛 |
| 岗位内容真实性 | 问「这个岗位第一年主要交付什么」，与 JD 对照 |
| 业务与行业 | 该业务线是在扩张还是收缩（看招聘量、公开财报） |
| 学习曲线 | 头三个月是否有人带，是否有可参考的现成流程 |
| 收入差距 | 把两边的总包按同一口径拆开比较（见 [薪资和总包怎么看](05-从学校走向第一份工作.md#offer-total-comp)） |

## 什么时候工资优先
- 差距超过 30% 且高薪那边**不牺牲上面五项**（这种情况直接选高薪）；
- 你有明确的现金流约束：家庭需要你尽快有收入、需要还贷；
- 岗位通用性强（同一技能在多个行业都值钱）：此时收入的增长空间更明显；
- 你已经很清楚下一步方向，第一份工作只是实现它的工具。

## 一个实用算法：三年后的简历
写下两份「三年后的简历摘要」，各三行。例如：

> A：在 X 公司做 B 端产品，负责一条产品线的迭代，主导过一次从 0 到 1 的功能上线。
> B：在 Y 公司做运营支持，负责数据报表与流程跟进。

哪一份更接近你想成为的人，就选哪一份；如果两份都写不出，说明两个岗位你都还不了解。

## 代价与退出条件
- **选高薪的代价**：可能被锁定在窄岗位，转型要付学费；
- **选成长的代价**：前两年的收入差距可能影响买房、落户、家庭预期；
- **退出信号**：入职半年内发现自己只在做重复性工作、没人给反馈、承诺的成长没有出现——这时应尽早内部转岗或换工作，而不是等三年。

## 三行检验法
把两份 offer 各写三行：我能学到什么**具体**技能？这个平台三年后给我的简历增加什么？这里的人两年后去了哪里？然后检查「成长」是不是可验证的（有带教、有项目、有明确的技术栈），还是一句口号——用「成长型岗位」接受没有成长内容的岗位，是把安慰剂当策略。反向自查也成立：明显低于同岗位市场水平的 offer，往往也说明这家公司对人的定价方式。

## 校准与复核
用第三方薪资参考校准预期（权威统计与行业报告，不要只用某个 App 的晒薪帖）。给自己设一个复核点：入职一年后回头看，当初的选择理由是否兑现。经济压力大到必须先解决现金流的，高薪没有错——此时短期收入不是选择题，是约束条件。

## 什么时候成长优先
- 两边薪资接近（差距在 10%–20% 以内），但一边有明确的带教与真实业务；
- 低薪那边能让你进入一个**以后很难从外部进入**的领域（例如核心研发、特定行业）；
- 高薪那边是支持性、重复性岗位，做三年后简历上没有可讲的东西；
- 你刚毕业，时间成本比现金更值得投入（前提是家庭能承受）。

```meta
summary: 长期找不到工作怎么办：先分清卡在哪一环、按环节改动作、管理现金流与心理状态，以及什么时候该换目标。
last_verified: 2026-10-06
```

「投了很多都没有结果」几乎总是**卡在某一环**，而不是整体不够好。把它拆成四环，逐环诊断，比继续加大投递量有效。

## 四环诊断
| 环节 | 症状 | 改法 |
| --- | --- | --- |
| 简历筛选 | 投递无任何回复（包括自动回复） | 改简历与定位：对齐 JD 关键词、删无关内容、突出可验证成果 |
| 测评/笔试 | 简历通过但止步笔试 | 限时练习题型，补基础（见 [在线测评](05-从学校走向第一份工作.md#job-hunting-written-test)） |
| 面试 | 有面试但过不了一面/二面 | 改表达方式：项目讲成「问题—动作—结果」，准备追问 |
| 终面/谈薪 | 到最后一轮被拒 | 多为匹配度或薪资预期问题，重新校准目标岗位 |

**诊断方法**：统计最近 30 次投递的漏斗（投递 → 回复 → 笔试 → 面试 → 结果），看在哪一步断崖式下降。

## 按环节的具体做法
- **简历**：把最近一段经历改写成「做了什么、结果如何、用什么方法」；一页；按 JD 调整顺序；
- **定位**：如果投的都是「够不着」的岗位，降一档投递更容易拿到反馈，再逐步上移；
- **渠道**：增加内推与官网渠道（见 [校友与内推](05-从学校走向第一份工作.md#job-channel-alumni)）；
- **面试**：每场后 24 小时内记录被问倒的问题，下一场前补上；
- **作品**：如果 20 份无回音，先补一个能展示的项目，再继续投；
- **反馈**：请业内朋友或做过面试官的人看一遍简历、做一次模拟面试——自己看不到的盲区，别人一眼就能看到。

## 现金流与时间安排
- **设定时间盒**：例如「三个月全职找工作」，同时准备后备方案（兼职、外包、实习转正、继续深造）；
- **保持结构化日程**：每天固定时段投递与练习，其余时间做项目或学习，避免整天焦虑；
- **接受阶段性收入**：短期兼职与外包不丢人，也能留下经历。

## 心理上的两个提醒
- **被拒不等于能力否定**：校招与社招的筛选有大量非能力因素（时间、名额、匹配度）；
- **不要把等待当作准备**：等待期间如果没有产出，三个月后你的处境会更差。

## 什么时候该换目标
- 同一方向连续三个月无任何面试机会，且已优化简历与渠道；
- 目标岗位的硬门槛你短期无法满足（学历、证书、年限）；
- 行业整体收缩（招聘量明显下降）——此时换相邻方向比死磕更现实。

**换目标不等于放弃**：最终进入的岗位，未必与最初设想的相同；先把目标调到「够得着且能积累」的位置，再逐步上移。

## 常见误区
- **用投递量代替诊断**：不看漏斗数据，只是每天多投十份；
- **只改简历、不改定位**：材料改了但目标岗位没变，命中率不会提升；
- **等状态好了再投**：等待期间没有产出，三个月后的处境只会更差；
- **把被拒当成能力否定**：校招与社招的筛选里，时间、名额与匹配度占很大比重；
- **不接受阶段性收入**：宁可不做兼职与外包，也不肯先有收入与经历。

### 要不要降低岗位要求

```meta

status: complete
stages: [new_grad, work_1_3, work_3_5]
topics: [job]
outputs: [work_experience]
effort: medium
evidence: [experience_based]

last_verified: 2026-09-27
```

「降低要求」不是认输，而是一种策略：**用更低的门槛进入目标行业，再在里面往上走**。前提是你要清楚降的是哪一项，以及有没有上升通道。

## 先分清降的是什么
| 降的维度 | 例子 | 风险 |
| --- | --- | --- |
| 降公司名气 | 大厂 → 行业中型公司 | 低（可能参与度更高） |
| 降岗位层级 | 正式岗 → 助理/初级岗 | 中（需要确认晋升路径） |
| 降薪资 | 接受更低的现金 | 中（后续涨薪受基准影响） |
| 降职能 | 研发 → 测试/支持，产品 → 运营 | **高**（再转回成本高） |

**最容易出问题的是最后一种**：职能降级往往伴随能力路径的改变，回头成本很高。

## 什么情况值得降
- 你缺的是**行业入口**，而不是技能（先进去，再往上走）；
- 新岗位能接触到你目标方向的核心业务（哪怕是支持性工作）；
- 新公司有明确的晋升或转岗机制（**要问到具体的例子**）；
- 时间压力现实（比如签证、空窗期、家庭需要收入）。

## 降到什么程度（三条底线）
1. **不降到与目标方向无关**：哪怕岗位小，也要在同一条能力线上；
2. **不降到没有上升通道**：问清「上一任是什么时候晋升的、晋升看什么」；
3. **不降到无法写入简历的下一段**：这段经历要能写成「做了什么 + 结果」。

## 降了以后怎么不掉进去
- 入职前把目标岗位的要求抄下来，作为你一年内的能力清单；
- 主动争取与目标方向相关的任务（哪怕不占你主要绩效）；
- 做记录与公开产出，让下一份工作有证据（见 [什么叫可验证成果](00-从这里开始.md#judge-verifiable-outcomes)）；
- 设一个复盘点（例如一年），看是否更接近目标岗位，不接近就换。

## 什么时候不该降
- 降了之后完全偏离目标方向，且行业收缩；
- 公司没有明确晋升机制，只是长期缺人；
- 薪酬降到无法覆盖必要支出（会让你很快再跳，反而更不稳定）；
- 你的问题其实是「面试表达」而不是「竞争力不足」（这种情况先改简历与面试）。

## 降门槛通常是理性的
从头部公司降到中型公司、从高薪岗位降到中等薪资、从一线城市核心岗降到同类岗位的其他城市——这类调整不损失方向，损失的是起点光环与短期收入，换回的是进入真实工作、积累可验证产出的机会。在一段空窗期开始拖长时，这往往是划算的。

## 降方向要更谨慎
从目标岗位转到完全不同的岗位类型（例如从开发转到纯销售），损失的是方向积累，而方向恰恰是最难补的东西。如果必须接受，优先选**仍能用上你可迁移技能**的岗位（见 [可迁移技能](07-当职业开始出现分岔.md#career-transferable-capital)），把这段经历当成过渡而不是终点。

## 怎么判断与回退
给自己设一条线：现金流能撑几个月？低于三个月时，先接受一份过渡工作保住节奏，同时继续投目标岗位——骑驴找马不丢人。回退成本上，降门槛容易回退（下一份工作可以再往上跳），降方向回退较难。见 [长期找不到工作怎么办](05-从学校走向第一份工作.md#job-hunting-long-search)。

### 要不要换城市

```meta
id: job-change-city
status: complete
stages: [new_grad, work_1_3]
topics: [job]
outputs: [work_experience]
effort: medium
evidence: [official, industry_data, experience_based]
summary: 要不要换城市：行业密度与成本怎么比较、换城市的隐性代价，以及降低风险的做法。
last_verified: 2026-09-27
```

换城市的决策，本质是**用迁移成本换行业密度**。判断方法是把两边的机会数量与生活成本放在同一张表上，再加三项隐性代价。

## 比较框架
```
目标城市的岗位数量（目标岗位） vs 当前城市
+ 薪资水平差异
− 生活成本差异（房租、通勤、餐饮）
− 一次性成本（搬家、押金、探亲）
− 隐性代价（关系网络、社保与落户年限、家庭照护）
```

**岗位数量是最容易被忽略的一项**：在招聘平台搜你的岗位，看两城的数量差，通常比想象的更明显。

## 三项隐性代价
1. **关系网络**：在原城市积累的同行、朋友与机会需要重新建立；
2. **社保与落户**：缴费年限与当地政策会影响买房、子女入学与医保待遇（**以当地当年政策为准**）；
3. **家庭与情感**：探亲成本、照护责任、伴侣的工作安排。

## 什么情况值得换
- 你的行业在目标城市明显聚集（更多岗位、更高薪资、更强的同行生态）；
- 在原城市已经连续投递无果，且原因是岗位供给而非能力；
- 公司提供明确的外派或调动支持（搬迁补贴、临时住宿）；
- 你有可迁移的成果（不依赖本地关系也能找到下家）。

## 降低风险的做法
1. **先拿到书面 offer 再搬**（含薪资、岗位、报到时间、是否有搬迁支持）；
2. **保留社保连续性**：问清转移与衔接方式（跨省转移规则以当地规定为准）；
3. **准备一份回退预算**：至少能支撑三个月的开支与返程；
4. **把成果放在可携带的地方**（公开作品、行业社群），避免完全依赖本地关系。

## 三步判断
1. **行业密度**：搜目标岗位的在招数量与公司数量，看集中在哪些城市。行业在地理上高度集中而你又不想离开现在的城市，要么换城市要么换行业，两头都要是要付额外代价的；
2. **真实收入**：算「税后收入 − 房租 − 通勤时间的折算」，而不是只比名义薪资。名义高但房租与通勤吃掉的部分，常常被低估；
3. **政策环境**：查目标城市的落户、人才补贴与住房政策（当地政府官网，政策会调整，别假定永远不变）。

## 回退与风险
城市可以换，但每次迁移都有成本（搬家、社保衔接、关系网络重建）。降低风险的方式是把「想走随时能走」的行业技能留在自己身上，见 [可迁移技能](07-当职业开始出现分岔.md#career-transferable-capital)。

### 要不要继续升学

```meta
id: job-or-further-study

outputs: [degree]

last_verified: 2026-09-27
```

工作之后再考虑升学，判断标准与应届时不同：**你放弃的不只是收入，还有正在积累的职业位置**。

## 第一步：确认学历是不是硬门槛
翻十五到二十条目标岗位 JD：

- 多数写「硕士及以上」→ 升学是必要条件；
- 多数写「本科及以上」或「经验优先」→ 需要其他理由（例如行业进入通道、身份、转方向）；
- 部分通道（高校、研究院、部分资格）有明确学历线 → 以官方文件为准。

## 工作几年后的特殊成本
```
直接成本（学费、书本、可能的住宿）
+ 机会成本（放弃的薪资 × 学制年数）← 通常最大
+ 职业中断（晋升节奏、团队位置、关系网络）
+ 身份与手续（档案、社保、户口衔接）
− 资助与可能的收入（助研/兼职）
```

**在职与脱产的差别主要在这里**：在职保留收入与位置，代价是时间与精力；脱产学习更完整，代价是收入与职业连续性。

## 三种常见动机与对应选择
| 动机 | 更适合 |
| --- | --- |
| 目标岗位需要硕士学位 | 全日制或非全日制学历项目（查清是否要求全日制） |
| 想转行业或转职能 | 有转行通道的项目（如 MBA/MPA、第二硕士；见 [MBA / MPA 等职业学位](07-当职业开始出现分岔.md#edu-mba-mpa)） |
| 想补知识（本行深造） | 在职项目或短期课程，不必脱产 |
| 想换环境/缓冲 | 先做减法（换团队、休假），读书不是最优解 |

## 判断顺序
```
1. 目标岗位是否真的需要这个学位（用 JD 验证）
2. 在职还是脱产（比较净投入与职业中断）
3. 报考条件（年限、学历、是否要求定向培养）
4. 回退方案（读完达不到预期时的备选）
```

**第 4 条常被跳过**：先想清楚「如果读完没有达到预期，我还有什么」，再决定投入。

## 什么时候不值得
- 目标岗位不看学历，而你看重的是收入与经验；
- 只是「不知道做什么，先读着」（把不确定推迟并附上成本）；
- 家庭现金流不允许，且没有明确资助来源。

## 先看门槛
找二十条目标岗位的招聘公告，看「学历要求」一栏：如果普遍写「硕士及以上」，学历是硬门槛，早晚要补；如果普遍写「本科及以上」或「能力优先」，那学历的边际价值要单独算。门槛存在时，升学解决的是一个具体问题（入场券），这时回报最明确。

## 再算成本
升学成本不只是学费：还包括两到三年的时间与收入损失（机会成本通常是最大的一块），以及读期间是否真的产出可验证的东西。判断方法见 [为教育投入多少钱才合理](01-先决定下一步往哪里走.md#education-cost-budget)。

## 哪些情况可以先工作
目标行业看作品与经验；家庭需要现金流；你已经有一段明确的方向、只是缺时间积累。工作后再读也完全可行（非全日制、海外申请、同等学力等通道都开放），见 [工作后重新读书](06-进入职场以后继续积累.md#work-study-again)。

## 一次低成本验证
先做三个月的目标岗位实习或项目：如果这段时间你明确感到「被学历卡住」，升学的判断就有了依据；如果卡住的是能力而不是学历，先补能力。

### 空窗期怎么处理

```meta
id: job-gap-period
status: complete
stages: [new_grad, work_1_3, work_3_5]
topics: [job]
outputs: [work_experience]
effort: medium
evidence: [official, experience_based]
summary: 空窗期怎么处理：哪些原因需要解释、怎么写才可信、期间可以补什么，以及常见失误。
last_verified: 2026-09-27
```

空窗期本身不是问题，**没有可说明的产出**才是。处理方式是：如实说明 + 说明这段时间的产出或方向。

## 先分类：你是哪种空窗
| 类型 | 例子 | 面试时怎么说 |
| --- | --- | --- |
| 备考型 | 考研、考公、考语言 | 说明目标、结果、期间的产出 |
| 休整型 | 身体、家庭照护、心理状态调整 | 简要说明，重点说现在的状态与规划 |
| 探索型 | 做项目、学技能、做副业 | 说明做了什么、留下了什么证据 |
| 被动型 | 被裁、项目结束、公司变动 | 说事实，不评价前雇主，说明现在的方向 |

**共同原则**：不编造、不夸大、把重点放在「这段时间我做了什么」和「为什么现在准备好了」。

## 怎么写才可信
```
一句说明原因（不展开抱怨）
+ 期间的产出（项目、学习成果、资格证书、写作或开源）
+ 与现在岗位的连接（为什么这段经历不影响你胜任）
```

**有产出就建议写出来**：哪怕是一个完整的项目、一篇技术文章、一次开源贡献。

## 期间可以补什么（按性价比）
1. **一个可展示的项目**（最能填补简历空白）；
2. **与目标岗位相关的资格或课程**（要能拿出证书或作品）；
3. **兼职、外包、志愿工作**（真实经历，哪怕规模小）；
4. **公开产出**（文章、开源、数据集）。

## 时间线要保持一致
简历、面试、背调与社保记录之间不能有矛盾：

- 写清起止月份（以合同、离职证明或社保记录为准）；
- 不要为了「好看」调整时间（背景核实会发现问题）；
- 短于三个月的经历可以合并或省略，但不要伪造（见 [背调](05-从学校走向第一份工作.md#job-hunting-background-check)）。

## 常见误区
- 只说「休息了一段时间」，没有任何产出；
- 过度解释私人原因（面试官不需要细节）；
- 抱怨前雇主或行业（会被记为风险）；
- 编造一段经历（风险极高，且容易被追问）。

## 特殊情形：应届择业期与身份
部分政策对应届生与择业期有界定（**各地与各校规定不同**），如果空窗涉及身份问题，提前问学校就业中心与相关部门，不要凭他人经验判断。

## 空窗期里该做什么
- 补一块具体的能力或产出：一个完整的小项目、一门与目标岗位直接相关的课程、一次真实兼职或志愿项目——它们让这段时期有可讲的内容；
- 保持与行业的接触：参加活动、维护作品集、定期投递；
- 记录这段时间的计划与结果，面试时能拿出具体材料。

## 面试里怎么讲
讲「为什么 + 做了什么 + 现在为什么回来」，控制在两三句：说明原因（照顾家庭、准备考试、调整方向等真实原因即可），讲这段时间的具体产出，说明现在的状态与动机。不要过度辩解，也不要含糊其辞——背调时会核实任职时间，见 [背调](05-从学校走向第一份工作.md#job-hunting-background-check)。

## 什么时候需要更主动
空窗超过三个月且投递没有回音时，按 [长期找不到工作怎么办](05-从学校走向第一份工作.md#job-hunting-long-search) 做一次诊断：问题通常在定位与材料，不在投递量。现金流紧张时，先接受过渡性工作保住节奏。

入职后发现选择不理想很常见。先分辨是哪一种「错」：**方向错**（这个岗位/行业本身不是你想做的）还是**环境错**（方向对，但团队、上级或公司不合适）。

## 两种错的不同解法
- 环境错：优先内部转岗、换团队，或在同一方向上跳槽。这类调整保留了方向积累，成本最低，见 [内部转岗](06-进入职场以后继续积累.md#work-internal-transfer)；
- 方向错：先确认是不是真的错——很多「不喜欢」来自最初几个月的生疏期，通常三到六个月后会变化。确认后要走，就按 [转行前先判断什么](07-当职业开始出现分岔.md#switch-before-decide) 的思路走，优先选能带走可迁移能力的下一站。

## 成本与时机
离开的成本包括时间损失、解释成本，以及可能的竞业限制。多数情况下，**一年内纠错的代价远小于硬扛三年**；但频繁短期离职会增加后续筛选成本，所以要给自己设一个判断期（例如六个月）：在判断期内先做补救动作（换项目、找导师、补技能），到期仍无改善再走。

## 这段经历怎么用
无论去留，把这段时间做成的具体事情整理成材料——它们是下一次面试的依据，也是你讲「我为什么换方向」的素材。见 [怎么记录职业成果](06-进入职场以后继续积累.md#work-record-achievements)。
