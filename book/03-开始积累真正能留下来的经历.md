### 什么才算真正的项目

```meta

status: complete
stages: [college, undergraduate, master, secondary_vocational, new_grad]
topics: [project]
outputs: [project, work_experience]
effort: low
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  一个“真正的项目”要满足三个要素：**解决一个具体的真实问题**（哪怕是自己的）、**有别人可验证的产物**（能运行、能看、能用）、**经历了至少一次真实的反馈与修改**。三者缺二，它更接近一次练习。

- 适合谁：
  需要用作品证明能力的学生与转行者；不确定自己的东西算不算“项目”的人。

- 不太适合谁：
  ——（标准本身对所有人都适用；不必用它否定做过的练习，练习有练习的价值。）

- 能换回什么：
  简历上经得起追问的一行；面试时能讲 20 分钟的故事；对“完成”的真实理解。

- 要付出什么：
  数周到数月；真实的迭代（这一步最容易被跳过）。

- 怎么开始：
  1. 写一句话问题陈述：为谁、解决什么、怎么算解决。
  2. 缩到一个月内能出第一版可用的规模——完成一个小而真的项目，胜过规划一个大而空的。
  3. 上线或交付给至少一个真实用户（用户可以是自己持续使用、可以是同学同事），收集反馈。
  4. 按反馈做第二轮修改，记录改了什么、为什么。
  5. 把过程沉淀为 README 与演示（见 [作品集](03-开始积累真正能留下来的经历.md#project-portfolio)）。

- 常见误区：
  把跟教程做的东西当项目；只有代码没有使用者；规划宏伟、从未完成；没有版本二，反馈环节完全缺失。

- 下一步可能打开什么：
  作品集的核心件；面试叙事；真实用户的意外反馈（常常指向下一个项目）。

- 证据与来源：
  - 项目能力评估的普遍经验。 （Experience-based）

- 最后核实：
  2026-09-21

## GitHub 项目做到什么程度才算项目经历



- 一句话：
  三个问题就够了：有没有人用它、能不能被验证、别人能不能在五分钟内看懂并跑起来。过不了这三关的，可以叫练习，但不要写进简历当经历。

- 适合谁：
  想用项目补简历的人；在校生与转行者；面试被问到“讲一个你做的项目”却答不上来的人；有技术能力但缺少可展示产出的人。

- 不太适合谁：
  目标岗位不通过项目评估的情况（以考试、资历、执业资格为主要筛选的岗位）。这时应把时间投到对应门槛上，而不是硬做项目。

- 能换回什么：
  可验证的作品；面试中的具体话题（能深聊半小时的项目远胜十个 demo）；技能证明；真实用户反馈；公开贡献记录；有时还有工作或合作机会。

- 要付出什么：
  几十到几百小时；维护成本（Issue、文档、兼容、更新）；被指出 bug 与被批评的心理成本；发布之后持续的投入——这一点最常被低估。上线不是结束。

- 怎么开始：
  1. 从自己的真实需求出发，选一个**小而完整**的题目：解决一个你每周都会遇到的问题，而不是做一个大而空的“平台”。
  2. 定义“做完”的标准：可运行的入口 + README + 最小测试 + 至少一个真实用户。缺一项都还没到可以展示的程度。
  3. README 五要素：一句话说明是什么；用在什么场景；怎么安装运行；演示（截图、GIF 或在线地址）；已知限制。
  4. 先做能在两周内跑通的版本，再迭代。不要憋大招。
  5. 找 1–3 个真实用户（同学、社群、同事），收集反馈，把反馈与处理写进 README 或 Issue。
  6. 写进简历时用“问题 → 做法 → 结果”的格式，结果要能量化：用户数、处理量、耗时、误差、节省的时间。不要写“使用 X 框架实现了 Y”。

- 常见误区：
  项目多而浅——十个半成品不如一个有真实用户的项目；没有 README，或 README 只列技术栈；把教程项目当原创（面试官看得出来）；只有 commit 记录没有交付；不写限制与不足，反而降低可信度；把 star 数当唯一指标（star 受推广影响大于质量）；项目无法在你自己的机器上重新跑起来。

- 下一步可能打开什么：
  开源贡献与维护者角色；面试中的深挖环节；实习与工作机会；技术社群与同行关系。

- 证据与来源：
  - GitHub 官方文档：README、许可证、Issue 与 Pull Request 的规范与实践。https://docs.github.com/ （Official）
  - 开源项目的贡献指南（CONTRIBUTING）、行为准则与治理文件，是其所在仓库的权威依据。 （Official）
  - “项目经历在招聘中的权重”因岗位而异，缺少统一统计，本条只给出可验证性的判断方法。 （Experience-based）

- 最后核实：
  2026-09-21


### 教程项目有没有价值

```meta
id: project-tutorial
status: complete
stages: [highschool, college, undergraduate, secondary_vocational]
topics: [project, skill]
outputs: [work_experience]
effort: low
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  教程项目是学习工具，不是能力证明——**面试官看一眼就知道它是教程，因为教程项目长得都一样**。它的问题不在“做了”，而在“没有做任何教程之外的决定”。

- 适合谁：
  初学者（认真跟完、改出变化的教程项目是有价值的阶段）；想补齐技术栈的人。

- 不太适合谁：
  把三四个教程项目放进简历核心位置的人；跟完教程连改一个需求都不会的人。

- 能换回什么：
  技术栈的初始理解；一套可改造的代码基底。

- 要付出什么：
  教程本身的数小时到数周；如果止步于此，沉没的是本可以做真实项目的时间。

- 怎么开始：
  1. 跟完教程后立即做“改造练习”：换数据源、换核心功能、加一个教程没有的需求。
  2. 遇到教程没覆盖的问题，查官方文档解决——这一步才是真实工作的常态。
  3. 把改造后的版本作为第一个“自己的项目”，写清与原教程的差异。
  4. 简历上不写教程项目原样，只写你在其之上做出来的东西。

- 常见误区：
  跟完教程就放进简历；连续跟五六个教程获得“学了很多”的错觉；从不脱离教程自主排错。

- 下一步可能打开什么：
  第一个真实项目（见 [什么叫真正的项目](03-开始积累真正能留下来的经历.md#project-what-is-real)）。

- 证据与来源：
  - 招聘方对教程项目的普遍判断。 （Experience-based）

- 最后核实：
  2026-09-21


### 第一个个人项目怎么开始

```meta
id: project-personal
status: complete
stages: [college, undergraduate, master, secondary_vocational, new_grad, work_1_3]
topics: [project]
outputs: [project, work_experience]
effort: medium
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  个人项目的价值公式是**真实需求 × 完成度 × 展示质量**。一个可靠的选题方向是“给自己解决一个真实痛点”——因为需求真实、你懂用户、还能长期维护。

- 适合谁：
  需要作品的学生与转行者；有真实小痛点愿意自己动手解决的人。

- 不太适合谁：
  选题追热点但自己不用的人（做不出来也留不住）；同时开五六个项目、每个都半成品的人。

- 能换回什么：
  一个能演示、能讲述、能迭代的作品；完整的问题定义—实现—维护经验；可能的真实用户。

- 要付出什么：
  数周到数月的业余时间；维护的长期成本（一个有人用的项目会持续要你修东西）。

- 怎么开始：
  1. 列出你每周重复做、又麻烦的事，挑一个能用程序或流程解决的。
  2. 第一版限制在两周内能用，功能只留最核心的三个。
  3. 自己真实使用两周，记录所有别扭的地方——这是第二轮的清单。
  4. 给它一个干净的 README：解决什么、怎么用、截图或演示。
  5. 有真实用户后，认真处理反馈，哪怕每月只有一两条。

- 常见误区：
  技术炫技但无人受益；功能膨胀导致烂尾；上线后再也不维护；README 空到没人知道怎么跑起来。

- 下一步可能打开什么：
  作品集的核心件；面试叙事；甚至一款小生意的起点（见 [创业、自由职业与副业](08-其他同样成立的人生路径.md#startup-side-project)）。

- 证据与来源：
  - 个人项目经验的普遍规律。 （Experience-based）

- 最后核实：
  2026-09-21


### 团队项目

```meta
id: project-team
status: complete
stages: [college, undergraduate, master, secondary_vocational, work_1_3]
topics: [project, community]
outputs: [project, work_experience, network]
effort: medium
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  团队项目练的是个人项目练不到的东西：**分工、约定、依赖别人的进度、以及吵架之后还能把事做完**。雇主看团队项目，看的正是这些信号。

- 适合谁：
  缺协作证据的学生；想做比个人能力更大的事的人。

- 不太适合谁：
  找不到靠谱队友、每次都自己扛所有事的人（不如先做个人项目）；为组队而组队、目标不一致的草台班子。

- 能换回什么：
  真实的协作与版本管理经验；规模更大的产出；可以互相背书的队友。

- 要付出什么：
  沟通成本（经常超过预期）；进度被队友拖累的风险；利益与署名的提前约定。

- 怎么开始：
  1. 三到五人、能力互补、时间表能对齐——这三条缺一就先别开工。
  2. 开工前书面约定：目标、分工、代码与文档归属、谁对外负责。
  3. 用真实的协作工具与流程：任务看板、代码评审、每周同步。
  4. 每个阶段都有可交付物，而不是最后一个月赶工。
  5. 结束后互相写具体的评价（比“合作愉快”有用得多）。

- 常见误区：
  一人干活全队署名；没有约定，成果归属扯皮；把“开会多”当协作好；烂尾后互相拉黑。

- 下一步可能打开什么：
  面试中的协作证据；一段可验证的伙伴关系；更大的项目。

- 证据与来源：
  - 团队协作项目的普遍经验。 （Experience-based）

- 最后核实：
  2026-09-21


### 作品集

```meta
id: project-portfolio
status: complete
stages: [college, undergraduate, master, secondary_vocational, new_grad, career_change]
topics: [project]
outputs: [project, work_experience, optionality]
effort: low
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  作品集不是项目列表，是**按目标岗位组织的能力证据**：三个打磨过的项目加清晰的讲述，胜过十个仓库链接。评审平均只给每个项目一两分钟，所以第一屏就要回答“这是什么、解决了什么、做得怎么样”。

- 适合谁：
  找实习与工作的人；转行需要证据的人；接单与自由职业者（给客户看的能力陈列）。

- 不太适合谁：
  只搬运 README、没有任何自己加工的人。

- 能换回什么：
  简历通过率；面试中的主动权；对自身能力结构的清晰认识。

- 要付出什么：
  每个项目的整理时间（写清、截图、录演示各需数小时）；定期维护。

- 怎么开始：
  1. 选三个最能代表目标岗位能力的项目，宁缺毋滥。
  2. 每个项目写统一结构：问题 → 你的方案 → 关键难点与解决 → 结果（数字或演示）→ 链接。
  3. 给每个项目配 30 秒内能看完的演示（截图或录屏），评审点开就能看懂。
  4. 排序按“与目标岗位的相关度”，不是时间倒序。
  5. 每半年更新一次：删掉过时的，替换更强的。

- 常见误区：
  十个仓库全是半成品；只有代码没有讲述；简历与作品集口径不一致；链接失效或打不开。

- 下一步可能打开什么：
  更高的面试转化；清晰的自我定位。

- 证据与来源：
  - 作品集评审的普遍经验。 （Experience-based）

- 最后核实：
  2026-09-21

## 怎么识别“付费拿奖”的竞赛



- 一句话：
  典型特征是三条里至少中两条：主办方是商业或培训中介机构；获奖比例高得异常（“参与即获奖”“人人有奖”）；奖项在官方名单、高校认定或企业招聘里都查不到。收费本身不等于无效，但这三条是核查的起点。

- 适合谁：
  正在被推销“国际竞赛名额”的学生与家长；需要判断某个比赛要不要交钱的人；负责审核学生获奖材料的教师与人事。

- 不太适合谁：
  已经确认该奖项在本校或目标单位被明确认可的情况——按已知事实处理，不必套用本条。

- 能换回什么：
  避免几千到几万元的无效应支出；把时间放到有实际回报的地方；一份可以反复使用的核查清单。

- 要付出什么：
  半小时核查时间；以及在“名额有限”“今天是最后一天”这类话术面前不立刻付款的定力。

- 怎么开始：
  1. **查主办方**：政府部门、学术组织、行业协会、学校，还是培训机构或中介？只有最后一类需要警惕，但它出现的频率很高。
  2. **查获奖比例与评审规则**：有没有评分标准、评委名单、获奖名额上限。写“人人有奖”的，价值通常很低。
  3. **查外部认可**：是否出现在教育部门公布的竞赛名单里；本校教务处或学院是否认定；目标企业或奖学金评定是否认可。三条都查不到时非常谨慎。
  4. **查往届痕迹**：往届获奖者是谁、作品能不能公开查到、后续发展如何。查不到任何往届痕迹的“国际大赛”要警惕。
  5. **算替代方案**：如果目的只是“简历上有一行奖”，把同样的钱与时间投在一个有真实用户的小项目上，产出通常更硬。
  6. 确实要交费时，索取章程与发票，看清退费条款。

- 常见误区：
  把“国际”“全球”“名校主办”当成含金量标准（多数只是名称）；相信“有助于留学申请”这类没有来源的承诺；用收费竞赛的证书替代真实能力证明；报名后才去核对本校是否认定，结果在评奖评优时不被承认；把“参加人数多”当成认可度高；认为收费就一定有用（实际回报取决于评价是否严格）。

- 下一步可能打开什么：
  把省下的时间投入有真实评审的比赛或项目；回头核查已有奖项的实际含金量；理解“资历”是如何被第三方承认的。

## 国际竞赛



- 一句话：
  国际竞赛的判断标准只有一条：**它在目标评价体系里是否被认可**。学科奥赛、顶级学生赛事的奖牌信号很强；而需要付费参加、获奖比例高、回国后没人认得的“国际”赛事，多数只有体验价值（见 [怎么识别“付费拿奖”的竞赛](03-开始积累真正能留下来的经历.md#competition-what-worth-joining)）。

- 适合谁：
  走强基、竞赛保送、海外申请路径的学生；所在领域确有国际公认赛事的人。

- 不太适合谁：
  只为简历加一行英文的人；需要先付费后筛选、且无法在官方体系查证的项目。

- 能换回什么：
  强认可赛事：保研与升学中的硬信号、国际同行的网络；弱认可赛事：一段经历与视野。

- 要付出什么：
  长周期备赛；报名、差旅、签证成本；部分赛事的参赛费用不低。

- 怎么开始：
  1. 先确认认可度：问目标院校、目标行业的评价者“这个奖你们怎么看”，而不是问主办方。
  2. 核查主办方与选拔机制：正规国际赛事有公开的国家队选拔或区域选拔（如学科奥赛由中国科协相关机构组织选拔）。
  3. 核查费用结构：报名费、培训费、差旅费分别是谁承担、多少，警惕“参赛＋高价培训”打包销售。
  4. 评估性价比：同样的时间投入在国内认可赛事或科研项目上，信号会不会更强。

- 常见误区：
  被“国际”两个字唬住；分不清主办国行业协会与商业公司办赛的区别；为拿奖付出远超信号价值的成本。

- 下一步可能打开什么：
  强认可赛事：升学与申请的硬通货；任何赛事：一段国际化的经历。

## 先看这个比赛能不能留下东西

可以按产出分类：

- **作品型**：设计、写作、Hackathon、Game Jam、程序设计——留下可展示的东西。
- **数据型**：数学建模、数据竞赛——留下方法与报告。
- **团队型**：商业案例、创业竞赛——留下协作经历与对某个行业的理解。
- **技能型**：职业技能竞赛、行业赛事——留下可被行业认可的等级或证书。

只有证书、没有产出的比赛，价值主要落在“参与”上，需要按你的目标判断值不值。

## 奖项与过程哪个更重要，取决于你缺什么

需要过门槛（保研加分、部分招录认定）时，看的是奖项的被认可度；需要能力与作品时，看的是过程的密度。两者都缺的人很少，多数人只需要补其中一项。

## 怎么判断一个比赛值不值得

1. 查主办方：是学会、高校、行业协会，还是以收费为主的公司。
2. 查评审：有没有公开的评审规则与获奖公示，往届作品能不能看到。
3. 查时间成本：准备周期与你当前的主线冲突吗。
4. 查认可范围：目标学校或目标企业的评价体系里，它算不算数——问评价者，不要问主办方。

## 哪些比赛只有练习价值

面向中小学生但被包装成“国际赛事”的、报名即获奖比例极高的、必须购买培训才能参赛的、获奖名单不公开的。这类比赛的共同点是：**它的收益主要在收费环节**。识别方法见 [怎么识别“付费拿奖”的竞赛](../book/11-避坑.md#trap-paid-competitions)。

## 参加之后

无论结果，把产出一并收好：作品链接、报告、复盘。这些是下一次面试时真正能拿出来讲的东西。

### 奖项和过程哪个更重要

```meta
outputs: [award, work_experience, network]
```

- 一句话：
  奖项的作用是**通过别人的筛选门槛**（保研加分、简历筛选、落户加分），过程的作用是**长在你自己身上的能力**。前者依赖比赛的外部认可度，后者依赖你的投入方式——所以“值不值得”不能只看获奖率，要看两样东西你缺哪个。

- 适合谁：
  需要奖项通过硬门槛的人（保研综合测评、部分城市落户加分）；需要能力与作品的人。

- 不太适合谁：
  两者都不缺的人（用这段时间做项目或科研往往复利更高）；指望用一次获奖逆转所有局面的。

- 能换回什么：
  奖项侧：证书、加分、简历行；过程侧：队友协作经验、真实作品、对某个技能的集中训练、一段能讲的故事。

- 要付出什么：
  数周到数月的备赛；报名与差旅成本（部分赛事由学校承担，部分自费，见 [怎么识别“付费拿奖”的竞赛](03-开始积累真正能留下来的经历.md#competition-what-worth-joining)）；与课业冲突的风险。

- 怎么开始：
  1. 先写下你缺哪个：门槛证明还是能力证据。缺门槛，选认可度高、赛道匹配的；缺能力，选过程密度大的。
  2. 查往届获奖作品的水平：获奖线远超你现在水平且备赛时间不足，多数人是陪跑。
  3. 组队比比赛本身重要：找能力互补、时间能对齐的人。
  4. 把参赛产出设计成双重用途：作品同时是简历项目、比赛同时是能力证明。
  5. 无论拿不拿奖，赛后写复盘：学到的方法、作品链接、下届要不要再来。

- 常见误区：
  用报名费衡量价值（免费的比赛也可能浪费一学期）；只冲奖不沉淀过程；拿了奖但作品拿不出手；年年参赛年年陪跑不复盘。

- 下一步可能打开什么：
  简历上的一行硬通货；能力与作品；一两个长期队友。

- 证据与来源：
  - 比赛价值判断的普遍经验。 （Experience-based）

- 一句话：
  数学建模类竞赛的核心价值是**在 72–96 小时内完整走一遍“把现实问题翻译成数学问题、求解、写成论文”的流程**——这个训练对理工、经管、生物、环境等几乎所有需要数据分析的专业都通用。本科组与专科组分开评奖，高职高专学生同样有专属赛道。

- 适合谁：
  会一点编程或统计、想集中训练分析能力的人；专业需要数据建模（生物、环境、经济、工程等）的人；需要团队协作证据的人。

- 不太适合谁：
  数学或编程基础接近零且没时间补的人；指望靠赛前突击一个月拿国奖的人。

- 能换回什么：
  一篇完整建模范式的论文；建模、编程、写作的三人协作经验；保研与评奖中被广泛认可的奖项（国家级奖项含金量高）。

- 要付出什么：
  三天四夜的比赛本身；赛前数月的训练（真题模拟至少三轮）；组队磨合成本。

- 怎么开始：
  1. 主赛：全国大学生数学建模竞赛，创办于 1992 年，每年 9 月举行，由中国工业与应用数学学会主办，官网 http://www.mcm.edu.cn ，报名与论文提交经竞赛管理系统进行；参赛费用由学校按标准承担，学生一般不直接向全国组委会交费。
  2. 组队按“建模 + 编程 + 写作”三角色互补，赛前用往年真题完整模拟。
  3. 留意竞赛的 AI 工具使用规定（2026 年起试行），违规使用会被取消评奖资格。
  4. 美赛（COMAP 主办的 MCM/ICM）是平行选择，注意它与国赛的时间、赛制不同，报名费自理，按官网为准。

- 常见误区：
  三个人都会编程却没人会写作；赛前只看不练；比赛第一天选题犹豫耗掉半天；把 AI 生成内容当解题（违反规则）。

- 下一步可能打开什么：
  保研综合测评的加分项；数据分析与算法岗位的能力证据；持续合作的队友。

- 证据与来源：
  - 全国大学生数学建模竞赛官网（章程、参赛规则、AI 工具使用规定）：http://www.mcm.edu.cn （Official）
  - 中国工业与应用数学学会：http://www.csiam.org.cn （Official）

## Hackathon



- 一句话：
  Hackathon 的价值几乎全在过程：**48 小时内把一个想法做成能演示的原型**。它是最便宜的“从零到一”训练，也是认识做事靠谱的同伴的高密度场景——奖项反而是次要的。

- 适合谁：
  想体验完整产品构建的人；想找合伙人或队友的人；有技能（写代码、做设计、做产品）想快速组合运用的人。

- 不太适合谁：
  期待产出可直接上线的完整产品的人（原型就是原型）；熬夜两天的身体成本承受不了的人。

- 能换回什么：
  一个可演示的原型；产品—设计—技术的完整协作体验；社交网络；部分比赛由企业命题，可能带来面试直通或赞助商关注。

- 要付出什么：
  一个周末；通常免费或低报名费（正规 hackathon 一般不收费，收费的要警惕）。

- 怎么开始：
  1. 选比赛：学校社团、科技企业、开发者社区都有举办，优先选有明确评审与真实赞助方的。
  2. 赛前定好分工与选题方向，现场再微调——现场组队搭_zero 信任的团队成功率低。
  3. 目标设为“能跑的 demo + 能讲的故事”，而不是功能完整。
  4. 结束时把代码放公开仓库、写一篇复盘，让这个周末留下长期证据。

- 常见误区：
  追求完美架构导致 demo 都跑不起来；组队只看关系不看互补；赛后什么都没沉淀。

- 下一步可能打开什么：
  一个能进作品集的原型；靠谱的队友或合伙人；企业的关注。

  - Hackathon 组织的普遍经验。 （Experience-based）

## 人工智能与数据竞赛



- 一句话：
  AI 与数据竞赛（Kaggle 是代表）的价值在于**在真实数据集上解决一个有评测标准的问题**，产出可以直接写进简历：“方案排名前 x%”比“学习过机器学习”有力得多。它的门槛比算法竞赛低，训练效果的确定性更高。

- 适合谁：
  会 Python 与基本机器学习方法的人；想转入数据、算法方向的人；需要与真实业务数据打交道的专业（金融、医疗、工业）。

- 不太适合谁：
  编程基础尚未建立的人（先补基础）；只看教程不动数据的人。

- 要付出什么：

  3. 把比赛成果整理成报告或代码仓库，投岗位时直接给链接。
  4. 团队赛注意分工与提交纪律；个人赛先稳定流程再冲榜。

  追榜单忘记沉淀方法；比赛做了一堆、简历上写不出来；用奖金赛的收入预期做决策（头部化严重）。

## Game Jam



- 一句话：
  Game Jam 是**在限定时间（通常 48–72 小时）内围绕一个主题做出一款小游戏**。它检验的不是技术深度而是“把创意完整落地”的能力——对想进游戏行业或练产品设计的人，一次认真对待的 jam 胜过十个烂尾项目。

- 适合谁：
  想进游戏行业的学生；想做设计、叙事、玩法验证的人；有编程、美术、音频任何一项技能的人。

- 不太适合谁：
  指望 jam 作品直接商业化的；无法接受粗糙成品的人（ jam 的产物就是粗粝的）。

- 能换回什么：
  一款可玩、可分享的小游戏；玩法设计与快速原型能力；游戏社区的同伴（Ludum Dare、Global Game Jam 等社区的参与感很强）。

- 要付出什么：
  一个周末；免费开源工具即可（引擎、美术素材库大量免费）。

- 怎么开始：
  1. 从线上 jam 入门（如 Ludum Dare，官网 https://ldjam.com ），线下活动（Global Game Jam，https://globalgamejam.org ）按官方渠道报名。
  2. 第一次参加目标设为“完成”，不做完比做得丑更可惜。
  3. 控制范围：一个核心玩法循环打磨到能玩，远胜五个半成品系统。
  4. 赛后把游戏发布到 itch.io 等平台并收集反馈，这就是作品集的一页。

- 常见误区：
  第一次就想做大世界；只写设计文档不动手；赛后不发布不收集反馈。

- 下一步可能打开什么：
  作品集里的第一款完整作品；游戏行业的入场谈资；持续的创作社区。

## 科研初体验

### 科研到底是什么

```meta
id: research-what-is-research
status: complete
stages: [undergraduate, master, phd]
topics: [research]
outputs: [research_experience, paper, recommendation]
effort: medium
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  科研的本质是**产出新的、可检验的知识**：先问出一个还没被回答的问题，再用别人能重复的方法回答它。它与“看论文”“在实验室待着”“帮老师干活”都不是一回事——没有问题、方法与可检验结论的，不构成研究经历。

- 适合谁：
  对某个具体问题有持续好奇、愿意花几个月弄清楚一件事的人；需要研究经历支撑深造的人。

- 不太适合谁：
  只想要一段经历装点简历、不打算回答任何问题的人；无法忍受数月不出结果的人。

- 能换回什么：
  研究经历与（可能的）论文；导师与同行的推荐信；一套“提出问题—设计方案—验证—表达”的方法论（它迁移到任何行业都值钱）。

- 要付出什么：
  以月计的持续投入；大部分时间在重复、失败与改错；成果的随机性（同样的投入可能没有产出）。

- 怎么开始：
  1. 选一个你有真实好奇的具体问题，而不是“一个领域”。
  2. 读该问题下最常被引用的 5–10 篇论文，弄清已知什么、缺口在哪。
  3. 进一个真实在做研究的组（见 [本科生什么时候值得开始科研](03-开始积累真正能留下来的经历.md#research-undergrad-start)），从小任务做起。
  4. 把自己的工作对着“问题—方法—证据—结论”四要素检查，缺哪个补哪个。

- 常见误区：
  把打杂当科研；把“读了多少文献”当产出；问题模糊到无法设计实验；只做一次就期待结果。

- 下一步可能打开什么：
  研究生或博士申请的核心材料；一套终身受用的方法训练。

- 证据与来源：
  - 科学方法论的一般共识（可重复性、可证伪性）。 （Research-backed）
  - 科研训练过程的普遍经验。 （Experience-based）

- 最后核实：
  2026-09-21


### 哪些人值得接触科研

```meta
id: research-who-suits
status: complete
stages: [undergraduate, master, phd]
topics: [research]
outputs: [research_experience, optionality]
effort: low
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  适合做科研的人通常有三个特征：**对具体问题的耐心大于对短期回报的需要**、**能承受高比例的失败**、**愿意把一件事讲到任何人都能懂**。成绩好不是充分条件——成绩衡量的是掌握已知，科研面对的是未知。

- 适合谁：
  被某个问题缠住、不弄明白不舒服的人；计划以研究为职业（高校、研究院所、企业研究岗）的人。

- 不太适合谁：
  主要动机是“学历好看”或“家里希望”；对重复劳动和延迟满足明显不适的人；只想做应用落地的人（工程与产品岗位可能更合适）。

- 能换回什么：
  一次低成本验证“我适不适合走研究这条路”的判断——这个判断本身就是最值钱的产出。

- 要付出什么：
  一段完整的科研尝试（通常一学期到一年）；放弃这段投入后可能转向的机会成本。

- 怎么开始：
  1. 用一次真实的研究经历做测试，而不是用想象或测评。
  2. 测试中观察自己：卡住三天还能接受吗？重跑第十次实验还有耐心吗？写第一稿痛苦吗？
  3. 记录“喜欢做什么”和“擅长做什么”的重合部分（见 [每次尝试后记录什么](02-在学校里先把基础打好.md#explore-low-cost-experiments)）。
  4. 无论结论如何，把经历整理成材料——它对任何路径都有用。

- 常见误区：
  用绩点推断科研潜力；只看别人的成功故事；把不适感误判为不适合（多数不适应在 2–3 个月后消失），也把长期痛苦硬扛成坚持。

- 下一步可能打开什么：
  对读研读博的真实意愿；一段可用于申请的经历。

- 证据与来源：
  - 科研职业选择相关研究（如博士职业预期与实际路径差异的综述研究）。 （Research-backed）
  - 科研适配判断的普遍经验。 （Experience-based）

- 最后核实：
  2026-09-21


### 怎么找到第一次科研机会

```meta

status: complete
stages: [undergraduate]
topics: [research]
outputs: [research_experience, recommendation, paper, optionality]
effort: high
evidence: [official, experience_based, uncertain]
last_verified: 2026-09-21
```

科研不是只有“发论文”一种形态。对本科生来说，第一段科研经历更重要的产出是：**知道研究是怎么做的**、**知道自己在其中能不能待得住**，以及**得到一封了解你的推荐信**。论文是可能的副产品，不是入门条件。

## 不同学科的入口不一样

- 理工科：进课题组，从复现一篇论文或搭一套实验装置开始。
- 生命科学与医学：协助实验、整理样本与数据、学习规范操作。
- 人文社科：整理文献地图、编码访谈材料、核对档案与数据。
- 设计与艺术：做调研、跟项目、把过程整理成可展示的作品。

共同点是：都在做一件可以被检验的小事。

## 第一次任务应该足够小

不需要先达到“能独立完成研究”的程度。合适的起点是：在导师或高年级成员指导下完成一个可验证的小任务——复现代码、整理文献、协助实验、清理数据、访谈编码、档案整理、田野记录。小任务做完，才有资格谈更大的问题。

## 合适的时点

通常出现在三件事之后：基础课不再拖后腿、你能在指导下完成上面那样的小任务、每周能拿出固定的连续时间。顺序反了，容易变成在实验室里刷存在感。

## 怎么找老师

先读 5 篇该方向的论文（含 1 篇综述），能用自己的话讲出这个方向在解决什么问题；再带着一个具体的产出（复现结果、文献整理、数据梳理）去联系老师。邮件写法见 [联系导师邮件模板](../docs/tools/联系导师邮件模板.md)。

进组前问清五件事：每周投入要求、谁带你、是否参与具体课题、产出预期、署名规则。

## 进组以后先做什么

第一个月把小事做完并交付，让人知道你可靠，再谈更大的任务。同时把每次讨论、每个实验记录留档——这既是科研习惯，也是将来写材料时的依据。

## 怎么判断自己真的积累到了科研经验

三个自检问题：能不能讲清这个课题在解决什么问题？能不能复述自己做过的具体工作与结论？有没有人（导师或合作者）愿意为你写具体的推荐信？

## 如果发现不喜欢科研

尽早知道也是收获。科研训练里可迁移的部分——提问题、查文献、验证结论、把过程写清楚——在任何行业都用得上。

### 怎么找导师

```meta
id: research-find-supervisor
status: complete
stages: [undergraduate, master, phd]
topics: [research]
outputs: [recommendation, network, optionality]
effort: medium
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  选导师是在选**未来几年的工作方式与心情**，不是在选头衔。判断依据按权重排：在组学生做什么与状态如何 > 导师近期产出与指导风格 > 头衔与行政职务。前一项只有问组里的人才知道，所以多数人选错。

- 适合谁：
  准备读研读博、进组、或联系暑期科研的人。

- 不太适合谁：
  只看排名与头衔、不愿花两周做调查的人。

- 能换回什么：
  一段能真正学到东西的师生关系；稳定的指导与（可能的）推荐信。

- 要付出什么：
  两到四周的调查时间；联系与面谈的沟通成本。

- 怎么开始：
  1. 列出候选导师，逐一查近三年论文（第一作者与通讯作者是谁、方向是否与你匹配）与主页招生说明。
  2. **至少联系两位在读或刚毕业的组员**，问四件事：日常怎么指导、组会怎么开、多久见一次、师兄师姐去了哪。
  3. 邮件联系参考 [联系导师邮件模板](../docs/tools/联系导师邮件模板.md)，一次只联系同一院系的一位。
  4. 面谈时问清楚：入学后第一年做什么、课题是给定的还是自选、经费能否支撑实验。
  5. 汇总信息后做决策，警惕只有官网信息没有学生视角的选择。

- 常见误区：
  只看职称与头衔；不问组里学生；入学后才发现指导方式完全不合；同时联系同组多人被发现。

- 下一步可能打开什么：
  稳定的研究方向与指导；推荐信；一个可持续的合作关系。

- 证据与来源：
  - 导师指导质量与研究生发展关系的研究（高等教育研究领域的多项实证）。 （Research-backed）
  - 导师选择的普遍经验。 （Experience-based）

### 怎么判断一个实验室

```meta
id: research-choosing-a-lab
status: complete
stages: [undergraduate, master, phd]
topics: [research]
outputs: [research_experience, paper, recommendation, network]
effort: medium
evidence: [official, experience_based]
last_verified: 2026-09-21
```

- 一句话：
  看四件事：有没有明确的研究问题、有没有人带你、有没有近年的产出先例、以及你能不能拿到可验证的署名或成果。四项里缺两项以上，慎入。

- 适合谁：
  准备进组的人；已经在组里但感觉长时间没有进展、准备换组的人；申请博士时需要判断课题组质量的人。

- 不太适合谁：
  只想要一封推荐信、不打算投入时间的人。这种情况更该做的是把预期和老师讲清楚，找短期、边界明确的任务，而不是占用一个长期研究席位。

- 能换回什么：
  方法与训练；署名或成果；推荐信（取决于你实际做了什么）；学术圈内的信息与人脉。

- 要付出什么：
  6–24 个月时间；可能的大量重复劳动；与导师期望不匹配时的沟通成本和换组成本。

- 怎么开始：
  1. 查这个课题组近三年的公开产出：论文、会议、项目、学生去向。没有可查产出的组，要问清原因。
  2. 找 2–3 位在读或已毕业的成员私下了解：每周投入、组会频率、导师是否给方向、毕业与署名情况。
  3. 明确你的目标（推荐信 / 学方法 / 发论文 / 试水），并当面说清。目标不同，投入方式应该不同。
  4. 确认署名规则与数据归属，建议留下邮件记录。
  5. 设三个月检查点。没有指导、没有产出、也没有方法学习时，换组不是失败，是止损。

- 常见误区：
  只看导师名气，不看是否亲自带人；只信官网宣传，不问在读学生；接受“先干杂活再说”却没有期限约定；不确认署名规则；把课题组氛围问题当成自己能力不足；一次换组失败就认为“我不适合科研”。

- 下一步可能打开什么：
  论文与推荐信；博士申请；产业研发岗位；合作者网络。

- 证据与来源：
  - 课题组产出可通过学校官网、教师主页与公开学术数据库核对。 （Official）
  - 学生对课题组的评价属二手信息，需要交叉验证，不能单独作为依据。 （Experience-based）

  把开源当求职捷径、只想刷 commit 数的人（维护者能识别，这类贡献通常也不被计入）；不使用目标项目的人；无法承担“提交后几周无人回应”的人。

- 能换回什么：
  真实的评审经验；与维护者的联系；公开可见的贡献记录；对工程流程（Issue、分支、CI、Review、发布）的实际理解；少数情况下直接带来工作机会。

- 要付出什么：
  前期阅读代码的时间通常比写代码多；英文沟通；被拒绝或被要求重改的心理成本；持续跟进——PR 挂几周是常态，不是异常。

- 怎么开始：
  1. 选一个你**已经在用**的项目（工具、库、框架都可以），能本地跑起来。
  2. 读它的 CONTRIBUTING.md 和 Issue 标签说明。不少项目要求先开 Issue 讨论再提 PR，跳过这一步会被直接关闭。
  3. 从最小的事开始：文档错字、示例代码跑不通、错误信息不清楚、测试覆盖。文档类贡献同样计入贡献记录。
  4. 遇到 bug 先复现，写出最小复现步骤。这份描述本身就是有价值的工作。
  5. 提 PR 保持小而聚焦：一个 PR 解决一件事，写清“改了什么、为什么、怎么验证”。
  6. 维护者要求改动是正常流程，不代表你能力不行。及时跟进回复。
  7. 第一次被合并后，再认领更复杂的问题。在一个项目里持续贡献，价值远大于到处撒网。

- 常见误区：
  一上来改核心代码然后被关掉；不看贡献指南直接提 PR；一个 PR 混入多个不相关修改；把机器翻译的文档或格式调整当成主要贡献；提交后失联；用“提了多少 PR”当资本，而不看合并率；被拒绝一次就认为开源不欢迎新人。

- 下一步可能打开什么：
  成为常用项目的稳定贡献者；参与 SIG 与工作组（见 [社群、导师与行业影响力](06-进入职场以后继续积累.md)）；申请开源项目的差旅或开发资助（见第 12 章）；维护者身份带来的机会。

- 证据与来源：
  - GitHub 官方文档：Issue、Pull Request 与开源项目治理文件的说明。https://docs.github.com/ （Official）
  - 各开源项目的 CONTRIBUTING.md 与行为准则，是判断贡献方式的权威依据。 （Official）


- 一句话：
  从贡献者到 Maintainer 的转变不是荣誉授予，是**接过一份长期责任**：审别人的代码、回别人的 Issue、处理社区分歧、在自己没空的时候项目也活着。想做之前先想清楚维护成本，很多流行项目死于作者失联。

- 适合谁：
  有一个真实被使用、自己也持续在用的项目的人；愿意把“让项目活下去”当长期事务的人。

- 不太适合谁：
  只想要 Maintainer 头衔的人；项目爆火但自己已无力维护的人（及时补充维护者或明确归档，比装死体面）。

- 能换回什么：
  真实的治理经验（评审、发布、社区管理——这些是工作里稀缺的证据）；社区声誉；用人单位看得见的领导力证明。

- 要付出什么：
  每周固定的维护时间（社区通常比想象中 demanding）；处理分歧的情绪成本；长期义务。

- 怎么开始：
  1. 先在自己的项目上练习全套治理：发布版本、写变更日志、处理外部 PR。
  2. 在参与的项目里主动承担可见的维护工作（审 PR、修文档、管 Issue 列表）。
  3. 现有 Maintainer 邀请或你主动申请时，先明确能投入的时间与权限范围。
  4. 建立可持续机制：贡献指南、行为准则、明确的技术决策流程；一个人扛所有事不可持续。
  5. 学会归档：项目不做了就明确标注，留好交接说明。

- 常见误区：
  不好意思拒绝低质量贡献导致精力耗尽；治理规则缺失导致社区争吵；失联式维护毁掉项目与自己的声誉。

- 下一步可能打开什么：
  开源社区的正式角色；行业声誉与工作机会；治理与领导力的实证经历。

- 证据与来源：
  - 开源治理的普遍实践（各基金会与社区公开的治理文档）。 （Official）
  - 维护者经验的普遍规律（维护者倦怠是开源社区的公开话题）。 （Experience-based）

### Student Chapter

```meta
id: community-student-chapter
status: complete
stages: [college, undergraduate, master, new_grad]
topics: [community]
outputs: [network, reputation, leadership, work_experience]
effort: medium
evidence: [official, experience_based]
last_verified: 2026-09-21
```

- 一句话：
  这类角色的价值不在头衔，而在你可能因此拿到的三样东西：可验证的组织经验、与行业前辈的稳定联系、以及一次低风险的公开产出。做之前先想清楚你要的是哪一样，否则很容易变成消耗时间的挂名。

- 适合谁：
  想进入某个行业但缺少人脉入口的人；愿意做事、组织、表达的人；想在简历之外积累行业可见度的学生与新人；想练习公开表达与协调能力的人。

- 不太适合谁：
  只想挂名、不愿投入时间的人——做不好会留下负面印象，比不参与更差；主线事务已经排满的人；把社群活动当成逃避主线任务的方式的人。

- 能换回什么：
  组织与协调经验，且能写成具体成果（办了几场活动、服务多少人、拉到什么资源、内容触达多少）；与讲者、导师、同行的长期联系；公开产出的机会（活动记录、内容、社群运营、播客）；推荐人与推荐信；有时还有会议差旅减免或实习内推。

- 要付出什么：
  每月固定的时间投入；与学业和工作冲突时的取舍；组织活动失败、参与度低的挫败感；部分角色需要缴费或个人先垫付（务必提前问清）；一旦挂名不做事，声誉上的损失比收益大。

- 怎么开始：
  1. 先选一个你真正在用的领域（专业协会、技术社区、行业社群）。为了头衔去陌生圈子是最常见的错误。
  2. 从一件具体的小事开始：帮一次活动、整理一份资料、写一篇活动记录。先把一件小事做完，再谈长期角色。
  3. 做完之后立刻记录成果：参与人数、反馈、产出链接。这些是你后来写材料时最硬的依据。
  4. 争取一个**有名字的角色**（某分会成员、内容负责人、某活动负责人），而不是“帮忙的人”。有名字的角色才能写进材料。
  5. 半年后评估：有没有获得联系、产出和机会。没有就换方向，不要为了“坚持”继续消耗。
  6. 注意合规：不要以社群名义做商业宣传，不要泄露他人信息。

- 常见误区：
  只看头衔不问要做什么；进社区只发广告不参与讨论；把活动合影当成果，不记录数据；同时挂名三个组织，哪件都没做完；忽略时间成本，用主线的进展换虚名；把“认识很多人”当成有网络，而实际没有可求助的联系人。

- 下一步可能打开什么：
  组织更大规模的活动；成为导师或讲者；进入学会的委员会或工作组；获得推荐人与工作机会。

- 证据与来源：
  - 各专业协会与社区的学生分会章程、志愿者岗位说明（以官方页面为准，逐年变化）。 （Official）
  - “社群经历在招聘中的权重”缺少统一统计；本条只给出可验证性的判断方法。 （Experience-based）

- 一句话：
  志愿服务的价值分两层：一层是政策层面明确写出来的（服务期、待遇、部分招录倾斜），另一层是行业层面是否认可这段经历——后者差异很大，教育和公共服务领域认可度高，部分商业岗位几乎不看。

- 适合谁：
  想进入教育、公共服务、社会组织领域的人；需要在毕业前获得一段独当一面的独立工作经历的人；希望通过服务期换取明确的政策通道的人；已经清楚这段经历在目标行业里被认可的人。

- 不太适合谁：
  目标行业完全不看这类经历的人（此时服务期的机会成本需要重新计算）；家庭经济压力大、服务期待遇无法支撑生活的人；把志愿服务当成“简历上添一行”的人——面试官追问细节时会立刻露出来。

- 能换回什么：
  服务期证明与考核材料；独立开展项目与对接多方资源的经验；在基层环境中处理真实问题的能力；部分项目对应的政策倾斜（例如在考研、公务员招录中的定向或加分政策，具体以当年公告为准）；一段能讲出具体故事的经历。

- 要付出什么：
  通常 1–3 年的服务期；服务期间收入通常低于同等学历的市场薪资；地理位置往往偏远；脱离原专业领域的技能空窗；结束后需要重新找工作或考试。

- 怎么开始：
  1. 先查项目官方网站确认**当年**的招募公告、服务期限、待遇构成与报名条件。常见项目包括大学生志愿服务西部计划、中国青年志愿者协会的各类项目、三支一扶等，各自的主管部门与政策都不同。
  2. 把“能拿到什么政策倾斜”抄成清单，逐条核对资格条件与时限，尤其是需不需要“服务期满且考核合格”、需不需要在退役或结束后的特定期限内使用。
  3. 选岗位时优先看：这个岗位有没有明确的工作内容与产出（例如带一个班、完成一个项目），而不是“协助处理日常事务”。
  4. 服务期内主动整理成果：教学记录、项目文档、活动照片与总结，这些都是后来面试时最有说服力的材料。

- 常见误区：
  把不同类型的项目混为一谈（西部计划、三支一扶、支教团、普通志愿活动在待遇、时长与政策上完全不同）；以为“参加过”就等于“有优势”，不核对该经历在目标行业是否被认可；服务期内被动等待安排，没有主动产出可写的东西；忽视服务期的机会成本。

  教育、公共服务、社会组织方向的岗位；定向招录与政策倾斜对应的通道；在基层积累的人脉与真实项目经验；一段可以支撑“我为什么选了这个方向”的具体经历。

  只想挂个名的人（没有产出与出席，成员身份毫无信号价值）。

- 能换回什么：
  领域内最前沿的信息与人脉；对标准与方向的实质影响；简历上可核实的专业参与。

- 要付出什么：
  定期的会议与讨论时间（常有跨时区问题）；阅读背景材料的时间；从旁观到发言的心理跨越。

- 怎么开始：
  1. 找到目标领域的 SIG/WG：开源项目按其官网的治理文档（如 Apache 项目的 SIG 说明、W3C/IETF 的工作组列表），学术与行业协会按官网。
  2. 先旁听三次会议，读会议纪要与邮件列表，搞清楚在讨论什么、谁在主导。
  3. 从小事切入：整理纪要、修复文档、做调研——每个工作组都需要这些劳动。
  4. 有能力后提交正式提案或承担明确任务。
  5. 把参与沉淀为公开记录：会议发言、提案链接、你维护的文档。

- 常见误区：
  加入后潜水直到退出；跳过背景阅读直接发表意见；低估持续投入的时间成本。

- 下一步可能打开什么：
  领域内的专业声誉（见 [行业影响力](06-进入职场以后继续积累.md#community-industry-influence)）；标准制定与核心项目的参与资格。

  - 各开源基金会与标准组织的治理文档（Apache、W3C、IETF 等官网）。 （Official）
  - 社区参与的普遍经验。 （Experience-based）

## 实习准备

### 实习有什么用

```meta
id: internship-worth-it
summary: 判断实习价值看三件事：能否产出可写进简历的成果、能否验证方向、时间成本是否划算。
status: complete
stages: [college, undergraduate, master, secondary_vocational]
topics: [job]
outputs: [work_experience, network, optionality]
effort: medium
evidence: [official, experience_based]
last_verified: 2026-09-21
```

判断一段实习值不值得，看三件事：**能不能产出可写进简历的具体成果**、**能不能让你确认或排除一个方向**、**时间成本是否低于它替换掉的机会**。打杂三个月且说不出做过什么，不如用同样的时间做完一个自己的项目。

## 先问自己：这段实习在回答什么问题

是“这行的日常到底是什么样”，还是“我能不能胜任这类工作”，还是“这类公司适不适合我”。问题不同，应该找的岗位也不同：验证行业选大公司，验证能力选能给你真实任务的团队。

## 看岗位描述，而不是看公司名气

同一个公司里，有的实习能接触核心业务，有的只是整理表格。判断方法很朴素：看招聘描述里“你将负责什么”，如果通篇是“协助、支持、杂项”，进去之后大概率就是这样。

## 三个记录指标

进去之后每月问自己一次：

- 我在积累可写进简历的成果吗？
- 我学到了能带走的东西吗（方法、工具、行业理解）？
- 我确认或排除了什么？

三个都答不上来，就该主动争取任务，或者考虑结束。

## 关于报酬与协议

在校生利用业余时间勤工助学一般不视为就业，可以不签订劳动合同——这既意味着实习门槛低，也意味着你的社保与解雇保护与正式员工不同。签约前看清协议性质：是实习协议还是劳动合同，报酬、工时、保险怎么约定。职业院校学生还可以对照《职业学校学生实习管理规定》检查岗位、时长与报酬是否合规。

## 结束时留下三样东西

一段能具体描述的经历、一两个愿意为你背书的同事、以及对这个方向的判断。哪怕结论是“不适合我”，那也是有效收获——它让你少走两年弯路。

### 什么时候开始找第一段实习

```meta
id: internship-types
status: complete
stages: [college, undergraduate, master, secondary_vocational]
topics: [job]
outputs: [work_experience, income, optionality]
effort: medium
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  日常实习、暑期实习、寒假实习的区别不在名字，在**录取难度、留用机会与你的可支配时间**。暑期实习录取最难、留用通道最正式；日常实习门槛低、时间灵活，是很多人积累第一段经历的入口。

- 适合谁：
  想多段积累经历的人（日常实习）；冲着留用去的人（暑期实习）；想试水又只有假期的人（寒假实习）。

- 不太适合谁：
  学期中课业繁重还硬凑日常实习的人；只把暑期实习当唯一目标、错过日常实习积累的人。

- 能换回什么：
  日常实习：低门槛进入真实工作环境，可多段试错；暑期实习：更系统的培养与正式的留用评估；寒假实习：假期内的短段经历，部分行业（如券商、审计）有寒假招聘窗口。

- 要付出什么：
  日常实习：学期内每周数天的时间（与课业冲突时要权衡）；暑期实习：一整个暑假，且要提前一季准备；寒假实习：春节前后的时间窗口。

- 怎么开始：
  1. 大二、大三（或读研第一年）是开始实习的常见时间点，不必等“准备好了”。
  2. 第一段实习优先选“能学到东西、能写进简历”的，薪资可以往后放。
  3. 暑期实习一般提前 3–6 个月招，各公司时间不同，以官方招聘渠道为准。
  4. 日常实习在招聘平台、公司官网与学长内推里都有，注意甄别（见 [怎么找实习](03-开始积累真正能留下来的经历.md#internship-how-to-find)）。
  5. 多段实习逐步升级：第一段求入行，第二段求方向确认，第三段冲留用或更好的平台。

- 常见误区：
  只投暑期实习，前面的时间空着；把寒假实习当成唯一机会（窗口短、名额少）；为凑经历去做与方向无关的纯打杂岗位。

- 下一步可能打开什么：
  留用机会（见 [留用实习](04-当你开始面对第一次重要分流.md#internship-return-offer)）；第一份工作的具体判断（见 [第一份工作最应该换回什么](05-从学校走向第一份工作.md#first-job-what-to-trade-for)）。

- 证据与来源：
  - 各公司官方招聘渠道发布的实习项目公告（时间、要求逐项核实）。 （Official）
  - 各行业实习规律的普遍经验。 （Experience-based）

### 没经验怎么找实习

```meta
id: internship-how-to-find
status: complete
stages: [college, undergraduate, master, secondary_vocational]
topics: [job]
outputs: [work_experience, optionality]
effort: low
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  找实习的有效渠道按命中率排序大致是：**熟人内推 > 学校就业信息 > 公司官网直投 > 招聘平台**。渠道只解决“投到哪里”，简历与岗位匹配才决定命中率。

- 适合谁：
  所有找实习的人。

- 不太适合谁：
  没有目标方向、海投所有岗位的人——先想清楚投什么，再谈渠道。

- 能换回什么：
  面试机会；对目标行业招聘口径的了解。

- 要付出什么：
  简历制作与投递的时间；内推关系的维护成本；被拒的常态化心理成本。

- 怎么开始：
  1. 先定 2–3 类目标岗位，据此改出针对性简历（不要一份简历海投所有岗位）。
  2. 盘点内推资源：学长学姐、老师、实习过的同学、行业社群；内推时要给对方一份现成的简历与岗位链接。
  3. 学校就业信息网与院系群往往有经过筛选的岗位，别忽略。
  4. 公司官网与官方公众号的岗位最可靠；第三方平台上“收费内推”“保证录取”一律不碰。
  5. 记录每轮投递的结果与反馈，两周复盘一次投递策略。

- 常见误区：
  只用一个大平台海投；简历一份通用；付费买内推；投递无记录，被拒也不知道原因。

- 下一步可能打开什么：
  面试机会与最终录用；对简历与面试的迭代（见 [简历](05-从学校走向第一份工作.md#job-hunting-resume)）。

- 证据与来源：
  - 各招聘平台与公司官方招聘渠道。 （Official）
  - 求职渠道有效性的普遍经验。 （Experience-based）

### 怎么判断一段实习值不值得

```meta
id: internship-remote
status: complete
stages: [college, undergraduate, master, secondary_vocational]
topics: [job]
outputs: [work_experience, optionality]
effort: low
evidence: [experience_based]
last_verified: 2026-09-21
```

- 一句话：
  远程实习的好处是地点自由、门槛相对低，坏处是**学习密度天然更低、成果更难被看见**。它适合自律且目标明确的人；需要环境逼着成长的人，线下更好。

- 适合谁：
  所在地实习机会少的人；课程安排碎片化、只能远程投入的人；工作内容本身可远程交付的岗位（开发、设计、内容、数据等）。

- 不太适合谁：
  需要现场观察行业运作的人；自驱力不足、容易被挂起的人；岗位内容必须驻场的（实验室、产线、临床等）。

- 能换回什么：
  一段可写进简历的经历（前提是产出具体）；异步协作与书面沟通能力；时间上的灵活性。

- 要付出什么：
  与线下同等的投入；更高的自我管理成本；如果收费或要求“先交钱培训”，那是骗局（见 [假实习与付费实习](11-避坑.md#trap-fake-internships-and-paid-research)）。

- 怎么开始：
  1. 只找有明确带教安排的远程实习：入职前确认周会、任务分配、交付方式。
  2. 把工作成果沉淀为可验证的形式（代码仓库、文档、成品），比口头汇报有效。
  3. 主动同步进度，远程环境里“没人看见你的努力”，要让成果可见。
  4. 结束时请带教写一段具体的评价或愿意背书。

- 常见误区：
  接受无带教、无任务的挂名远程实习；收费的“远程实习内推”；因为没人管而实际投入远低于简历所写。

- 下一步可能打开什么：
  下一段更好的实习；具体的成果与背书。

- 证据与来源：
  - 远程工作与实习的普遍经验。 （Experience-based）
  - 涉及收费或虚假实习的警示见第 16 章对应条目。 （Experience-based）

  2026-09-21
