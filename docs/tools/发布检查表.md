# 项目发布检查表

发布（或提交比赛/课程）前 30 分钟逐项确认，避免最后一步翻车。

## 代码

- [ ] 主分支能跑通核心流程（不是「应该能跑」）；
- [ ] 没有调试用的硬编码（绝对路径、临时开关、测试密钥）；
- [ ] 敏感信息（密钥、密码）没有进仓库；
- [ ] 依赖清单是最新的。

## 测试

- [ ] 核心流程测试通过；
- [ ] 至少手动跑过一次完整流程（从零开始，不是增量）；
- [ ] 已知缺陷记录在案。

## 文档

- [ ] README 通过 [README 检查表](README检查表.md)；
- [ ] 版本号已更新（语义化：不兼容升主版本）；
- [ ] 变更日志写了这一版的关键改动；
- [ ] 许可证文件存在且类型明确。

## 演示与证据

- [ ] 演示链接可访问（或录屏已上传）；
- [ ] 演示用的是最新版本；
- [ ] 关键指标有记录与口径说明；
- [ ] 准备好兜底方案（离线版本 / 预录视频）。

## 归档

- [ ] 代码、数据、报告、演示材料放进一个目录；
- [ ] 写下「这一版做了什么、下一版做什么」；
- [ ] 如果用于作品集，已按「问题—动作—结果—限制」整理成一页。

## 两次确认

发布动作本身由两个人确认（或自己隔 10 分钟再看一次）：一次检查内容，一次检查提交方式（格式、命名、截止时间）。

## 示例：一次发布前的实际勾选

```
【代码】
[x] 主分支跑通完整流程（重跑一次，从零配置到出结果）
[x] 去掉调试硬编码（发现一处 /Users/xxx 绝对路径 → 改成相对路径）
[x] 密钥未入库（.env 已加入 .gitignore）
[x] 依赖清单更新（requirements.txt 手动同步）

【测试】
[x] 核心流程测试 6 项通过
[x] 手动从零跑一遍完整流程
[ ] 已知缺陷已记录（1 项：远距离丢包上升 → 写进 README 限制）

【文档】
[x] README 通过检查表（含 Quick Start 与限制）
[x] 版本号 v0.3.0（新增导出功能 → MINOR）
[x] 变更日志写明三项改动
[x] LICENSE 存在（MIT）

【演示与证据】
[x] 演示链接可访问（部署版）
[x] 录屏 90 秒（备用，防现场网络问题）
[x] 指标记录：首屏 1.6s、包体 420KB
[ ] 兜底方案演练一次 → 待做（演示前一天演练）
```
