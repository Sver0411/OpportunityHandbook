# 项目发布检查表

发布（或提交比赛/课程）前 30 分钟逐项确认，避免最后一步翻车。

## 代码

- [ ] 主分支能跑通核心流程（不是「应该能跑」）；
- [ ] 没有调试用的硬编码（绝对路径、临时开关、测试密钥）；
- [ ] 敏感信息（密钥、密码）没有进仓库；
- [ ] 依赖清单是最新的。

## 测试

- [ ] 核心流程测试通过；
- [ ] 至少手动跑过一次完整流程（从零开始，不是增量）；
- [ ] 已知缺陷记录在案。

## 文档

- [ ] README 通过 [README 检查表](README检查表.md)；
- [ ] 版本号已更新（语义化：不兼容升主版本）；
- [ ] 变更日志写了这一版的关键改动；
- [ ] 许可证文件存在且类型明确。

## 演示与证据

- [ ] 演示链接可访问（或录屏已上传）；
- [ ] 演示用的是最新版本；
- [ ] 关键指标有记录与口径说明；
- [ ] 准备好兜底方案（离线版本 / 预录视频）。

## 归档

- [ ] 代码、数据、报告、演示材料放进一个目录；
- [ ] 写下「这一版做了什么、下一版做什么」；
- [ ] 如果用于作品集，已按「问题—动作—结果—限制」整理成一页。

## 两次确认

发布动作本身由两个人确认（或自己隔 10 分钟再看一次）：一次检查内容，一次检查提交方式（格式、命名、截止时间）。
