# Benchmark 记录表

用途：把「性能不错」变成可核对的数字。**没有口径的数字等于没有数字。**

## 模板

```
一、指标定义
  指标名：           单位：
  起点（从何时开始计）：        终点（到何时结束）：
  统计方式：均值 / 中位数 / P95 / 最大

二、测量协议
  运行命令：
  重复次数：      每次时长：      预热时长：
  并发 / 数据规模：

三、环境
  硬件：        系统：        运行时与版本：
  依赖版本：

四、结果
| 编号 | 条件 | 次数 | 均值 | P95 / 波动 | 备注 |
| B01 | 基线（旧实现） | 5 |  |  |  |
| B02 | 新实现 | 5 |  |  |  |

五、原始数据位置
  目录 / 文件：

六、结论与限制
  结论：在 ______ 条件下，______ 从 ______ 变为 ______。
  不成立的条件：
  未测量的部分：
```

## 填写示例（接口性能）

| 编号 | 条件 | 次数 | 均值 | P95 | 备注 |
| --- | --- | --- | --- | --- | --- |
| B01 | 50 并发、旧实现 | 5 | 480 ms | 610 ms | 峰值内存 220 MB |
| B02 | 50 并发、加索引 + 批量查询 | 5 | 90 ms | 140 ms | 峰值内存 180 MB |

结论：在 50 并发、10 万行数据下，P95 从 610 ms 降到 140 ms；**在 200 并发下未测**，且高并发时连接池配置仍需调整。

## 三条纪律

1. **先定义再测量**：口径在跑之前写死，跑完之后不许改；
2. **保留失败与波动**：只报最好一次等于自毁可信度；
3. **写清不成立的条件**：这一栏是这份表最值钱的部分。
