# PR 检查表

提交前逐项打勾。**目标是让对方一次就能判断能不能合并。**

## 五项自查

- [ ] **范围**：这个 PR 只做一件事？没有夹带格式化、重命名或无关重构？
- [ ] **测试**：新增/修改的行为有对应测试？先确认过测试在修复前会失败？
- [ ] **文档**：影响使用方式的改动，README / 文档 / 变更日志同步更新了吗？
- [ ] **描述**：写清了「改了什么、为什么、怎么验证」？关联了 issue 编号？
- [ ] **本地验证**：本地全量测试通过？CI 失败是否已自查？

## 描述模板

```
修复 #1234：<一句话问题>

改了什么：
为什么：
怎么验证：
影响范围：
```

## 提交后的三步

1. CI 失败 → 先自己看日志修复，不等维护者指出；
2. 收到评审意见 → 逐条回应（改了什么 / 为什么保持原状），并在原 PR 上更新；
3. 合并后 → 记录到自己的贡献清单。

## 常见被要求修改的原因

| 原因 | 预防 |
| --- | --- |
| 改动太大 | 拆成多个 PR |
| 没有测试 | 先写失败测试 |
| 描述不清 | 用上面的模板 |
| 风格不一致 | 读最近合并的 PR |
| 忘记更新文档 | 把文档列入检查项 |
