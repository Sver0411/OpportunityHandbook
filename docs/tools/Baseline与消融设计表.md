# Baseline 与消融设计表

用途：动实验之前把「和谁比、去掉什么、预期看到什么」写下来，避免事后凑表格。

## 基线部分

| 基线 | 类型（平凡/启发式/强/SOTA） | 来源与实现 | 预算（算力/调参） | 为何选它 |
| --- | --- | --- | --- | --- |
| 随机 / 多数类 | 平凡 | 自实现 | 无 | 给出难度下限 |
| 规则法 A | 启发式 | 论文 x | 无 | 证明复杂方法有必要 |
| 方法 B（官方实现） | 强 | 开源仓库 | 与我的方法对齐 | 主要对比对象 |

**公平比较清单**：同数据划分 / 同预算 / 同评估协议 / 报告波动 / 代码可复现。

## 消融部分

| 组件 | 去掉后的预期 | 实际结果 | 结论 |
| --- | --- | --- | --- |
| 模块 X | 指标下降明显 | | |
| 模块 Y | 影响小（冗余？） | | |
| 参数 Z 扫参 | 稳定区间 | | |

**纪律**：一次只删一个组件；先写预期再看结果；若消融显示某组件影响很小，正文主张要相应调整。

## 结果记录

- 每次运行记录：配置、随机种子、时间、指标（均值与波动）；
- 保留原始输出，别只留汇总；
- 用 [Benchmark 记录表](Benchmark记录表.md) 登记指标口径与环境。

## 常见问题

- 只和弱基线比较 → 结论不可信；
- 同时去掉两个组件 → 无法归因；
- 只跑一次 → 波动未知；
- 消融表格与正文主张不一致 → 改主张，不要改数据。

## 示例：填好的样子

| 基线 | 类型 | 来源与实现 | 预算 | 为何选它 |
| --- | --- | --- | --- | --- |
| 多数类 | 平凡 | 自实现（3 行） | 无 | 证明任务不是随便猜 |
| 规则法（关键词匹配） | 启发式 | 自实现 | 无 | 验证「需不需要模型」 |
| Method-X（官方实现） | 强 | 作者仓库 v1.2 | 调参 20 组 | 主要对比对象 |
| 论文报告值 | 参考 | 原论文表 3 | — | 检查我的复现差距 |

**公平比较记录**：同一划分（种子 42）、同一训练预算（20 组调参）、同一评估脚本；我的复现与原论文差 1.2 个点，定位到预处理顺序差异（已写入限制）。

| 消融项 | 预期 | 实测 | 结论 |
| --- | --- | --- | --- |
| 去掉重加权 | 小样本召回下降 ≥2 点 | 下降 2.1 点 | 该组件有效 |
| 去掉新损失函数 | 下降约 1 点 | 下降 0.6 点 | 收益有限，正文只写「略有提升」 |
| 采样比例 0.5–2.0 扫参 | 存在稳定区间 | 0.8–1.2 内波动 <0.3 | 结论对比例不敏感 |
