# 文献地图（Literature Map）

用途：把零散的论文整理成一张「领域在争什么」的图，找出可以做的位置。

## 三种组织方式

1. **时间线**：横轴年份，纵轴方法类别，展示方法的演进与替换；
2. **方法树**：上游方法 → 改进分支，标注每支的假设与代价；
3. **对照表**：行是论文，列是「问题 / 方法 / 数据 / 指标 / 主要结论 / 局限」。

先用对照表收集，再画时间线或方法树。

## 对照表模板

| 论文 | 问题 | 方法 | 数据 | 指标 | 结论 | 局限 |
| --- | --- | --- | --- | --- | --- | --- |
| A (2023) | | | | | | |
| B (2024) | | | | | | |

## 怎么找空白

- 同一问题下，**所有论文都用同一数据集** → 换数据（或换条件）可能出新结果；
- 指标口径不统一 → 统一口径做一次对比本身就是贡献；
- 某类条件下的结论互相矛盾 → 值得做条件刻画（见 [科研失败案例](../research-deep/科研失败案例.md)）；
- 「大家都在做」但都被同一假设限制 → 检验假设即为贡献。

## 维护方式

- 每读一篇更新一行（配合 [论文精读表](论文精读表.md)）；
- 每两周画一次当前版本的时间线；
- 写开题/相关工作章节时，直接引用这张表的结构。

## 什么时候该画这张图

不是一开始就要画。适合动手的信号：

- 同一个问题已经读到 5 篇以上，开始记混哪篇是哪篇；
- 你发现两篇论文结论互相矛盾，却说不清矛盾在哪；
- 你要写相关工作章节，需要说明这条线是怎么演进的。

只有两三篇时，画图不如直接读。

## 地图变大之后

文献超过三四十篇，一张大表就失去可读性了。常见处理：

- **按子问题拆**：一个子问题一张表，总图只保留结论；
- **按时间切**：只留最近三年加奠基性工作，中间年代折叠成一句话；
- **标注状态**：每行加「已精读 / 只读摘要 / 待读」，避免把摘要印象当成读过。

## 找到空白不等于值得做

空白区有几种来源，只有一部分是机会：

- **真空白**：没人做，因为需要新方法或新数据——也可能只是难；
- **假空白**：别人做过但没发表，或者你的检索方式漏掉了；
- **伪空白**：没人做是因为结论已经清楚、题目不值得再做。这是最常见的一种，也最容易让人白费一年。

下判断前先问一句：如果这个空白是真的，为什么过去几年没人填？**答不上来，就不要把它当成选题。**
