# 客户沟通与需求确认表

用途：把口头沟通变成可追溯的记录。**尾款纠纷的根源几乎都是「当初只是口头说好了」。**

## 首次沟通记录

| 字段 | 内容 |
| --- | --- |
| 客户与联系人 | |
| 现状 | 现在怎么处理这个问题 |
| 痛点 | 最烦哪一步（抄原话） |
| 频率与成本 | 多久一次、每次耗时/花费 |
| 期望结果 | 客户认为「做好了」是什么样 |
| 约束 | 时间、预算、合规、必须使用的工具 |
| 我的理解 | 一句话复述需求（**发给对方确认**） |

## 范围与验收

| 项 | 内容 |
| --- | --- |
| 交付物 | 格式、数量 |
| 不包含 | 明确排除 |
| 验收标准 | 谁验收、怎么算通过 |
| 反馈期限 | 收到后几日内必须反馈 |
| 修改轮次 | 含几轮、超出如何计费 |

## 变更记录

| 日期 | 变更内容 | 影响（时间/费用） | 客户确认方式 |
| --- | --- | --- | --- |
| | | | 邮件 / 聊天记录截图 |

**纪律**：任何新增需求都先记录、评估、报价，再决定是否纳入当期。

## 沟通节奏

- 每周固定一次进展同步（哪怕只有三行）；
- 风险提前说：可能延期时，第一时间告知并给新时间点；
- 交付确认：每个里程碑结束请对方回一句「确认」。

## 对方不确认怎么办

发出去的需求复述没人回，是自由职业里最常见的隐患。分三步处理：

- **给默认规则**：在消息里写明「如无异议，我将按以上理解推进」，并说明什么时候开始做。沉默就不再等于没有意见；
- **换成更容易确认的方式**：长邮件没人细读，就改成三行消息加一条语音；或者直接打电话复述一遍，事后把结论用文字发回去；
- **在合同里写确认期限**：约定「收到交付物后 N 日内未反馈视为通过」，把沉默变成流程的一部分，而不是后来的争议。

## 口头承诺怎么补录

电话里或当面谈成的事，当天补一条消息：**「刚才我们确认的三点是 1 / 2 / 3，如果有出入请回复我。」** 对方哪怕只回一个「好」，这条记录也就成立了。

不要等到交付时才发现双方理解不同——分歧在刚发生的时候处理成本最低，隔了一个月就变成各说各话。

## 示例：一次真实填写

```
客户与联系人：XX 培训（王老师）
现状：用微信群接龙报名，每天手工核名单约 1 小时
痛点（原话）：「最怕漏单，上个月有一次学员没进名单，来上课才发现」
频率与成本：每天 1 次，每次约 1 小时；出错 1 次/月
期望结果：学员能自助报名，能看到名单，能导出
约束：预算 1 万左右；3 周内要能用；手机端为主
我的理解（已发对方确认）：你要的是「每天不再花 1 小时核名单，并且不丢单」 —— 对方回复「对」
```

```
范围与验收
交付物：报名页 + 名单管理页 + 导出（CSV）
不包含：支付、营销页、多校区
验收标准：能完成一次真实报名并被看到；导出文件能被 Excel 打开
反馈期限：交付后 2 个工作日内    修改轮次：含 2 轮，超出按 500/轮
```

| 日期 | 变更内容 | 影响 | 客户确认 |
| --- | --- | --- | --- |
| 10-09 | 增加微信通知 | +2 天，+1500 元 | 邮件确认 |
| 10-13 | 增加家长端查看 | 排入下一期 | 邮件确认 |
