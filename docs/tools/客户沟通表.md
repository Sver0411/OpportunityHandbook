# 客户沟通与需求确认表

用途：把口头沟通变成可追溯的记录。**尾款纠纷的根源几乎都是「当初只是口头说好了」。**

## 首次沟通记录

| 字段 | 内容 |
| --- | --- |
| 客户与联系人 | |
| 现状 | 现在怎么处理这个问题 |
| 痛点 | 最烦哪一步（抄原话） |
| 频率与成本 | 多久一次、每次耗时/花费 |
| 期望结果 | 客户认为「做好了」是什么样 |
| 约束 | 时间、预算、合规、必须使用的工具 |
| 我的理解 | 一句话复述需求（**发给对方确认**） |

## 范围与验收

| 项 | 内容 |
| --- | --- |
| 交付物 | 格式、数量 |
| 不包含 | 明确排除 |
| 验收标准 | 谁验收、怎么算通过 |
| 反馈期限 | 收到后几日内必须反馈 |
| 修改轮次 | 含几轮、超出如何计费 |

## 变更记录

| 日期 | 变更内容 | 影响（时间/费用） | 客户确认方式 |
| --- | --- | --- | --- |
| | | | 邮件 / 聊天记录截图 |

**纪律**：任何新增需求都先记录、评估、报价，再决定是否纳入当期。

## 沟通节奏

- 每周固定一次进展同步（哪怕只有三行）；
- 风险提前说：可能延期时，第一时间告知并给新时间点；
- 交付确认：每个里程碑结束请对方回一句「确认」。
