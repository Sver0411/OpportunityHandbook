# 项目设计 Canvas

用途：在写代码之前把项目想清楚，一页写完。写不满说明还没想好；写不下的说明范围太大。

## 一页模板

```
问题（一句话）
  谁，在什么场景下，遇到什么问题，现在怎么凑合：

不做（明确排除）
  · 不做多用户
  · 不做移动端
  · 不处理历史数据

第一版「完整走通」的定义
  输入 → 处理 → 输出 → 谁看到结果：

会留下的证据
  · 可访问地址 / 录屏
  · 指标与口径：
  · 真实使用（谁、多久）：

风险与替代
  最大风险：            替代方案：
  次大风险：            替代方案：

里程碑（含日期）
  M1（能跑通）：
  M2（能演示）：
  M3（能交付）：

停止条件
  · 连续两周无可展示进展 → 砍范围
  · 已能回答最初问题 → 停止加功能，转测量
```

## 填写要点

- 「问题」一栏必须能说出「现在怎么凑合」——说不出说明需求不真实；
- 「不做」至少写三条，否则范围没有边界；
- 「证据」一栏先写再做事，因为证据形态决定实现取舍（见 [项目类型专项](../projects/项目类型专项.md)）；
- 里程碑不要超过三个，每个都要能「演示」。

## 什么时候更新它

- 每次要加新功能前：先看它属于哪个里程碑，还是应该进入下一版；
- 每次里程碑到期：写三行进展（做完什么、没做完什么、砍什么）。
