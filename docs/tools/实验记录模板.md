# 实验记录模板

用途：让每一次运行都可追溯。**记录的标准是「别人（或三个月后的你）能复现」。**

## 模板（每次运行一份）

```
## 基本信息
日期：            实验编号：
目的：这次要验证什么（一句话假设）

## 配置
代码版本 / 提交号：
数据集与版本：      划分方式：
随机种子：          运行命令：
环境：OS / 运行时 / 硬件：
关键超参：

## 过程记录
开始与结束时间：
遇到的异常与处理：
中途改动（如果有，为什么改）：

## 结果
指标定义与口径：
数值（含波动 / 重复次数）：
与基线对比：
截图或输出文件位置：

## 结论与下一步
支持假设吗？为什么：
限制与异常现象：
下一步：
```

## 三条纪律

1. **失败的运行也记**（否则「从未失败」是假象）；
2. **口径先写后跑**，跑完不改；
3. **原始输出归档**，不只留整理后的表格。

## 与数据集成的做法

- 每个实验一个文件，命名带日期与编号；
- 汇总表（`results.csv`）只放指标与配置引用，正文从记录里抄；
- 论文/报告的每个数字都能追到某一条记录。

## 记录到什么程度够用

记录也有成本，标准是「够复现，不多写」。判断方法很简单：三个月后只看到这份记录，你能把这次运行重跑一遍吗？

- **必须记**：代码版本、数据集版本、随机种子、运行命令、关键超参、指标口径——缺任何一项都无法复现；
- **不必记**：每天的琐碎操作、试错的中间过程（只留「试了 A 不行，因为 X」这一句结论）；
- **值得多写一句**：任何让你意外的现象。意外往往是下一个问题的入口，而它最容易在几天后被忘掉。

## 忘了记怎么补

前几天没记、现在想补，是常态。补的时候注意两点：

- 能从工具里查到的（提交号、运行时间、环境版本）照实补；
- 靠回忆、拿不准的，标上「待确认」，不要写成确定值——一份混进猜测的记录比没有记录更危险，因为三个月后的你会当它可信。

如果关键信息已经彻底丢失，就在记录里直接写「本次不可复现，原因：未记录随机种子」。这本身也是一个有用的结论。
