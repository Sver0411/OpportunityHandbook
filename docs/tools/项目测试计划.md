# 项目测试计划模板

用途：让「我试过了」变成「有记录、可复现、别人也能验证」。

## 模板

```
一、被测对象
  项目 / 版本 / 提交号：

二、环境
  机器与系统：    运行时版本：    数据版本：

三、用例表
| 编号 | 类型 | 输入 / 操作 | 期望结果 | 实际结果 | 通过 |
| T01  | 功能 |             |          |          |      |
| T02  | 边界 |             |          |          |      |
| T03  | 异常 |             |          |          |      |

四、指标记录（若有）
  指标定义：      口径：      测量方式：      数值与波动：

五、未覆盖与已知缺陷
  · 未覆盖：
  · 已知缺陷与原因：

六、复现步骤
  1. …
  2. …
```

## 填写示例（IoT 上报）

| 编号 | 类型 | 输入 / 操作 | 期望结果 | 实际结果 | 通过 |
| --- | --- | --- | --- | --- | --- |
| T01 | 功能 | 正常上电，近距离 | 每 5 秒上报一次 | 符合 | ✅ |
| T02 | 边界 | 持续运行 24 小时 | 无重启、无丢包 | 丢包 0.3%、0 重启 | ✅ |
| T03 | 边界 | 隔两道墙 | 仍能上报 | 丢包 18% | ⚠️ 记录为限制 |
| T04 | 异常 | 断电 10 秒后恢复 | 自动重连并继续上报 | 6 秒恢复 | ✅ |
| T05 | 异常 | 拔掉天线 | 不崩溃，记录错误 | 不崩溃但不重试 | ❌ 已开缺陷单 |

## 类型说明

- **功能**：正常路径；
- **边界**：极小、极大、恰好等于阈值的输入；
- **异常**：断网、断电、依赖失败、非法输入。

## 使用纪律

- 失败用例必须记录（它们是证据，不是污点）；
- 每次改动后重跑 T 序列里标为「核心」的用例；
- 把本表放进仓库，与 README 的「Testing」一节互相链接。

方法与判据见 [工程项目的测试、指标与证据](../projects/测试与指标体系.md)。
