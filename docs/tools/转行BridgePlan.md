# 转行 Bridge Plan

转行前先判断什么，见主线 [转行前先判断什么](../../book/07-晋升、跳槽还是转行.md#switch-before-decide)；过渡机会的概念见 [Bridge Opportunity](../../book/07-晋升、跳槽还是转行.md#career-bridge-opportunity)。

## 计划模板（可直接复制填写）

```text
当前岗位：
目标岗位：
（目标岗位的 2–3 条硬性要求，来自真实 JD）

已有能力（能拿出证据的）：
已有行业经验（可迁移的）：
缺口（技能 / 经验 / 证书 / 人脉）：

Bridge Opportunity（同时沾着两边的位置）：
  · 候选一：
  · 候选二：

3 个月动作（可检查的）：
  · 第 1 个月：
  · 第 2 个月：
  · 第 3 个月：

可验证成果（做完以后能拿给别人看什么）：

市场反馈（投递 / 面试 / 从业者访谈的结论）：

是否继续（继续 / 调整 / 停止，以及判断依据）：
```

## 怎么用才有效

- **目标岗位一栏必须来自真实 JD**，不要写「我想做数据相关的工作」这种模糊方向；
- **缺口要分类**：技能可以自学补；经验要靠过渡岗位；证书有明确考试周期；人脉靠社群与访谈——四类解法不同；
- **3 个月动作必须可检查**：写「完成一个数据分析项目并公开」而不是「多学习」；
- **可验证成果**是这张计划的核心，见 [什么叫可验证成果](../../book/00-从这里开始.md#judge-verifiable-outcomes)；
- **市场反馈**决定继续还是调整：投了三十份没有面试，说明缺口判断有误，回到上一栏重写。

## 示例：填好的一份（8 个月）

```
起点 → 目标：工艺工程师 → 数据分析（制造业方向）

能力盘点（我有什么）
  · 可迁移：良率数据清洗经验、跨部门沟通、报告写作
  · 缺口：SQL（不会）、Python（只会读）、指标体系（不系统）

Bridge 选项（先用现有岗位做过渡）
  ① 在现岗位把手工 Excel 周报改成 SQL 查询（4 周）——用真实工作练工具
  ② 主动接生产数据的看板需求（6 周）——拿到一个可展示的作品
  ③ 内部转岗到质量/数据相关岗位（若有机会，优先级最高）

时间表
  第 1–4 周：SQL 基础 + 改造周报
  第 5–10 周：Python + 看板项目（含数据采集与清洗）
  第 11–16 周：写作品报告 + 收 15 份目标 JD 做 Gap 复核
  第 17–32 周：投递（只投制造业数据分析），每周复盘漏斗

第一个月里程碑（可验证）
  · 周报改造上线，单次耗时从 40 分钟降到 3 分钟
  · 完成一份 60 行以内的 SQL 查询脚本，被同事复用
```

**这份计划的关键**：Bridge 不是「先辞职学三个月」，而是**在现有岗位里制造证据**——第 ① 步就已经产出可写的成果。
