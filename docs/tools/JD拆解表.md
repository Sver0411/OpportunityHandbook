# JD 拆解表

用途：把「看 JD」变成可比较的数据。用法：每份 JD 填一张单表；攒够 8–15 份后填汇总表。

## 单份 JD 拆解

| 项目 | 内容 |
| --- | --- |
| 公司 / 岗位 / 城市 | |
| 来源与日期 | |
| 职责（每天做什么） | 1. 2. 3. |
| 硬性要求 | 学历 / 专业 / 年限 / 必会技术 |
| 优先与加分 | |
| 关键词（可对齐简历的名词） | |
| 隐藏信号 | 团队阶段、业务方向、技术栈迁移、值班与节奏 |
| 我的差距 | 每条要求 → 具备 / 部分 / 没有 |
| 准备优先级 | 差距最大且可短期补齐的前三项 |

## 多份 JD 汇总

| 要求 | 出现次数 | 占比 | 我的状态 | 补齐方式 | 期限 |
| --- | --- | --- | --- | --- | --- |
| 例：熟悉 MySQL | 12/15 | 80% | 部分 | 做一个含索引优化的项目 | 4 周 |
| 例：熟悉 Redis | 6/15 | 40% | 没有 | 小项目加缓存层 | 6 周 |
| 例：分布式基础 | 6/15 | 40% | 没有 | 读概念 + 复现一个场景 | 8 周 |

## 判读规则

- 出现率 ≥ 60%：行业共识，尽量补齐；
- 20%–60%：竞争维度，能补就补；
- < 20%：通常是公司特殊要求，先不管。

## 常见误用

- 只用一份 JD 就改简历；
- 把加分项当硬门槛，提前自我淘汰；
- 统计了很多份却不动手补差距。
