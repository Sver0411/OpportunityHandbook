# 面试复盘表

用途：让每一次面试都产生**可执行的改进项**，而不是只留下情绪。

## 模板

| 字段 | 内容 |
| --- | --- |
| 公司 / 岗位 / 轮次 | |
| 日期与时长 | |
| 题型分布 | 知识 __ / 编程 __ / 项目 __ / 行为 __ / 反问 __ |
| 问到的问题 | 逐条记（写原话，不要概括） |
| 我的回答 | 关键句 |
| 卡点 | 哪一层卡住：知识 / 表达 / 项目深度 / 时间 |
| 正确思路 | 事后想到的更好答案 |
| 改进动作 | 具体到「补哪一块、何时完成」 |

## 示例

| 字段 | 内容 |
| --- | --- |
| 问题 | 「你的缓存失效策略是什么？」 |
| 我的回答 | 「设置了过期时间」（过于笼统） |
| 卡点 | 项目深度 |
| 正确思路 | 说明过期时间取值依据、缓存与数据库不一致时的处理、是否做过压测 |
| 改进动作 | 给项目加上过期策略与一致性处理，本周完成 |

## 归纳（每 3–5 场做一次）

- 哪些题型反复卡？→ 优先补这一类；
- 哪一类问题回答得越来越顺？→ 说明准备有效；
- 有没有「答得不错但没进下一轮」的情况？→ 可能是匹配度或岗位定位问题，见 [求职失败诊断](../job-search/求职漏斗诊断.md)。

## 三条纪律

1. **24 小时内写**：拖久了记忆会自动美化；
2. **写原话**：只写「问了缓存」没用，要知道他的原句；
3. **每条卡点必须落成动作**：否则写等于没写。
