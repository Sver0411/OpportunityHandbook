# Peer Review 与 Rebuttal

投稿之后的工作，一半在回应评审。理解审稿人的判断框架，比反复润色语言更有用。

## 审稿人实际在判断什么

三个轴：**soundness（做得对不对）、novelty（新不新）、significance（重不重要）**。

- 方法是否有漏洞、实验是否支撑主张 → soundness；
- 与已有工作的差异是否清楚 → novelty；
- 结论对领域有没有影响 → significance。

多数拒稿理由不在这三项之外，但表述常见为「实验不充分」「贡献不清晰」「与已有工作区别不明」。

## 怎么模拟一次评审

投稿前做一次「反向评审」：找一位不熟悉你工作的同学，给 20 分钟读，然后让他回答——问题是什么、你做了什么改进、证据在哪。他答不出，说明正文没写清楚，而审稿人通常只有更少时间。

更狠的做法是列出「我最怕被问的三个问题」，然后自己写答案改进正文。常见三个问题：**为什么不用更简单的基线？提升有多少来自调参？换个数据集还成立吗？**

## 意见分类与取舍

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| 事实性错误 | 引错数字、写错公式 | 直接改，并感谢 |
| 实验不足 | 缺某类对照 | 能补就补；补不了就明确写成限制 |
| 表述不清 | 读者误解你的意图 | 改文字，不改主张 |
| 与已有工作差异不明 | 「与 X 的区别是什么」 | 补一段明确对比，必要时加实验 |
| 不同意但合理 | 主张范围之争 | 缩小主张或补证据，不必辩论 |
| 误解性意见 | 你正文已写 | 礼貌指出位置，别带情绪 |

原则：**能通过补实验解决的就补，能通过缩小主张解决的就缩，只有确实误读时才反驳。**

## Rebuttal 的结构

一段一段对应，每段三件事：**确认问题 → 给出回应（新数据/新表/澄清）→ 说明正文如何修改**。

写作要点：

- 开头一段总结「我们做了什么修改」，让审稿人一眼看到变化；
- 新实验给具体数字，不要只说「我们会补充」；
- 情绪化的句子全部删掉；不评价审稿人；
- 无法满足的要求，明确说明原因与替代方案（例如「该数据集不公开，我们用 Y 数据复现了同一结论」）；
- 篇幅有限就写最重要的三点，其余折叠到「其他修改」。

## 被拒之后

把评审意见分类成两类：**可以通过修改解决的**（换更强基线、补消融、改主张）与**方向性的**（问题本身不够重要）。前者改投，后者需要重新思考问题——这时不要急着换会议，先改问题。

## 自检

- 我能预测审稿人会问的三个最强问题吗？
- 每一条意见我准备用「补实验 / 缩主张 / 澄清」中的哪一种解决？
- rebuttal 里有没有一句是在为自己的工作辩护而不是回应问题？
