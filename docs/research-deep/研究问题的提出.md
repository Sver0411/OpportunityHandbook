# 如何提出 Research Question

研究问题不是「一个领域」，也不是「我想研究 X」。它是一个**可以被证据回答、且答案目前未知的具体问句**。这一页给一条从观察到问题的操作链条。

## 五步链条

**observation（现象）→ gap（缺口）→ hypothesis（假设）→ research question（问题）→ contribution（贡献）**

### 1. observation：先有现象，不是先有领域

现象是你在数据、系统或真实场景里看到的具体事实：「模型在小样本类别上准确率骤降」「这套方法在长文档上比短文档慢十倍」「这个协议在丢包 5% 时吞吐崩塌」。

判据：**能举出一个具体例子**（哪个数据集、哪个条件、哪次实验）。举不出，就还在「领域」层面。

### 2. gap：现有工作为什么没解决

读三到五篇最相关的论文，回答三个问题：它们解决了什么、用的什么方法、**在什么条件下失效**。第三条就是缺口。

缺口分几种，价值不同：

- **能力缺口**：现有方法做不了（存在即有价值）；
- **条件缺口**：只在理想条件下成立（价值取决于条件有多普遍）；
- **效率缺口**：能做但代价过高（要有明确的代价指标）；
- **认知缺口**：现象被观察到但没人解释（常见于系统与 HCI 研究）。

### 3. hypothesis：一个可被推翻的猜测

假设要写成能预测具体结果的句子：「如果把 A 换成 B，那么在小样本类别上的召回会提升，因为……」

不能预测结果的假设是空话。

### 4. research question：收成一个问句

把假设改写成问句，并检查四个性质：

| 性质 | 检查方式 |
| --- | --- |
| 可证伪 | 什么结果会证明它错了？说不出来 → 不成立 |
| 可执行 | 你现在能拿到数据/设备/被试吗？ |
| 新颖 | 读过文献，确认没有现成答案 |
| 重要 | 答案会改变谁的什么判断？ |

### 5. contribution：你能给出什么

明确写下你的贡献类型：新方法、新数据、新发现、新系统、新分析框架。**一句话说不清贡献，说明问题还没收敛。**

## 好问题与坏问题对照

| 坏问题 | 问题在哪 | 改成 |
| --- | --- | --- |
| 「人工智能对教育的影响」 | 无边界、无法验证 | 「在 X 类课程中引入自动批改后，学生重做率是否上升？」 |
| 「如何让模型更准确」 | 目标泛、无对照 | 「在样本量小于 500 的类别上，X 方法能否把召回提升到 Y 以上？」 |
| 「深度学习能用于医疗吗」 | 答案为「能」，无信息量 | 「在 X 数据集上，A 方法相比临床基线在漏诊率上的差距是多少？」 |
| 「为什么这个方法好」 | 不可证伪 | 「A 方法提升来自哪一组件？消融后差距多大？」 |
| 「研究一下图神经网络」 | 不是问题 | 「在稀疏图上，消息传递的层数增加何时开始伤害性能？」 |

## 反复换问题的三种情况

- 数据拿不到或规模不够 → 降级问题（换更小的数据集或更窄的场景）；
- 文献显示已有答案 → 前移缺口（问更细的条件或机制）；
- 问题做完发现不重要 → 把「重要」这一步补在前头，重排优先级。

## 自检

- 你的一句话问题里，有没有「是否 / 如何 / 多少 / 在什么条件下」这类可回答的词？
- 什么结果会让你认为假设错了？
- 你的贡献属于哪一类？
- 如果只能用一句话向同学解释，你能不能讲清「为什么要做它」？
