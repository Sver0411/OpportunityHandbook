# 项目面试：从第一句开始的追问链

「介绍一下你的项目」不是让你复述文档，而是给你一个可以深挖三十秒的开头。准备方式是按真实追问链走一遍。

## 完整追问链

```
介绍一下你的项目
├── 为什么做这个？谁的问题？
├── 为什么用这个架构 / 方法？
│    └── 还考虑过哪些方案？为什么不选？
├── 性能 / 效果怎么样？怎么测的？
│    └── 条件是什么？瓶颈在哪？
├── 怎么测试的？失败过吗？
│    └── 出过什么 bug？怎么定位的？
├── 如果重新做，你会改什么？
└── 你具体负责哪一部分？
```

## 每一层的答法

### 开场（30 秒）

一句话问题 + 一句话方案 + 一个结果。「为 X 场景做一个 Y，效果是 Z」。不要从技术栈开始讲。

### 为什么做

给具体来源：自己遇到的麻烦、某次实习的需求、某篇论文的缺口。**「因为想练手」是最弱的答案**，可以说但要接一句「具体是想验证 X 能不能做到 Y」。

### 为什么这个架构

关键不是「它很流行」，而是「它在我的约束下最合适」：时间、算力、已有技能、可维护性。必须能说出一个被否掉的方案。

- 好：`考虑过用消息队列解耦，但部署复杂度超过收益，这条链路的量级用同步调用足够。`
- 差：`这个技术现在比较主流。`

### 性能与测试

按 [工程项目的测试、指标与证据](../projects/测试与指标体系.md) 的框架答：指标定义、口径、环境、波动、基线。被问「你怎么知道有效」，要能立刻给出数字与条件。

### 失败过吗

必须准备一个真实失败：现象、排查过程、根因、修复、后来如何避免。**没有失败经历的候选人反而显得可疑**——说明项目太浅或你没真正参与。

### 重做会改什么

给出一个有取舍的答案：不是「加更多功能」，而是「先做什么、砍掉什么」。这一问考的是判断力。

### 你负责什么

诚实划界。团队项目要能说清「哪一行是我写的」「哪一部分是我设计的」。含糊其辞是最常见的失分点，面试官会连续追问两次。

## 准备方式

1. 写出自己的完整追问链（针对你的项目）；
2. 每一层写三个要点，口头讲一遍并录音；
3. 找一个同学扮演追问者，专挑你答得含糊的地方；
4. 把答不上的地方补实验或补说明——**这是面试准备中最能带来实质提升的一步**。

## 自检

- 我的开场能不能在 30 秒内说清问题、方案、结果？
- 我能说出一个被否掉的方案与原因吗？
- 我有一个真实失败案例，并且知道根因吗？
- 团队项目里，我能用一句话说清我的边界吗？
