# 简历从差到好（六种背景完整改写）

改写简历的通用方法只有一条：**把「我做了什么」改成「我解决了什么问题，留下了什么证据」**。下面按背景给六组对照。

## 1. 无实习的学生

- 原文：`参与课程项目开发，负责部分功能实现。`
- 问题：没说什么功能、什么角色、什么结果。
- v1：`课程项目：用 Flask 实现图书借阅系统，负责借阅与归还模块。`
- v2：`为课程小组做图书借阅系统（Flask + SQLite）：独立实现借阅/归还/续借流程与逾期计算，覆盖 6 类边界输入；同组 4 人使用，期末演示获课程评分 A。`
- 理由：给出模块边界、可核对的范围与结果；边界输入体现测试意识。

## 2. 有项目但没结果

- 原文：`做了一款聊天机器人。`
- v1：`用 Python + 大模型 API 做聊天机器人，支持多轮对话。`
- v2：`为用户调研问卷设计的问答机器人：把 40 页产品文档接入检索，回答准确率在自建 60 题测试集上从 62%（纯模型）提升到 85%（加检索）；支持多轮追问，响应 P95 约 1.8 秒。`
- 理由：有场景、有基线、有自测集、有延迟——即便没有真实用户，也能体现工程与验证能力。

## 3. 有科研

- 原文：`参与老师课题组，做了一些实验。`
- v1：`参与 X 方向研究，负责实验与数据处理。`
- v2：`在 X 课题组完成一项复现与改进：复现 A 方法在公开数据集上的结果（与原论文差距 1.2 个点，定位到预处理差异）；在此基础上对采样策略做消融，发现收益主要来自类别重加权而非论文中主张的损失函数。`
- 理由：复现差距的定位与消融结论，比「参与课题」有力得多。

## 4. 有实习

- 原文：`在公司实习，负责后端开发。`
- v1：`负责订单模块的接口开发与维护。`
- v2：`订单模块实习开发：独立交付 3 个接口（日均调用约 2 万次），把其中一个报表接口的 P99 从 1.2 秒优化到 300 毫秒（加索引 + 批量查询），并补了 12 条回归测试。`
- 理由：数字有口径（日均、P99）、手段具体、有质量动作。

## 5. 转行

- 原文：`自学前端，做过几个练习项目。`
- v1：`自学 React，完成记账与待办两个练习项目。`
- v2：`从 X 岗位转向前端（自学 9 个月）：为原公司内部做客户随访看板（React + 接口对接），替代原先每天手工汇总 Excel 的流程，团队 4 人日常使用；另有开源组件库贡献 2 个修复。`
- 理由：用工作场景里的真实需求证明能力，比练习项目可信。

## 6. 工作 1–3 年

- 原文：`负责公司内部系统的开发与维护。`
- v1：`负责内部系统的需求开发、上线与维护。`
- v2：`负责内部审批系统的一条业务线：完成 2 次版本重构（把单体拆分为 3 个服务），支撑日活从 300 涨到 1200；制定接口规范后被另外 2 个团队采用。`
- 理由：从「做事」升级到「影响范围与标准化」，这正是社招看的东西。

## 六条通用规则

1. 每条只说一件事，句式：为 X 问题 → 做了什么 → 结果如何；
2. 数字必须带口径，否则是自设陷阱；
3. 写「你的动作」，不写「项目的动作」；
4. 删掉无法验证的词（精通、熟练掌握、深刻理解）；
5. 排序按目标岗位相关度，不按时间；
6. 一页为限，超出就删最弱的。

## 自检

- 每条能不能被追问三层而不崩？
- 有没有一条体现了「你的判断」，而不只是「你的执行」？
- 目标岗位的 JD 关键词，我哪些真实具备却没写？
