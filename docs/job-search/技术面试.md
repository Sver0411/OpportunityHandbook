# 技术面试全流程

技术面试考的不是「你记得多少」，而是「给你一个没做过的问题，你能不能有条理地推进」。

## 五类题与各自的准备方式

| 题型 | 考什么 | 准备方式 |
| --- | --- | --- |
| 知识题 | 基础是否扎实 | 列清单自测，能当场推导，不背结论 |
| 项目题 | 你是否真的做过 | 见 [项目面试](项目面试.md) |
| 编程题 | 能不能写出可运行的代码 | 限时练，先讲思路再写 |
| 调试题 | 遇到未知错误怎么办 | 见 [如何 Debug](../learning/调试方法.md) |
| 系统设计 | 会不会权衡 | 从需求与规模出发，边画边讲取舍 |
| 领域题 | 岗位特有的知识 | 按 JD 关键词准备 |

## 现场的四条纪律

1. **先澄清再动手**：边界、规模、约束、输入输出格式。问清楚不是示弱，是基本功；
2. **思考出声**：把假设、方案、为什么放弃另一条路说出来。面试官评估的是过程；
3. **先给可用解，再谈优化**：能跑的思路比完美但没写完的思路分高；
4. **不会就直接说**：「这块我没有系统学过，我的思路是……」然后给一个可验证的推理。

## 遇到不会的题怎么做

- 说出你已知的相邻知识（「我没用过这个库，但我知道这类问题通常是……的机制」）；
- 把问题拆小：「如果简化成只有一台机器，我会这样做」；
- 说明你会怎么查：文档的哪一节、用什么关键词、如何验证；
- 不要在沉默里硬撑，也不要编造 API 名字。

## 系统设计题的推进顺序

需求 → 规模估算 → 数据模型 → 接口 → 核心流程 → 瓶颈与权衡 → 失败与监控。

每一步都留一句「这里我做了取舍，因为……」。规模估算不必精确，但要有数量级与推导过程。

## 不同岗位的差异

- **后端 / 基础设施**：并发、数据一致性、故障处理；
- **前端**：渲染与状态、性能、兼容与可访问性；
- **嵌入式**：资源约束、实时性、硬件交互；
- **数据 / 算法**：特征与指标、实验设计、线上效果；
- **测试 / QA**：用例设计、边界与失败路径。

## 面试后 24 小时必须复盘

写下：问了什么、你答了什么、卡在哪、正确思路是什么、下次怎么改。复盘三次之后，重复题型的表现会明显变化。模板见 [面试复盘表](../tools/面试复盘表.md)。

## 自检

- 我能不能在 30 秒内说清自己的思路，再开始写？
- 被追问「还有别的方案吗」时，我能给出两个并说明取舍吗？
- 不会的题我是怎么处理的？有没有编造？
- 上次面试的三个卡点，我补了吗？
