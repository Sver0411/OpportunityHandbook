# 数据与 AI 竞赛

数据与 AI 竞赛（Kaggle、天池类平台赛、企业命题赛、线下建模赛）的特点是**评价自动、可量化、可复现**：同一份提交能被反复打分，因此它比大部分活动更容易变成证据。

## 两类赛制，工作方式完全不同

| 类型 | 形式 | 关键点 |
| --- | --- | --- |
| 平台赛（线上） | 给定数据与评测接口，长期开放 | 可以反复提交，注重迭代与特征工程 |
| 现场/线下赛 | 限时（几小时到几天），团队提交报告 | 注重快速建模 + 写作表达 |
| 企业命题赛 | 真实业务问题，评审包含业务方 | 注重问题定义与方案可落地性 |

**线下赛的胜负常在写作**：模型差不多时，讲得清「数据怎么理解、验证怎么做、结论边界在哪」的队伍得分更高。

## 从零到提交：可执行的流程

```
1. 读题与数据：字段含义、缺失率、标签分布、时间范围
2. 建一个能跑通的基线（最简单的模型 + 固定切分）
3. 建立可信的本地验证集（不要用测试集调参）
4. 特征与模型迭代：每次只改一件事，记录离线与线上分数
5. 误差分析：看错得最多的样本长什么样，往往能发现数据问题
6. 提交与选择：按线下验证选提交，不要被排行榜牵着走
7. 复盘与整理：代码、说明、结论写成仓库
```

## 排行榜的陷阱

- **公开/私有榜单不一致**：公开榜高分不等于最终高分，**过拟合排行榜**是新手最常见的失败；
- **数据泄漏**：时间序列用了未来信息、ID 与标签相关、交叉验证划分不当——这类「高分」在真实场景里不可用；
- **评测口径未知**：有些比赛指标与业务目标脱节，得高分未必解决真问题；
- **重复提交刷分**：消耗时间但不带来方法上的进步。

**建议**：把「线下验证的稳定提升」当作主要目标，排行榜当作参考。

## 团队怎么分工

数据竞赛的常见有效分工：数据处理（清洗、特征）、建模（模型与调参）、验证与提交（流程与记录）、写作（报告与结论）。**必须有一个统一记录文件**（谁改了什么、对应分数多少），否则多人改动无法归因。

## 把名次变成可讲的作品

竞赛结束后，把过程整理成一份可以给别人看的东西：

- **README**：问题、数据、方法、验证方式、结果；
- **关键决策记录**：为什么这样切分数据、试过哪些方案、哪个失败；
- **可复现说明**：环境、随机种子、运行步骤；
- **局限**：在什么条件下这个方法会失效。

**面试中真正加分的是「你做过哪些判断」**，而不是名次本身。

## 判断值不值得参加

- 想进入数据/算法方向且缺少项目 → 很值得（能快速产出可展示的完整流程）；
- 已有真实业务项目或实习 → 边际收益下降，优先级可后移；
- 时间紧（考试、毕业）→ 选限时短的线下赛或小型平台赛，别开长期战线；
- 想练工程能力 → 平台赛的提分乐趣可能掩盖工程能力的缺失，需要额外补。
