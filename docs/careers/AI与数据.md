# AI 与数据

判断方法一律在主线：[怎么了解一个行业](../../book/02-在学校里先把基础打好.md#understand-industry)、[怎么从岗位要求反推技能](../../book/02-在学校里先把基础打好.md#skill-reverse-engineer)。

## 先把「AI 与数据」拆开

这个大类至少包含六类工作，招聘时的标题、面试内容与准备方式都不一样：

- **数据分析（Data Analyst）**：回答业务问题。写 SQL 取数、设计指标、做可视化、写结论，输出是「这个月为什么掉了 8%」这类判断。门槛最友好，业务理解权重高；
- **数据科学（Data Scientist）**：在分析之上处理预测与实验。做 A/B 实验设计、统计建模、因果推断，输出常是「要不要上这个改动」；
- **数据工程（Data Engineer）**：搭建与维护数据管道、数仓与调度，保证数据按时、准确、可追溯。是数据团队里最被低估、岗位缺口也较稳定的一类；
- **机器学习工程（MLE）**：把模型做成可上线的系统——特征、训练流程、推理服务、监控与回滚；
- **算法研究（Research / Applied Scientist）**：解决问题本身，产出偏论文、专利或新方法，常要求研究型学位；
- **AI 应用/产品方向**：把模型能力接进业务流程，做评测、提示与产品化，对工程与产品的复合能力要求高，对数学要求相对低。

**最容易犯的误解**是把它们混成「AI」：一个想做数据分析的人，按算法岗的路线去刷数学题，往往两头落空。

## 每天到底在做什么

- 分析与科学岗：大量时间在取数、核对口径、和业务方确认问题，真正建模的时间占比不高；
- 数据工程岗：写管道、处理脏数据与失败重试、盯任务与成本；
- MLE：上线与维护的比重往往超过训练模型，排查线上效果衰减是日常；
- 研究岗：读论文、做实验、写稿，失败与返工的比重很高（见 [科研到底是什么](../../book/03-开始积累真正能留下来的经历.md#research-what-is-research)）。

## 什么最被看重

- **学历**：研究岗与部分大厂算法岗对硕士/博士有偏好；分析、数据工程岗更看经历与技能；
- **作品与项目**：一个能跑通的数据项目（数据来源 → 清洗 → 建模 → 结论）比「学过机器学习」有力得多，见 [什么才算真正的项目](../../book/03-开始积累真正能留下来的经历.md#project-what-is-real)；
- **竞赛与公开产出**：数据竞赛的排名是可量化的证据（见 [编程与数据竞赛](../../book/03-开始积累真正能留下来的经历.md#competition-programming-contest)）；
- **业务理解**：越往上越关键——能定义对的问题，比能把模型调准更稀缺。

## 用什么方式判断门槛

去招聘平台搜「数据分析 / 数据工程 / 机器学习」等具体岗位名，各收集 15–20 条 JD，比较它们的学历、技能与年限要求：这三类岗位的要求差异大得惊人。**不要用一个岗位的要求推另一个岗位。** 具体的方法见 [怎么看招聘 JD](../../book/02-在学校里先把基础打好.md#read-jd)。

## 怎么低成本试一次

- 选一个你真正关心的问题（自己专业的就业数据、某平台的公开数据），完整走一遍分析流程并写成报告；
- 用公开数据集打一场入门级数据竞赛，走完提交与复盘；
- 想判断自己是否适合工程侧，就试着把一个小模型部署成能访问的服务，看自己是享受还是厌烦。

## 需要留意的资质与监管

这个大类通常**没有统一的法定准入资格**，招聘看能力与经历。但以下情况需要额外核实：涉及个人信息、医疗与金融数据的处理，受数据安全与行业监管约束；部分金融风控、征信相关岗位有明确的合规要求。具体以行业主管部门规定与用人单位的合规要求为准。

## 信息入口

- 招聘平台的目标岗位 JD（判断门槛的第一手材料）；
- 公开竞赛平台与开源项目（作品与证据来源）；
- 各高校与企业的招聘页面（了解真实岗位划分）；
- 国家数据局与行业主管部门发布的数据合规文件（涉及数据业务时核实）。
