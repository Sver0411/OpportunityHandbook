# 技术与工程

判断方法一律在主线：[怎么了解一个行业](../../book/02-在学校里先把基础打好.md#understand-industry)、[证书到底该不该考](../../book/02-在学校里先把基础打好.md#certificate-not-for-certificates)。

## 这个大类内部差异极大

「技术与工程」至少包含两类性质完全不同的路径：

**数字与软件方向**
- **软件开发**：前端、后端、移动、测试、运维/平台，入门门槛主要是可运行的作品与代码能力；
- **数据与基础设施**：与 [AI 与数据](AI与数据.md) 有重叠，偏工程一侧。

**实体与制造方向**
- **电子 / 嵌入式**：电路、固件、传感器与设备调试，往往需要实验室与设备经验；
- **机械 / 自动化**：结构设计、工艺、产线调试，图纸与实物经验并重；
- **土木 / 建筑 / 能源**：项目周期长、现场经验重要，且**受注册执业制度约束**（见下）。

同一个「工程师」头衔，在这些方向里的日常工作、门槛与职业路径几乎不共享。

## 每天在做什么

- 软件方向：写代码、评审、排查线上问题、对齐需求；产出以可运行的系统和代码为主；
- 电子/嵌入式：调试板子、看波形、解决时序与稳定性问题，实物与设备是工作对象；
- 机械/自动化：绘图、算强度、跟产线、处理装配与工艺偏差；
- 土木/能源：跟项目、跑现场、做算量与合规审查，周期以月或年计。

## 什么最被看重（分方向）

| 方向 | 主要证据 | 学历权重 | 法定资格 |
| --- | --- | --- | --- |
| 软件开发 | 项目、代码仓库、实习 | 中（部分公司收紧） | 无统一准入 |
| 电子 / 嵌入式 | 实做项目、竞赛、实习 | 中高 | 部分岗位有行业认证 |
| 机械 / 自动化 | 图纸与项目、实习 | 中 | 部分职业需注册或评审 |
| 土木 / 建筑 | 项目经历 + 注册资格 | 高 | **注册类执业资格较关键** |
| 能源 / 电力 | 项目 + 资质 | 高 | 相关执业与安全资质 |

**重要提醒**：受监管的工程职业（如注册建筑师、勘察设计注册工程师、注册建造师等）需要**考试与注册**，学位本身不等于执业资格。具体报考条件、专业范围与年限要求，以住房和城乡建设部、人力资源和社会保障部及中国人事考试网当年文件为准。

## 怎么判断具体岗位的门槛

按 [怎么看招聘 JD](../../book/02-在学校里先把基础打好.md#read-jd) 的方法做：收 15 条同方向 JD，看它们反复出现的工具、项目类型与证书要求。软件方向常见「作品 + 实习」，实体方向常见「专业对口 + 项目经历 + 资格」。

## 怎么低成本试一次

- 软件：做一个两周能用的小工具，部署成可访问的服务；
- 电子/嵌入式：买一块开发板完成一个完整小项目（采集 → 处理 → 输出）；
- 机械/自动化/土木：参与一次真实的竞赛、实训或实习项目，重点体验「跟完一个周期」是否受得了。

## 常见误区

- 「工程师都靠技术，不看资格」——实体工程方向的注册资格常常决定能不能签字负责；
- 「软件不用读太多书」——基础概念不过在面试与排查问题时会持续暴露；
- 「先学会所有工具再找实习」——顺序反了，见 [学课程还是直接实践](../../book/02-在学校里先把基础打好.md#skill-course-or-practice)。

## 一张表看懂：六个方向的证据形态

| 方向 | 日常工作占比最高的事 | 简历上最有力的证据 |
| --- | --- | --- |
| 后端 / 服务端 | 接口、数据、排障 | 性能数字（P95、并发）+ 一次故障处理记录 |
| 前端 / 客户端 | 界面实现、性能、兼容 | 线上地址 + 首屏/包体数据 |
| 嵌入式 / 硬件 | 驱动、板级调试、长时运行 | 真机 + 72 小时运行 + 功耗与丢包数据 |
| 算法 / 建模 | 数据、实验、调参 | 基线对比 + 消融 + 可复现脚本 |
| 测试 / 质量 | 用例设计、自动化、发布把关 | 一份测试计划 + 缺陷清单 |
| 运维 / SRE | 部署、监控、事故处理 | 监控告警方案 + 一次事故复盘 |

## 一个具体的人：机械专业怎么挤进嵌入式

小陈，机械设计制造及其自动化，大四，想进嵌入式但没写过单片机。

- **第 1 步（1 周）**：翻 12 份嵌入式 JD，发现高频要求是 C 语言（12/12）、一款 MCU（10/12）、通信协议（9/12），而不是他担心的「电子电路设计」；
- **第 2 步（5 周）**：买一块 ESP32（约 50 元），做「温湿度采集 + 上报」：先点亮，再加 MQTT 上报，再加断网重连，最后连续跑 72 小时记录丢包与重启；
- **第 3 步（1 周）**：把过程写成 README：接线图、复现步骤、72 小时结果（丢包 0.3%、0 重启）、已知限制（远距离丢包上升）。简历里写成一条：「用 ESP32 + MQTT 完成采集节点，连续运行 72 小时、丢包 0.3%」；
- **结果**：投 15 家嵌入式岗位，3 个面试，最终入职一家工业控制公司做固件（起薪 8k，苏州）。

**他的优势很具体**：机械背景让他看得懂结构图与装配关系，这在嵌入式岗位上反而是加分项。
