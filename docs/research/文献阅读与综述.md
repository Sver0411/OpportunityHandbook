# 文献阅读与综述

读文献最大的浪费不是读得慢，而是**读完不知道留下了什么**。这一页给一套可执行的流程：先过滤，再精读，最后把读到的变成能用的东西。

## 第一步：先决定「这篇要不要读」

按三轮过滤，成本从低到高，随时可以停：

1. **只看标题**（5 秒）：领域与问题是否相关？不相关直接跳过；
2. **看摘要 + 图表 + 结论**（3–5 分钟）：它解决的问题、用的方法、结论的边界条件。写下三行笔记，判断是否需要精读；
3. **精读方法与实验**（30–90 分钟）：目标是能回答两个问题——「如果我来复现，缺哪一步？」「它的结论在什么条件下不成立？」

**关键判断**：一篇文献值不值得精读，取决于它和**你要回答的问题**的距离，而不是它看起来是否权威。综述、经典与最新工作的读法不同。

## 第二步：笔记怎么记才有用

推荐一种简单结构（每篇一条，用文献管理器或纯文本都行）：

```
标题 / 作者 / 年份：
解决的问题：
方法（一句话）：
关键结论与边界条件：
与我关心的关系（支持 / 反驳 / 提供工具 / 无关）：
可复现性（有无代码、数据、环境说明）：
疑问与待查：
```

**不要整段摘抄原文**。摘抄看起来在积累，实际很难复用。真正有价值的是「用你自己的话重述结论与限制」。

## 第三轮：用引文网络代替漫游

- **往前看**：这篇文章引用的哪几篇是它的基础？只挑被多次引用的；
- **往后看**：谁引用了它、后续有没有推翻或改进？这一步能快速了解一个方向的演进；
- **找综述**：先读一篇近三年的综述建立地图，再挑其中被反复提到的具体工作精读。**综述不适合作为唯一来源**（它有作者视角），但适合当索引。

## 从阅读到综述：写作流程

综述的难点不是读，而是**组织**。一个可执行的顺序：

1. **定范围**：明确你要回答的问题（例如「这个方法的失效条件有哪些」），范围太大写不下去；
2. **建表**：列一张表，行是文献，列是「方法 / 数据 / 结论 / 局限」。**这张表就是综述的骨架**；
3. **找分歧**：把结论不一致的文献挑出来，说明差异来自哪里（数据、定义、实验设置）——这是综述最有价值的部分；
4. **写结构**：按「问题 → 已有方法的分类 → 分歧与局限 → 缺口」组织，而不是按时间罗列；
5. **标注不确定性**：哪些结论有多篇支持、哪些只有一篇、哪些互相冲突，必须写清。

## 常见的时间浪费

| 浪费方式 | 表现 | 改法 |
| --- | --- | --- |
| 从摘要读到附录 | 每篇都花两小时 | 三轮过滤，允许跳过 |
| 只收藏不整理 | 收藏夹几百篇，没有笔记 | 每篇必须留下三行结论 |
| 追求读完全部相关工作 | 永远开始不了自己的问题 | 读完「最相关的 20 篇」就动手 |
| 用翻译软件代替理解 | 每个词都懂，连起来说不清 | 用自己的话复述一段 |
| 只读不写 | 读了很多但写不出 | 每周写一段小结 |

## 什么时候算读够了

判断标准不是数量，而是**你能不能回答**：

- 这个方向现在的主流方法是什么？它解决了什么、还剩下什么？
- 你要做的问题，和已有工作的差别在哪？
- 如果你现在动手，最小可验证的一步是什么？

三个问题都能一句话答出，说明可以停止阅读、开始做。

## 工具

- **文献管理器**：Zotero 等，用来管理条目、笔记与引用格式；
- **预印本**：arXiv、bioRxiv 等（注意预印本未经同行评审）；
- **引文网络**：Google Scholar / Semantic Scholar 等的引用与相似文献；
- 检索语法：多数数据库支持布尔运算与字段限定，先把「关键词 + 限定」练熟。
