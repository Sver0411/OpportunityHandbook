# 实验设计与数据

实验的目的不是「做出结果」，而是**让结果能被相信、能被重复**。这一页讲四件事：怎么设计、怎么做够重复、怎么记、结果不对时怎么排查。

## 一、先把假设写成一可被证伪的句子

「A 比 B 好」不是假设，因为它无法被证伪。可证伪的写法是：

> 在条件 C 下，方法 A 的指标 M 高于方法 B，且差值超过测量误差范围。

三个要素缺一不可：**条件 C、指标 M、可判断的差异阈值**。写成这样之后，「需要哪些对照组」几乎自动就出来了。

## 二、对照组与变量控制

- **必须有基线**：至少包含当前主流方法或最简单的可行方法。没有基线的「提升」无法解释；
- **一次只改一个变量**：同时改数据、超参、硬件，就无法归因；
- **消融实验（ablation）**：逐个去掉你的设计模块，看指标怎么变。这是审稿人最常要求补充的部分；
- **警惕混杂因素**：数据划分、随机种子、机器负载、试剂批次、操作者——它们都可能解释差异。

## 三、样本量与重复

- **重复的必要性**：单次结果无法区分「真实差异」与「随机波动」。实验科学通常要求生物学重复与技​​术重复分开；计算实验通常要求多随机种子；
- **样本量与统计**：需要多少重复取决于效应大小与噪声。做法是先做小规模预实验估计噪声，再决定规模；报告时给出**均值、方差与样本量**，而不是只报最好的那一次；
- **不要用调整阈值的方式「凑显著」**：这在方法上是错的，也是学术不端的常见起点；
- **记录失败的运行**：被丢弃的运行也要记录（丢了多少、为什么丢），否则会系统性高估效果。

## 四、数据记录与管理

最低可接受标准：

```
原始数据：不覆盖，按日期与条件命名，保留未处理版本
处理脚本：版本可追溯，能一键从原始数据复现中间结果
环境记录：依赖版本、随机种子、硬件/仪器型号与参数
日志：每次运行做了什么、观察到什么异常
说明文件：README 写清目录结构、文件含义、如何重跑
```

这套做法对应 FAIR 原则（可发现、可访问、可互操作、可复用）。**写论文时才发现数据对不上，是实验室里最常见也最昂贵的返工**。

## 五、结果不对时的排查顺序

按「最容易出错、最容易验证」的顺序查：

1. **数据**：样本顺序、标签对齐、划分是否泄漏、单位与量纲；
2. **代码**：随机种子、是否真的用上了新参数、缓存是否生效、评估脚本是否与训练一致；
3. **实验设置**：对照组是否真的公平（同样的数据量与调参预算）；
4. **测量**：仪器校准、环境条件、操作差异；
5. **假设**：以上都排除后，才考虑「原假设可能不成立」——这是最有价值的结论，但必须在排除前四条之后。

**重要**：把每次排查的结论记下来，组里的人会反复遇到同一个坑。

## 六、什么算「做完了」

- 结果在多次重复下稳定，且给出了不确定性；
- 有合理基线，且有消融说明每个设计的贡献；
- 换一份数据或换一个环境仍能得到方向一致的结论（或明确指出适用边界）；
- 别人拿着你的代码与说明能复现；
- 失败与限制写进了报告。

## 七、涉及人与动物时的额外要求

涉及人类受试者、人体样本、动物实验、个人信息的实验，必须先走伦理审查与知情同意流程，并遵守数据保护要求。这类流程通常需要提前数周准备，**不要等实验做完才补手续**。
