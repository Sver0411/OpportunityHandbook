# 科研手册

这一页不回答「要不要做科研」——那是主线的事，见 [科研到底是什么](../../book/03-开始积累真正能留下来的经历.md#research-what-is-research) 与 [读博值不值得](../../book/07-当职业开始出现分岔.md#research-phd-worth-it)。这一页回答另一个问题：**科研在现实中是怎么运作的，每一步具体要做什么、判断标准是什么、什么时候该停下来。**

## 科研工作的真实形态

论文里的科研是一个干净的故事：提出问题 → 设计方法 → 实验验证 → 得出结论。真实的科研是一个循环，而且大部分时间花在循环里最不出成果的部分：

```
读文献（并且发现别人早就做过）
→ 提出一个可能的问题
→ 发现工具/数据/设备不支持
→ 换一个更小的问题
→ 做实验，失败
→ 找失败原因（可能是代码、仪器，也可能是自己理解错了）
→ 重做，得到结果
→ 结果解释不通
→ 再读文献，发现漏了一个条件
→ 重做
→ 写出来，被审稿人指出漏洞
→ 补实验、改稿
```

一个可参考的经验比例（不同领域差异很大）：**读文献与思考、动手做、写作与沟通大致各占三分之一**，而真正「产生新结论」的时刻很短。选这条路之前，值得先接受这一点——见 [怎么判断自己是否喜欢科研](../../book/03-开始积累真正能留下来的经历.md#research-do-i-like-it)。

## 不同类型的科研，门槛完全不同

「科研」不是一种工作。至少分四类，需要的技能、日常状态与产出形态差别很大：

| 类型 | 日常工作 | 关键能力 | 常见卡点 |
| --- | --- | --- | --- |
| 实验科学（生物、化学、材料、医学） | 设计实验、操作仪器、重复 | 动手的稳定性、记录规范、耐心 | 条件不稳、周期长、设备与试剂排队 |
| 理论与数学 | 推导、证明、构造反例 | 数学功底、抽象思维 | 长期无进展、方向选错代价大 |
| 计算与数据（计算物理、生信、机器学习） | 写代码、跑实验、调参、复现 | 工程能力、实验设计、可复现意识 | 结果不可复现、算力与数据受限 |
| 工程与系统（系统、机器人、人机交互） | 造原型、做测量、跑用户 | 系统实现能力、测量方法 | 工程量被低估、评测口径不统一 |

**用自己的工程能力去做第四类，比自己数学一般却硬做第二类要现实得多**——这是择方向时常被忽略的一点。

## 本科、硕士、博士分别承担什么

三个阶段的差别不是「水平高低」，而是**你负责哪一段**。

- **本科阶段**：通常从「协助」进入。整理数据、复现代码、跑实验、查资料、做组会 PPT、清洗数据都是正常起点。目标是**先看清一个课题怎么运转**，并让导师知道你能交付；
- **硕士阶段**：一般需要在别人的问题框架内完成一部分工作，能独立跑通一个流程并解释结果；是否提出自己的问题，取决于课题类型与导师安排；
- **博士阶段**：核心要求是**自己定义问题并证明它值得做**，同时组织资源（人、设备、经费、合作者）把它做完。所以博士的困难往往不在技术，而在判断。

**常见误区**：本科进组几个月还在打杂就怀疑自己不适合科研。先看两件事——导师有没有给过完整的小任务、你有没有把任务做到能让别人直接用的程度。两条都满足却还是没有机会，才值得考虑换组（见 [怎么判断一个实验室](../../book/03-开始积累真正能留下来的经历.md#research-choosing-a-lab)）。

## 找方向：从问题进入，而不是从领域进入

「我对人工智能感兴趣」不能作为起点，它太大了。可行的做法是**从一个具体现象开始**：

1. 在学过的课程或做过的项目里，找一个「按道理应该这样，但实际不是」的现象；
2. 读这一现象下被引用最多的五到十篇论文，弄清已经解决了什么、还剩什么；
3. 判断「剩下的那部分」能不能在一学期内做出一小步验证；
4. 不行就退回第 1 步换一个现象。

这个过程通常要重复三到五次才能找到一个真正能做的题目。**找不到方向不是能力问题，是还没读够具体的文献。**

## 找实验室与导师：看什么、问什么

公开信息能看到的：近三年论文的产出节奏、一作是谁、经费来源、毕业生去向、组里有没有工程基础。看不到但决定体验的：指导频率、是否允许试错、组会氛围、毕业要求。这部分只能问人，问法见 [怎么找导师](../../book/03-开始积累真正能留下来的经历.md#research-find-supervisor)。

一份可以直接填写的对照表与逐列判断说明在 [导师筛选表](../tools/导师筛选表.md)。

## 第一次联系导师

不同招生体系的规则不同：导师制强的项目需要提前联系并确认是否有位置；委员会制项目先看官方说明是否鼓励联系。**邮件怎么写、标题怎么取、附不附研究计划、多久不回该怎么办、不同回复分别意味着什么**，在 [联系导师与套磁](../research/联系导师与套磁.md) 里逐项展开；配套模板见 [联系导师邮件模板](../tools/联系导师邮件模板.md)。

## 进组以后的路径

```
执行别人定义的任务
↓（做出可靠交付，导师开始给更重要的活）
理解为什么要这样做（读背景、问清假设与约束）
↓
提出局部改进（换一种方法、补一个对照、修正一个假设）
↓
提出自己的小问题（能在几周内验证）
↓
独立负责研究的一部分（自己定问题、自己安排资源）
```

**卡在第 1 步出不来是最常见的情况**，原因通常有三种：任务没有交付标准（去问「什么算做完」）、交付质量不稳定（先把重复性任务做到零返工）、组里根本没有在做的课题（这是要换组的信号）。对应动作与节奏见 [科研入门时间线](../timelines/科研入门时间线.md)。

## 文献：不要从摘要开始读

一个可执行的三轮读法：

1. **第一轮只看标题、摘要、图表**，判断它是否值得花 5 分钟继续；不确定就跳过，不要有心理负担；
2. **第二轮读引言与结论**，写下它解决的问题、用的方法、结论的边界条件；这一步决定要不要精读；
3. **第三轮精读方法与实验**，目标是能回答：「如果我来复现，缺哪一步？」「它的结论在什么条件下不成立？」

工具层面，文献管理器（Zotero 等）、预印本平台（arXiv、bioRxiv 等）、引文网络（谁引了它、它引了谁）比「读得多」更重要。**一个月整理出二十篇真正读懂的文章，胜过浏览两百篇摘要。**

## 复现：性价比最高的一次训练

第一次进组，最值得主动争取的任务是**复现一篇论文的关键结果**。它同时训练读方法、写代码、调环境、处理数据、判断「差一点点」是不是错，而且产出一个可展示的成果。做法：

1. 选一篇有公开代码或数据、结果明确的文章；
2. 先用原文数据跑通，再换成同领域另一份数据；
3. 记录所有与原文不符的地方——**这些「不一致」本身就是有价值的信息**（可能来自版本、超参、数据预处理差异）；
4. 写成一份简短复现报告：环境、步骤、结果、差异原因、能否重复。

这类报告可以放进 [项目与作品手册](项目与作品手册.md) 里说的作品集，也是面试中最有说服力的材料之一。

## 实验与数据：记录规范决定你能走多远

科研的可信度建立在「别人能按你的记录重复出来」。最低标准：

- **原始数据不覆盖**：每次实验产出新文件，命名带日期与条件；
- **环境可重建**：依赖版本、随机种子、硬件条件写进说明；
- **过程有日志**：做了什么、改了哪个参数、观察到什么异常；
- **负数也要记**：失败的实验与无效的对照组同样是结果，不记会导致重复踩坑。

数据管理的通用原则可参考 FAIR 原则（可发现、可访问、可互操作、可复用）；具体规范以导师与所在机构要求为准。

## 研究问题：怎么判断它值得做

四个可以自问的问题：

1. **它是不是真问题**——现有方法在什么条件下失效？有没有可观察的后果？
2. **它是否已被解决**——重点不是「没人做过」，而是「现有工作为什么不够」；
3. **它能不能被证伪**——能否设计一个实验，让「我有道理」与「我错了」产生不同的可观察结果；
4. **它是否做得完**——在你拿得到的设备、数据、时间与人手下，最小可验证的一步是什么。

四条里任何一条答不出，通常是问题还没想清楚，而不是缺资源。

## 失败、负结果与什么时候停

- **负结果是结果**：证明「这条路不通」有价值，很多领域的进展来自排除；
- **区分三种失败**：方法错了（换方法）、问题选错了（换问题）、条件不具备（换时间或换资源）——应对完全不同；
- **止损标准**：给一个方向设检查点（例如两个月）。到点连「最小可验证的一步」都没跑通，且原因不是投入不足，就值得换方向或请导师评估。

## 论文：写作、投稿与审稿

- **结构**：引言回答「为什么值得做」，方法回答「怎么做的、能不能复现」，结果回答「看到了什么」，讨论回答「意味着什么、边界在哪」。审稿人首先找的是「结论有没有被数据支持」；
- **投稿流程**：选刊（范围、周期、审稿口碑）→ 投稿 → 编辑初审（可能直接拒稿）→ 外审 → 修改或拒稿 → 接收与校对。周期从几周到一年以上都有，**不要把毕业或申请卡在一篇论文的接收时间上**；
- **常见拒稿原因**：与期刊范围不符、贡献增量不足、方法描述不可复现、结论超出数据支持范围、语言与结构不清；
- **被拒之后**：按意见修改再投是常态。保留一份「审稿意见 → 修改点」对照表，对下一篇同样有用。

更细的操作（结构拆解、审稿意见怎么回、常见策略）见 [论文写作与投稿](../research/论文写作与投稿.md)。

## 作者与署名

署名规则按领域与期刊不同，通用原则是**对研究有实质性贡献**（设计、执行、分析、写作）才署名，提供资源或一般性支持通常写进致谢。需要提前注意：

- 作者顺序的含义在不同领域差别很大（有的按贡献，有的按字母序），**投稿前与导师确认**；
- 通讯作者、共同一作的标注要在投稿时写清；
- 避免「送礼式署名」与「挂名」，这类行为在多数机构的学术规范中属于不端。

## 学术会议

会议的价值不只是发论文：它是**让同行知道你在做什么**的地方，也是找工作与找合作的实际渠道。做法上，先看会议范围与往届论文判断是否对口，再看截止时间与评审方式（全文评审还是摘要评审），准备一页讲清问题与结果的材料。参会时优先做两件事：听与自己方向最近的报告、主动和报告人聊十分钟。

## 推荐信怎么来

推荐信是日常交付的副产品。能让导师写出细节的前提是：他记得你做过什么、遇到过什么问题、你怎么解决的。可操作的做法是——每完成一个阶段给导师一段简短总结（做了什么、卡在哪、怎么解决），需要推荐信时再附一份材料清单。见 [推荐信](../../book/04-当你开始面对第一次重要分流.md#research-recommendation-letter)。

## 学术伦理：几条不能碰的红线

以下行为在几乎所有机构的规范里都属于学术不端，后果严重：

- 数据造假、篡改、选择性删除不利数据；
- 抄袭与不当引用（照搬他人文字、用了别人的 idea 不标来源）；
- 一稿多投、重复发表、拆分发表注水；
- 不当署名（挂名、占用他人贡献）、代写代投；
- 未经许可使用他人数据、代码、材料，或违反伦理审查要求（涉及人类受试者、动物实验、个人信息时尤其严格）。

依据可参考教育部《高等学校预防与处理学术不端行为办法》与所在机构的具体规定；涉及人类与动物的研究必须走伦理审查流程。

## 是否适合长期做科研

四条自测（任一条长期不成立都要重新评估）：

1. 能否接受「大部分时间没有结论」的日常？
2. 是否愿意为了一个问题持续读文献并反复验证？
3. 面对失败时，第一反应是找原因还是找借口？
4. 是否有稳定产出的节奏，而不是靠灵感？

回答完之后，再用一段真实经历（进组半年以上）验证，不要凭想象判断。

## 与升学、就业的关系

- **升学**：科研经历是研究型项目申请中最有说服力的材料（研究计划、推荐信、面谈都围绕它）。对授课型项目，它的权重低于成绩与语言，但能体现动机；
- **就业**：产业研究岗、算法岗、研发岗看「可复现的产出与工程能力」；非研究岗看解决问题的过程与协作经历——**科研训练里最有迁移价值的是「把问题定义清楚并验证」的方法**，见 [哪些能力可以跨路线使用](../../book/01-先决定下一步往哪里走.md#optionality-transferable)。
