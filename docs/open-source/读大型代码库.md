# 如何读一个大型代码库

读代码库的目标不是「读完」，而是**能改动一处并解释它的影响**。按下面顺序走，通常几天就能动手。

## 七个动作

1. **找入口**：从 CLI 命令、HTTP 路由表、主函数、插件注册处进入。找出「用户的一次操作从哪开始」；
2. **看目录**：不要逐个目录读，先回答「哪几个目录是我这次要动的」；区分源码、测试、文档、脚本；
3. **跑起来**：本地构建 + 跑一次测试。**跑不起来先修环境**，否则后面全是猜；
4. **读测试**：测试是行为说明书，比文档新。找到与你目标相关的测试文件，看它如何构造输入、断言什么；
5. **追一条调用链**：选一个你熟悉的场景（例如「加载配置」），从入口一路追到数据落库，画出 5–10 个节点的链；
6. **用调试器或日志**：在关键节点打断点或加打印，看真实数据流——比读代码快得多；
7. **从 issue 反推模块**：找一个已修复的相关 issue，看它的 diff 涉及哪些文件，那就是你要关注的区域。

## 一张阅读清单

- 入口文件是哪个？
- 配置从哪来（环境变量、配置文件、默认值）？
- 数据模型定义在哪个目录？
- 错误处理与日志的统一入口在哪？
- 测试怎么跑？覆盖哪些部分？
- 我这次打算改的地方，被谁依赖？

## 常见误区

- 从第一个文件开始顺序读（几天后失去方向）；
- 只读不跑，靠想象理解；
- 一次性想读完（大型项目的正确姿势是「按任务取用」）；
- 改了代码但不跑测试，提交后 CI 失败。

## 自检

- 我能不能画出「一次请求/一次命令」的完整路径？
- 我要改的地方，被哪几个模块依赖？
- 我跑通全量测试了吗？
