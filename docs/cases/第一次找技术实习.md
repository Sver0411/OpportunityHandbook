# Case：第一次找技术实习

背景：大三上，普通本科，无实习，两个跟着教程做的项目，目标岗位是后端开发实习。时间：每周 10 小时，八周。

## 第 1–2 周：岗位调研与 JD 抽样

收集 15 份后端实习 JD，统计高频要求：

| 要求 | 出现次数 |
| --- | --- |
| 熟悉一门后端语言（Java/Go/Python） | 15 |
| 数据库（MySQL）与缓存（Redis） | 12 |
| 接口开发经验 | 11 |
| Linux 基础 | 8 |
| 分布式 / 消息队列 | 6 |

结论：语言与数据库是硬门槛；分布式是加分。技能矩阵见 [技能 Gap 矩阵](../tools/技能Gap矩阵.md)。

## 第 3–4 周：项目重构（关键动作）

原来的两个项目都是教程项目（博客 + 待办）。他没有放弃，而是**各改一处**：

- 博客项目：接上真实数据（自己写的 40 篇笔记），加接口分页与错误处理，补 6 条接口测试；
- 待办项目：加一个「并发修改」场景（两个客户端同时改同一条），记录冲突处理方案。

产出：两个能在本地跑通、有测试、有 README 的项目；一个问题清单（「为什么不用消息队列」「为什么不用 ORM」）。

## 第 5 周：简历

用 [简历从差到好](../job-search/简历改造.md) 的方法改写。第一版简历投了 10 家，**0 回复**。

## 第 6 周：诊断与修正

诊断：0 回复说明简历或渠道有问题。逐项检查后发现三个问题：

1. 简历里写的是「做了什么」，没有「解决什么问题」；
2. 技术关键词与 JD 不对齐（JD 写 MySQL/Redis，他写 SQLite/内存缓存）；
3. 渠道单一（只用了招聘平台）。

修正：重写两条项目 bullet 加入具体数字与场景；补了一个用 Redis 的缓存小项目；增加内推与官网直投两条渠道。

## 第 7 周：第二轮投递与第一次面试

再投 12 家，得到 3 个测评、2 个面试。第一次面试挂在「项目追问」：被问「你的缓存失效策略是什么」时答不上来。

复盘写进 [面试复盘表](../tools/面试复盘表.md)：问题、我的回答、正确思路、下步动作。用三天补了缓存与索引的知识，并给项目真的加上了过期策略。

## 第 8 周：第二次面试

追问链为「为什么用缓存 → 失效策略 → 如果缓存与数据库不一致怎么办 → 你怎么测的」。这次能完整回答，并主动说了限制（「没有做多级缓存，量级不需要」）。

两周后拿到 offer。

## 可复用要点

1. **先统计 JD，再改自己**——避免凭感觉补技能；
2. 教程项目不必推翻，改一两处真实场景就能显著提升说服力；
3. 0 回复要诊断三件事：表达、关键词、渠道；
4. 面试挂点当天就要变成补课清单；
5. 「主动说出限制」比硬撑更加分。
