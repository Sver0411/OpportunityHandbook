# Case：把一次竞赛变成作品集与简历素材

背景：大二学生参加一次 48 小时 Hackathon（4 人队，主题为校园服务）。结果：**没有获奖**。

## 赛后第一天：归档

他把所有产出放进一个目录：

```
hackathon-2026-10/
  code/            代码与提交记录
  screenshots/     界面与演示截图
  slides/          演示材料
  notes/           会议记录与分工
  retro.md         复盘
```

并写下「这一版做了什么、没做什么」。

## 复盘（一页）

| 项 | 内容 |
| --- | --- |
| 评分项 | 创新性、完成度、演示效果、技术难度 |
| 我们的方案 | 用校园卡数据做空教室推荐 |
| 结果 | 未获奖；评委反馈「数据来源合规性不清晰、演示不完整」 |
| 卡点 | 前 8 小时在做方案讨论；最后 2 小时还在改代码，演示材料是赶出来的 |
| 下次改 | ① 开工 1 小时内定范围；② 预留 20% 时间做演示；③ 涉及数据先写清来源与合规 |

**拿到了评委反馈**，这是未获奖时最值钱的东西。

## 转成作品集条目

```
问题：校园里找空教室要逐个楼查看，效率低。
我的角色：数据与前端（4 人队）。
做法：用公开的课程表数据构建占用模型，做了一个按时间段查询的页面。
结果：48 小时内完成可用原型，覆盖 3 栋楼；演示脚本与录屏。
限制：数据仅来自公开课表，未接入实时刷卡数据（这也是评委指出的问题）。
```

要点：**未获奖也可以写**，但必须写清过程、角色与限制，不写「参与」。

## 简历 bullet

> 48 小时校园服务 Hackathon（4 人队）：负责占用模型与前端实现，完成覆盖 3 栋楼的可查询原型；复盘后按评委反馈补充了数据来源与合规说明。

## 面试追问准备

按 [项目面试：从第一句开始的追问链](../job-search/项目面试.md) 准备：

- 为什么用课程表数据而不是刷卡数据（合规 + 可得性）；
- 时间不够时砍了什么（实时性）；
- 如果重做会先做什么（先定范围、先做演示材料）。

## 如果获奖了怎么做

多一步：把奖项写清级别、名次与年份；在作品集里加一节「评审关注点」——说明评审看重的维度，这显示你理解了评分逻辑。

## 可复用要点

1. 48 小时内归档（越晚越只剩模糊印象）；
2. 主动向评委要反馈，写进复盘；
3. 作品集写「问题—角色—做法—结果—限制」；
4. 未获奖的案例同样能成为面试素材，前提是能讲清过程与取舍。
