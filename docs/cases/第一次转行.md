# Case：第一次转行

背景：27 岁，机械专业本科，工作四年做工艺工程师。目标：数据方向（数据分析 / 数据工程）。可投入：每周 12 小时，周期一年。

## 第 1 步：盘点可迁移能力（两周）

按 [可迁移技能](../../book/07-当职业开始出现分岔.md#career-transferable-capital) 的做法拆活动：

- 每条产线的良率分析（Excel + 简单统计）→ 数据清洗与指标口径；
- 与设备、质量、生产三方协调 → 跨部门沟通；
- 写工艺文件与改进报告 → 结构化写作；
- 做过的自动化改造 → 需求定义与落地。

结论：**统计与沟通是现成资本，工程化（SQL、Python、数据管道）是缺口。**

## 第 2 步：Gap 与补齐（4 个月）

用 [技能 Gap 矩阵](../tools/技能Gap矩阵.md) 排优先级（以 15 份目标岗位 JD 为据）：SQL（13/15）、Python 与 pandas（11/15）、可视化（9/15）、数据仓库概念（6/15）。

补齐方式：

- SQL：在现在的岗位上把手工 Excel 报表改成 SQL 查询（**用工作场景练**）；
- Python：把一条良率分析流程脚本化，每周固定两晚；
- 数据仓库：读一份公开教程 + 用一台云主机搭一个小的采集与清洗流程。

## 第 3 步：Bridge 项目（3 个月）

他没有直接投数据岗，而是先做了一个**沾两边**的项目：把车间的设备日志采集下来，做成一张良率看板。这个项目同时用了他的行业知识和数据技能。

产出：一个能演示的看板 + 一份分析报告（问题、方法、结论、限制）。

## 第 4 步：第一轮投递（失败）

投了 20 家数据岗，**全部无回复**。

诊断（按 [求职失败诊断](../job-search/求职漏斗诊断.md)）：

1. 简历写的是「工艺工程师」，技能栏排在最后 → 招聘方看不到数据能力；
2. 项目写成了「做了看板」，没有指标与规模；
3. 投递岗位跨度过大（数据分析 / 数据工程 / 算法混投）。

## 第 5 步：修正（两周）

- 简历改成「数据导向」版本：把 SQL、Python、看板项目放到最前，工艺经历改写为「业务理解与数据来源」；
- 项目用数字重写：采集 3 类设备、日均 2 万条记录、清洗后 1.6 万条、看板被 2 个班组使用；
- 岗位收窄到「数据分析（制造业/供应链方向）」——**用行业经验做差异化**。

## 第 6 步：第二轮（成功）

再投 15 家制造业数据分析岗：4 个回复、2 个面试、1 个 offer。

面试里最关键的一问是：「你没有数据岗经验，为什么我们能要你？」他的回答用了 Bridge 项目的具体数字 + 一句：「你们的业务问题我懂，工具我在补，这两件事同时具备的人不多。」

## 一年后的状态

- 入职后前三个月补 SQL 与数据仓库；
- 第一年里把原车间的经验变成部门里的一个优势（懂现场数据怎么产生）；
- 下一阶段目标：从「分析」转向「数据管道」，见 [数据工程师](../career-guides/数据工程师.md)。

## 可复用要点

1. 转行的起点是**能力盘点**，不是学新东西；
2. 用现有岗位练新技能（他改报表的方式就是练习）；
3. Bridge 项目要同时沾两边，而不是纯练习项目；
4. 第一轮全挂要诊断到具体项（表达、关键词、跨度），不要只加大投递量；
5. 用行业经验做差异化，与科班应届生错位竞争。
