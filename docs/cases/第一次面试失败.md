# Case：第一次面试失败之后

背景：大三下找实习，投 18 家，得 3 场面试，**3 场全部在第一轮被拒**。

## 第一步：把失败分类（不是「我不行」）

按 [面试复盘表](../tools/面试复盘表.md) 逐场填，然后归纳：

| 场次 | 挂在哪 | 具体问题 |
| --- | --- | --- |
| 1 | 知识 | 「索引为什么用 B+ 树，不用哈希？」答不出 |
| 2 | 表达 | 编程题思路没说，直接写，写到一半卡住 |
| 3 | 项目深度 | 「你的缓存失效策略？」只答了「设置了过期时间」 |

三类问题性质不同：知识可以背补，表达要练，项目深度要真做。

## 第二步：逐项补（三周）

**知识（一周）**：把 Java 后端高频知识列成 20 条清单，每条要求「能当场推导」。B+ 树那条他画了三遍图。

**表达（持续）**：每天用 20 分钟做「出声思考」练习——拿一道题，边写边说，录音回听。他还请同学模拟面试两次。

**项目深度（两周）**：给项目补上真实处理——加缓存过期策略、处理缓存与数据库不一致（先更新库再删缓存）、写一条测试。这样「缓存」这题有了第一手经验。

## 第三步：第二次投递与面试

再投 12 家，得 2 场面试。

- 第一场：编程题先讲思路再写，中途被追问「时间复杂度能不能更好」，他给出了两个方案并说明取舍 → 进入第二轮；
- 第二轮挂在一个系统设计题上（没做过），但他按「先澄清需求 → 给粗方案 → 指出瓶颈」的顺序作答，面试官反馈「思路清楚，经验不足」。

虽然没拿到，但他记录了一条：**系统设计类问题需要真实项目经验，短期补不了，但可以练框架**。

- 第二场：项目追问链全部答上（冰点问题也答了），一周后拿到 offer。

## 第四步：把这次经历变成资产

他把三件东西留了下来：一份 20 条知识清单（后来还在更新）、一段录音对比（第一次和第四次出声思考的差别）、一份项目追问链文档。后来面试别的公司时直接复用。

## 复盘出来的三条规律

1. **失败必须分类**：「面试挂」不是诊断，「项目深度不够」才是；
2. **表达是可以练的**：出声思考练习两周内就有明显变化；
3. **项目深度只能靠真做**：给项目加一个真实处理，胜过背十个答案。
