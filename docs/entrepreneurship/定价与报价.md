# 定价与报价

定价的本质是**替客户回答「这件事值多少钱」**，而不是「我花了多少时间」。

## 三种报价方式

| 方式 | 适用 | 风险 |
| --- | --- | --- |
| 按项目（固定价） | 范围清晰、可估量的交付 | 范围蔓延会吃掉利润 |
| 按时计费 | 探索型、需求不明确 | 客户可能压时长；你要解释每一小时 |
| 按结果 / 分成 | 效果可量化（增长、转化） | 归因困难，收款周期长 |

新手常犯的错是「按小时报价却要交付项目成果」——两边风险都由你承担。**选一种，并写进合同。**

## 成本法作为底线

算清：所需工时 × 你的目标时薪 + 直接成本（软件、差旅、外包）+ 风险余量（通常加 20%–30%）。

这条线是底线，不是定价。客户买的是结果，愿意为「省下的时间或增加的收益」付更多。

## 价值法作为上限

问客户三件事：这件事现在每月花你多少成本？如果解决，对你的收入或风险有什么影响？有没有预算范围？

把答案换算成一个区间——这通常比按小时算出来的高得多。

## 报价单结构

```
1. 交付物清单（含格式、数量、验收标准）
2. 不包含的内容（明确排除项）
3. 时间节点与里程碑
4. 修改次数（含几轮、超出如何计费）
5. 付款结构（预付 30%–50% + 里程碑 + 尾款）
6. 报价有效期
7. 前提假设（客户需要提供什么）
```

第 2 条和第 4 条是保护自己的关键。模板见 [自由职业报价单模板](../tools/自由职业报价单.md)。

## 议价与让步顺序

客户压价时，按这个顺序让：

1. **先让范围**（去掉一部分交付内容），不要先降价；
2. 再让**时间**（分批交付、延后部分节点）；
3. 最后才让**价格**，并且与范围或周期绑定（「这个价格对应这个范围」）。

直接降价的代价：以后所有报价都会拿这个低价当参照。

## 涨价时机

- 连续三个客户都毫不犹豫地接受报价 → 报价偏低；
- 你的交付时间被排满、需要拒绝客户 → 可以涨；
- 你新增了可证明的能力或成果（案例、认证、可量化的结果）；
- 涨价方式：先对新客户执行新价格，老客户在下一轮续约时告知。

## 自检

- 我的报价包含明确的「不包含」清单吗？
- 我算过底线成本吗？
- 客户压价时，我先让的是范围还是价格？
