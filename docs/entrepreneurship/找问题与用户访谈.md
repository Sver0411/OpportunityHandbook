# 找问题与用户访谈

判断需求是否真实，只有一种可靠方式：**看人们现在怎么做，而不是听他们说会怎么做。**

## 问题从哪来

- 你自己每周重复做、又觉得别扭的事；
- 你所在行业的「大家都这么忍」的环节（表格、审批、手工对账）；
- 已经在用笨办法的人：还在用 Excel、微信群、纸质单子。

最后一条是最强的信号：**笨办法＝需求已存在**。

## 访谈脚本（20–30 分钟）

```
1（背景）你现在怎么处理 X？上一次是什么时候？
2（过程）具体怎么做的？用了什么工具？花多久？
3（痛点）哪一步最烦？出错会怎样？
4（替代）试过别的方法吗？为什么放弃？
5（代价）这件事每月花你多少时间/多少钱？
6（开放）如果有个工具能解决，你最希望它先解决哪一步？
```

## 提问禁忌

| 不要问 | 因为 | 改问 |
| --- | --- | --- |
| 「你觉得这个想法怎么样？」 | 会得到客套的「不错」 | 「你上一次遇到这个问题是什么时候？」 |
| 「你会用吗？」 | 假设性问题都答「会」 | 「你现在花多少时间在这上面？」 |
| 「你会付多少钱？」 | 没到真实场景的报价不可靠 | 「你现在为解决它花了什么成本？」 |
| 「是不是很麻烦？」 | 引导性提问 | 「哪一步最烦？」（开放式） |

核心原则：**问过去的行为，不问未来的意愿。**

## 记录结构

每位受访者一页：

| 项 | 内容 |
| --- | --- |
| 身份与场景 | 谁、什么岗位、什么工作流 |
| 现状 | 现在怎么处理、频率、耗时 |
| 痛点原话 | 直接抄他的话（不要转述） |
| 已试过的替代 | 用过什么、为什么放弃 |
| 当前成本 | 时间/金钱/出错后果 |
| 付费线索 | 有没有为此付过钱 |
| 我的判断 | 真需求 / 弱需求 / 不是需求，理由 |

攒到 8–15 份之后，看重复出现的几句话——**重复出现的就是真需求**。工具见 [客户沟通与需求确认表](../tools/客户沟通表.md)。

## 怎么判断真需求

- 有人已经在为它花钱或花大量时间；
- 痛点能被一句话说清，且不依赖教育用户；
- 解决的频率足够高（每周至少一次比一年一次有价值）。

## 常见误区

- 只问朋友和同学（他们的回答最客气）；
- 用「我觉得」代替「他们说」；
- 收集了一堆意见却不动手做最小验证；
- 把「点赞多」当成需求信号。

## 自检

- 我问的是过去的行为还是未来的意愿？
- 有几位受访者提出了**相同的**痛点？
- 有人已经为此付过钱或付出大量时间吗？
