# Playbook：第一次技术面试

## Before：从拿到面试信息开始准备

- 动作：
  1. 读岗位 JD，列出可能考的三类题（知识、编程、项目）；
  2. 复习核心知识清单，能当场推导而不是背结论；
  3. 把简历上每段经历写成「背景—动作—结果—反思」四句；
  4. 准备一段简洁自我介绍（含一个具体项目），并准备真正想知道的反问问题；
- 检查点：我能不看资料讲清自己的项目吗？
- 产出：一页准备清单。

## 模拟：在正式面试前至少做一次真实压力下的练习

- 动作：找同学或朋友按真实节奏模拟一轮，重点练「思考出声」与澄清问题；
- 检查点：模拟中我卡在哪一层（知识/表达/项目深度）？
- 产出：卡点清单。

## 现场（面试当天）

- 动作（按顺序）：
  1. 先澄清问题（输入范围、边界、规模）；
  2. 说思路再动手；
  3. 写完自测一个用例；
  4. 时间不够时先说「我的下一步是……」，保留思路完整性；
  5. 项目问题用具体数字与取舍回答。
- 检查点：我是否在卡住时仍保持沟通，让对方知道我在验证什么？
- 失败分支：完全不会 → 说出已知的相邻知识 + 我打算怎么查；不要编造。

## After：趁问题和思路还记得时尽快复盘

- 动作：填 [面试复盘表](../tools/面试复盘表.md)：问题、我的回答、卡点、改进动作；
- 检查点：每道卡住的题是否都产出了一个具体的补课项？
- 产出：补课清单（按优先级，先处理最可能再次出现的卡点）。

## Stop condition

- 多场面试反复卡在同一类型问题上 → 暂停扩大投递，先把这个结构性短板补掉；
- 面试体验明显不合理（侮辱性提问、长时间无回应）→ 直接结束，不必勉强。

## 常见失败

- 上来就写，不澄清；
- 不会时沉默或乱猜；
- 项目问题只会背结论，被追问两层就崩；
- 面试后不复盘，同类问题反复出现。
