# Playbook：第一次参加 Hackathon

## Before（会前 1–3 天）

- 动作：
  1. 组队：2–4 人，技能互补（产品/前端/后端或数据），确认赛期全天可用；
  2. 读规则：评分项、提交要求、是否允许预制代码（多数允许使用库，但禁止预制作品）；
  3. 想 2–3 个可在 24–48 小时做出闭环的题目（不要选「平台」类）；
  4. 准备环境：账号、依赖、网络、备用热点。
- 检查点：赛期最后一天全员可用吗？
- 产出：选题范围 + 分工表。

## Kickoff（赛题公布后 1 小时）

- 动作：把题目翻译成一句话问题 + 一个能演示的闭环；明确「不做什么」；
- 检查点：全员对范围达成一致了吗（复述一遍）？
- 产出：范围卡（写在共享文档里）。

## 赛期节奏

| 阶段 | 目标 | 检查点 |
| --- | --- | --- |
| 前 25% | 最小闭环跑通 | 能演示 |
| 中 45% | 核心功能 + 数据 | 有中间结果 |
| 后 20% | 打磨 + 演示脚本 | 排练一次 |
| 最后 10% | 冻结与提交 | 提交完成 |

- 纪律：主分支随时可演示；提交前留出缓冲；
- 产出：可运行原型 + 演示材料。

## 演示脚本（2 分钟）

问题（15 秒）→ 现场演示（60 秒）→ 结果（30 秒）→ 差异化（15 秒）。准备一个兜底录屏。

## After（会后 48 小时）

- 动作：归档代码与演示；写一页复盘；把原型整理成作品集条目；
- 检查点：我的产出能让别人复现吗？
- 产出：作品集条目 + 复盘。

## Stop condition

- 主流程在中期检查点仍跑不通 → 砍范围，保住最小闭环；
- 队友中途失联 → 立刻重排范围，不要等；
- 连续熬夜影响演示状态 → 强制休息，演示质量优先。
