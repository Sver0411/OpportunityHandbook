# Playbook：第一次找实习

第一次找实习最容易犯的错，是一上来就海投，然后把“没有回复”解释成自己不够好。更有效的方式是把过程拆成一个反馈循环：**先定义目标 → 准备最低可用证据 → 小批量投递 → 看漏斗 → 只修当前卡点**。

这不是固定八周计划。课程压力、城市、招聘季和岗位门槛不同，节奏会差很多；是否进入下一步，应该看检查点，而不是日历。

## 先把目标岗位收窄到能比较

先回答三个问题：

- 我投哪一类岗位，而不是“什么都可以”？
- 我能去哪座城市、每周能到岗多少天、能持续多久？
- 哪些条件是底线，哪些只是偏好？

然后收集一批**同类、同级别** JD。持续收集到新增 JD 已经很少出现新的核心要求，再用 [JD 拆解表](../tools/JD拆解表.md) 做岗位画像。

产出不是“我想做后端”，而应该是：

> 我主要投校招/实习后端；常见要求集中在 Java/Go、SQL、缓存、基础网络和项目证据；当前最大缺口是数据库与服务端项目。

如果你同时整理出来“后端、产品、算法、运营”四套完全不同的要求，说明目标仍然太散。

## 做出一份“最低可投”证据包

第一次实习不需要等到“准备完全”。你至少需要：

- 一页能看懂的简历；
- 一到两个能被追问的项目、课程成果、科研或竞赛经历；
- 能证明基础能力的具体证据：代码、报告、Demo、数据、作品链接；
- 一段能讲清楚“我做了什么、为什么这样做、结果怎样”的项目表达。

如果目前只有教程项目，不要重新学一大堆课。先把一个项目按 [从教程 Demo 到真正作品](../projects/从教程到作品.md) 做到可以展示。

**进入下一步的检查点**：陌生人只看你的简历和链接，能不能在几分钟内知道你想投什么、做过什么、最强的证据是什么？

## 第一轮投递要小到能复盘

不要一口气把所有心仪公司投完。先选一批代表性岗位，刻意保留后续选择。记录：

- 公司 / 岗位 / 来源；
- 简历版本；
- 投递日期；
- 当前状态；
- 是否有回复、测评、面试；
- 被问到什么。

第一轮的目标不是证明“我能拿 Offer”，而是获取真实反馈。

### 反馈怎么解释

- **几乎没有回复**：先查定位、简历第一屏、硬门槛、项目证据；
- **能进面试但频繁一面挂**：问题多半已经从简历转到基础知识、项目追问或表达；
- **能到后段但拿不到 Offer**：重点看岗位匹配、综合判断、竞争者差异和面试稳定性；
- **有 Offer 但都不想去**：可能是筛选条件或投递池出了问题，而不是“求职成功”。

用 [求职漏斗诊断表](../tools/求职漏斗诊断表.md) 记录，不要只凭情绪判断。

## 只有当前卡点值得优先修

假设你已经能进面试，但觉得自己的 Redis 不够熟。此时继续重写简历意义不大；应该准备 Redis 相关的真实场景和追问。

反过来，如果几十次投递都没有进入面试，却一直刷算法题，也可能是在优化错误的环节。

一个简单规则：

> **每轮只改最可能影响下一步转化的一到两件事，然后再投一批验证。**

这样你能知道改动是否有效。

## 面试准备围绕“被追问的证据”

第一次面试前至少准备：

- 自我介绍：重点不是背稿，而是让对方知道你的方向和最值得问的经历；
- 项目追问：问题、你的贡献、方案选择、测试、失败、重做；
- 基础知识：围绕岗位高频要求补到能解释，不追求“题库全部刷完”；
- 一次模拟：让别人连续追问项目，找你讲不清的地方。

每场结束后尽快记下问题、卡住的位置和更好的回答。见 [面试复盘表](../tools/面试复盘表.md)。

## 没有实习经历时怎么打开第一扇门

可以降低的是**组织规模、品牌和岗位光环**，不一定要降低学习价值。常见入口包括：

- 小团队或创业公司，但要确认有人能给反馈；
- 实验室、校内技术团队、开源社区形成的真实交付；
- 行业相关的短期项目；
- 目标岗位相邻的 bridge role。

判断标准仍然是：能不能接触真实问题、得到反馈、留下可验证成果。

## 什么时候应该停下来重新定位

如果你已经经历了多轮有记录的投递和修改，仍然完全进不了目标岗位流程，就不要继续无差别加量。重新核对：

1. 是否存在没有满足的硬门槛；
2. 岗位是不是比当前水平高了一个完整层级；
3. 方向是否过窄，导致有效岗位太少；
4. 你的证据是否和岗位真正相关；
5. 是否需要先走一个相邻岗位或项目作为桥梁。

“停下来重新定位”不是放弃，而是避免把重复失败误当坚持。

## 收尾：拿到 Offer 以后仍然要核实

至少确认：实际职责、到岗安排、实习时长、补贴、导师/汇报对象、是否有转正机会及其条件、协议中的违约或保密条款。

口头说法和书面协议不一致时，以能留痕的正式信息为准。
