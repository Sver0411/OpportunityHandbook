# Playbook：第一次做实验与记录
## Before（写计划）

- 动作：
  1. 把假设写成可证伪的句子（「如果 X，则 Y 会从 A 变到 B」）；
  2. 列出自变量、因变量、控制变量；
  3. 定对照组与重复次数；
  4. 写下记录模板（见 [实验记录模板](../tools/实验记录模板.md)）。
- 检查点：什么结果会证明我的假设错了？
- 产出：一页实验计划。

## 执行（每次运行都记录）

- 动作：记录配置、随机种子、时间、环境、异常；**失败的运行也要记**；
- 检查点：三个月后我能凭记录复现这次运行吗？
- 失败分支：结果明显异常 → 先怀疑输入与配置（见 [如何 Debug](../learning/调试方法.md) 的思路），再怀疑方法。

## 对照与验证

- 至少一个对照条件（不作处理/旧方法）；
- 关键结果重复 3 次以上，报告均值与波动；
- 有条件时做一次消融，确认是哪一部分起作用（见 [Ablation 怎么设计](../research-deep/消融实验.md)）。

## 数据整理

- 原始数据保留不动，另建清洗后的版本；
- 每条结论能追到具体的运行记录；
- 定一个固定的指标口径，写下来，跑完不改。

## 汇报

- 结构：问题 → 方法 → 结果（含波动）→ 限制 → 下一步；
- 主动讲失败的运行与原因（这通常是导师最关心的部分）；
- 检查点：我有没有把「不显著」如实说出？

## Stop condition

- 连续多次结果不稳定 → 停下来查流程（划分、泄漏、随机性），不要加大投入；
- 结果支持不了原假设 → 改写主张（缩小范围），而不是继续调参凑结果。

## 动手前先确认三件事

实验最常见的两种失败，都不是方法问题，而是前提不成立。开始之前先确认：

- **数据 / 样本拿得到吗**：需要申请的、需要合作方提供的、有保密限制的，先去走流程，不要等设计完了才发现数据要等三个月；
- **算力与设备够用吗**：跑一次要多久、能不能重复 3 次、有没有备用方案（机器被占、设备故障）；
- **导师知道你在做什么吗**：不是要审批，而是确认方向没跑偏——不少返工来自「做完才发现这不是组里关心的方向」。

三件事里任何一件没底，先把那件事解决，再开实验。**计划做得漂亮但前提不成立，是最常见的浪费。**
