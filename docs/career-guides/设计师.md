# 设计师（交互 / 视觉 / 工业）
用一句话概括：用**方案与过程**解决用户在具体场景里的问题——好看只是必要条件之一。

## 三类方向的差别

| 方向 | 主要产出 | 关键能力 |
| --- | --- | --- |
| 交互 / UX | 流程、原型、信息结构 | 用户研究、逻辑、可用性 |
| 视觉 / UI | 界面、视觉规范、设计系统 | 排版、色彩、一致性 |
| 工业设计 | 外观与结构方案、量产可行性 | 造型、材料工艺、结构约束 |

## 从视觉交付到定义体验问题

- 初级：执行具体设计任务、维护规范；
- 中级：独立负责模块、参与用户研究、推动方案落地；
- 资深：定义体验方向、建立设计系统、带人。

## 产品、研发、研究和设计的接口

与产品、研发、运营协作。与产品的边界：产品定义要解决的问题与优先级，设计负责方案与体验质量。

## 作品集为什么比工具列表重要

- 硬技能：工具（Figma 等）、研究方法、视觉基础；
- 关键：**作品集**——不是成品堆砌，而是过程（问题 → 探索 → 取舍 → 结果）；
- 学历：门槛不高，作品决定一切。

## 作品集与面试怎么准备

- 一个项目讲清：背景与约束、你做过的探索（含被淘汰的方案）、最终方案的理由、上线结果与限制；
- 面试考法：逐页问「为什么这么做」「为什么不用另一种」、现场设计题（给你一个场景，30 分钟出方案）；
- 高频失分点：只说「好看」，不说决策依据。

## 第一份设计工作要不要能接触真实反馈

看是否有真实用户反馈与设计评审文化（只做报价单式的接单，成长慢）。

## 设计之后的专业、管理与产品分叉

设计负责人、产品设计方向、用户研究方向、独立设计（接单/产品化）、转产品。

## “作品好看”为什么不等于设计能力

- 把设计等同于美化（真正的工作是取舍与验证）；
- 作品集只有成品效果图；
- 不参与需求讨论，被动接稿。

## 选一个真实流程做一轮研究—设计—验证

选一个真实存在不好用的界面，做一次改版设计：用户问题 → 方案 → 验证（找三人试用）→ 复盘。


## 作品集真正展示的是“判断过程”，不是最终图

不论交互、视觉还是工业设计，最终稿只证明你会做一个结果。真正能区分设计能力的是：问题怎么定义、约束是什么、你探索过哪些方向、为什么删掉某个方案、用户/业务/工程反馈如何改变设计。

## 一个案例页应该怎么讲

比“背景—过程—结果”更有信息量的是：

问题 → 关键约束 → 证据 → 设计假设 → 方案分歧 → 验证 → 迭代 → 最终结果 → 未解决问题。

例如交互设计不要只放 wireframe。应该讲：
- 用户在哪一步卡住；
- 你如何知道；
- 为什么不是改文案就够；
- 设计改动如何验证；
- 指标/访谈反馈有没有变化。

## 三类设计岗位的证据不同

视觉更看审美系统与信息表达；交互/UX 更看研究、流程与行为；工业设计还要面对材料、结构、制造和成本。不要用同一种作品集结构强行套。

## 与产品和研发协作是工作的一部分

一个“设计上最优”的方案，如果研发成本太高或业务价值低，未必应该做。成熟设计师会保留核心体验，同时理解技术与商业边界。

面试时准备一件“设计被否掉”的经历，讲清你怎样重新定义问题，比只讲成功案例更有价值。
