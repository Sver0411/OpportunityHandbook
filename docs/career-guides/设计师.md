# 设计师（交互 / 视觉 / 工业）
用一句话概括：用**方案与过程**解决用户在具体场景里的问题——好看只是必要条件之一。

## 三类方向的差别

| 方向 | 主要产出 | 关键能力 |
| --- | --- | --- |
| 交互 / UX | 流程、原型、信息结构 | 用户研究、逻辑、可用性 |
| 视觉 / UI | 界面、视觉规范、设计系统 | 排版、色彩、一致性 |
| 工业设计 | 外观与结构方案、量产可行性 | 造型、材料工艺、结构约束 |

## 日常与层级

- 初级：执行具体设计任务、维护规范；
- 中级：独立负责模块、参与用户研究、推动方案落地；
- 资深：定义体验方向、建立设计系统、带人。

## 团队与相邻岗位

与产品、研发、运营协作。与产品的边界：产品定义要解决的问题与优先级，设计负责方案与体验质量。

## 招聘与门槛

- 硬技能：工具（Figma 等）、研究方法、视觉基础；
- 关键：**作品集**——不是成品堆砌，而是过程（问题 → 探索 → 取舍 → 结果）；
- 学历：门槛不高，作品决定一切。

## 作品集与面试怎么准备

- 一个项目讲清：背景与约束、你做过的探索（含被淘汰的方案）、最终方案的理由、上线结果与限制；
- 面试考法：逐页问「为什么这么做」「为什么不用另一种」、现场设计题（给你一个场景，30 分钟出方案）；
- 高频失分点：只说「好看」，不说决策依据。

## 第一份工作怎么看

看是否有真实用户反馈与设计评审文化（只做报价单式的接单，成长慢）。

## 3–5 年出口

设计负责人、产品设计方向、用户研究方向、独立设计（接单/产品化）、转产品。

## 常见误区

- 把设计等同于美化（真正的工作是取舍与验证）；
- 作品集只有成品效果图；
- 不参与需求讨论，被动接稿。

## 低成本试法

选一个真实存在不好用的界面，做一次改版设计：用户问题 → 方案 → 验证（找三人试用）→ 复盘。

## 一天通常是这样的

| 时间 | 做什么 | 备注 |
| --- | --- | --- |
| 10:00 | 与产品过需求：用户是谁、要解决什么、约束是什么 | 先对齐问题 |
| 10:30 | 画三个方向的草图（保守 / 折中 / 激进） | 先发散再收敛 |
| 13:30 | 与研发确认技术边界（动效、性能、字段） | 早问省返工 |
| 14:30–17:00 | 做中保真原型，走一遍完整流程（含空态与错误态） | 边界状态必画 |
| 17:00 | 找 3 位同事试走原型，记录卡点 | 20 分钟就有反馈 |
| 17:30 | 按反馈改一版，把被淘汰的方案也留存 | 过程是作品集素材 |

## 一次面试追问的典型走向

下面这段按面试与复盘里常见的追问整理，用来说明答法的结构，不是某位候选人的原话。

> **面试官**：这个方案为什么这么排？
> **候选人**：我们访谈的 8 位用户里，6 位第一眼找的是「最近的订单」而不是「全部订单」，所以把时效性最强的内容放在首屏。
>
> **面试官**：你淘汰了哪个方案？为什么？
> **候选人**：还有一个「按状态分组」的方案，测试时用户要来回切换，完成时间比现在长 40%，所以放弃了。
>
> **面试官**：如果产品坚持要那个方案呢？
> **候选人**：我会把两版原型都做出来做一次 5 人对比测试，用数据说话；如果结论仍不同，就按产品判断执行，但把我的顾虑和验证方式写进文档。

**要点**：设计面试考**取舍依据**与**验证方式**，「好看」不是答案。

## 设计作品集不是漂亮截图集

面试官要看你如何定义问题、做取舍、迭代和验证。一个完整 Case Study 应该能回答：目标是什么、你掌握了什么证据、有哪些方案、为什么选这个、验证后改了什么。最终视觉只是结果的一部分。

## 不同设计岗位关注点不同

交互更看流程、信息架构和可用性；视觉更看体系、品牌与表达；工业设计还要面对材料、结构、制造和人体工学。不要用同一份作品集同时证明所有能力。

## 评价自己的项目

把成品遮住，只看过程页。如果别人仍然能判断你做了哪些关键决策，这个案例才有职业价值。
