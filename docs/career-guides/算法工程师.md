# 算法工程师

用一句话概括：用模型或规则**把某个指标做上去**，并对它在真实数据上的表现负责。

## 两类岗位（差别很大）

| | 研究型 | 工程型 |
| --- | --- | --- |
| 目标 | 提出新方法、发论文/专利 | 把已有方法落地、优化效果与成本 |
| 日常 | 读论文、设计实验、写作 | 数据管道、训练/推理优化、上线与监控 |
| 证据 | 论文、实验结论 | 线上指标、性能与成本数字 |
| 门槛 | 硕士/博士为主 | 本科可入，看工程能力 |

求职时先确认目标岗位属哪一类——两者的准备方式完全不同。

## 常见岗位名称

算法工程师、机器学习工程师、CV/NLP/推荐算法、数据科学家、研究工程师（见 [Research Engineer](研究工程师.md)）。

## 招聘与门槛

- 硬技能：数学与统计基础、编程（Python）、深度学习框架、数据处理；
- 加分：竞赛名次、论文、开源实现、线上项目经验；
- 学历：研究型岗位普遍要求硕士及以上；工程型岗位对学历要求相对宽松。

## 项目与面试怎么准备

- 证据：**基线对比**、消融、数据划分说明、可复现脚本、失效样例（见 [工程项目的测试、指标与证据](../projects/测试与指标体系.md)）；
- 面试考法：编程题 + 机器学习基础 + 项目追问（数据、指标、失败）+ 部分岗位有论文讨论；
- 一个高频追问：「你的提升来自哪里？」——需要消融证据，不能只报数字。

## 第一份工作怎么看

看有没有真实数据与线上反馈（只做离线实验的岗位，成长会慢）。

## 3–5 年出口

研究工程师、算法负责人、数据科学方向、转工程（性能与系统能力）、创业。

## 常见误判

- 只看模型不看数据质量与成本；
- 用单一指标代表全部效果；
- 忽视工程能力（不会写可维护代码的算法岗上限有限）。

## 低成本试法

用公开数据做一次完整流程：基线 → 改进 → 消融 → 报告，并写清限制。这比再刷一门课有用。


## “算法岗”内部差异比职位名更大

推荐、搜索、广告、CV、NLP、语音、风控、运筹优化都可能叫算法工程师，但真正工作重心差很多。有的团队主要做模型与指标，有的团队更像机器学习工程，更多时间在数据、特征、推理链路和线上实验。

所以看岗位时至少继续确认三件事：主要目标指标是什么、模型离线上线有多远、工程平台由谁负责。只看“算法工程师”四个字很容易误判。

## 一个模型从论文到线上要经过什么

真实链路通常是：

问题定义 → 数据与标签 → baseline → 训练 → 离线评估 → 误差分析 → 消融/敏感性 → 推理成本 → 线上实验 → 监控漂移 → 迭代。

任何一步做弱，最后都可能出现“离线很好、上线没用”。因此项目不要只报一个 accuracy。至少要能解释：
- 数据从哪里来、有什么偏差；
- baseline 为什么公平；
- 主要错误集中在哪些样本；
- 指标和业务目标是否一致；
- 推理延迟和成本是否能接受；
- 上线后如何知道模型失效。

## 研究能力和工程能力怎么配

如果岗位偏研究，论文阅读、实验设计、数学与新方法能力更重要；如果偏应用，数据、系统、部署和迭代速度更重要。很多应届生的问题不是“算法不够深”，而是只有 notebook，没有把模型推进到可重复、可部署、可监控的状态。

一个好的作品可以故意把“模型 SOTA”放到次要位置，展示从 baseline、数据清洗、错误分析到部署后的完整证据链。

## 面试前应该准备哪类故事

至少准备一件“模型没有按预期工作”的经历。讲清楚你如何判断是数据、实现、评估口径还是方法本身的问题。这个过程往往比最终提升了几个点更能体现研究与工程判断。
