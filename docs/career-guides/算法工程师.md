# 算法工程师

用一句话概括：用模型或规则**把某个指标做上去**，并对它在真实数据上的表现负责。

## 两类岗位（差别很大）

| | 研究型 | 工程型 |
| --- | --- | --- |
| 目标 | 提出新方法、发论文/专利 | 把已有方法落地、优化效果与成本 |
| 日常 | 读论文、设计实验、写作 | 数据管道、训练/推理优化、上线与监控 |
| 证据 | 论文、实验结论 | 线上指标、性能与成本数字 |
| 门槛 | 硕士/博士为主 | 本科可入，看工程能力 |

求职时先确认目标岗位属哪一类——两者的准备方式完全不同。

## 常见岗位名称

算法工程师、机器学习工程师、CV/NLP/推荐算法、数据科学家、研究工程师（见 [Research Engineer](研究工程师.md)）。

## 招聘与门槛

- 硬技能：数学与统计基础、编程（Python）、深度学习框架、数据处理；
- 加分：竞赛名次、论文、开源实现、线上项目经验；
- 学历：研究型岗位普遍要求硕士及以上；工程型岗位对学历要求相对宽松。

## 项目与面试怎么准备

- 证据：**基线对比**、消融、数据划分说明、可复现脚本、失效样例（见 [工程项目的测试、指标与证据](../projects/测试与指标体系.md)）；
- 面试考法：编程题 + 机器学习基础 + 项目追问（数据、指标、失败）+ 部分岗位有论文讨论；
- 一个高频追问：「你的提升来自哪里？」——需要消融证据，不能只报数字。

## 第一份工作怎么看

看有没有真实数据与线上反馈（只做离线实验的岗位，成长会慢）。

## 3–5 年出口

研究工程师、算法负责人、数据科学方向、转工程（性能与系统能力）、创业。

## 常见误区

- 只看模型不看数据质量与成本；
- 用单一指标代表全部效果；
- 忽视工程能力（不会写可维护代码的算法岗上限有限）。

## 低成本试法

用公开数据做一次完整流程：基线 → 改进 → 消融 → 报告，并写清限制。这比再刷一门课有用。

## 一天通常是这样的

| 时间 | 做什么 | 备注 |
| --- | --- | --- |
| 10:00 | 看昨天实验的结果：加了新特征但召回降了 0.8 个点 | 先看数据分布 |
| 10:30 | 检查数据划分与预处理顺序 | 排除泄漏 |
| 11:30–12:00 | 跑消融：去掉新特征、去掉重加权 | 一次只改一项 |
| 14:00–16:00 | 定位到样本极少的类别被过度采样，改为分层验证 | 结论随证据改 |
| 16:00–17:00 | 更新实验记录与图表 | 口径先写后跑 |
| 17:00 | 与工程同学对齐上线指标与监控 | 离线好不等于线上好 |

## 一次真实的面试问答（原话）

> **面试官**：你说提升 3 个点，和谁比？
> **候选人**：和两个基线比：多数类基线，以及这版官方实现。同样数据划分、同样调参预算。
>
> **面试官**：提升主要来自哪里？
> **候选人**：消融显示重加权贡献 2.1 个点，新损失函数贡献 0.6，剩下的来自随机波动——所以我只把重加权写进了结论。
>
> **面试官**：换个数据集还成立吗？
> **候选人**：在另一个公开数据集上只提升 0.4 个点，方向一致但幅度小很多，我把它写进了限制里。

**要点**：算法面试最常见的问题就是「提升来自哪里」与「换了数据还成立吗」，需要消融与多数据集证据。

## 算法岗首先是“把指标变成业务结果”

训练出更高分不等于工作完成。先弄清标签如何产生、离线指标和线上目标是否一致、误报与漏报谁更贵、数据分布是否变化。一个模型从 notebook 到生产还要经历数据版本、预处理一致性、推理成本、监控、回滚和持续评估。

## 面试真正想确认的三个层次

第一层是基础：模型、优化、概率统计；第二层是实验判断：为什么这个 baseline、公平不公平、结果波动怎么解释；第三层是工程落地：吞吐、延迟、显存、部署、数据漂移。只会讲模型结构，很容易在第二层停住。

## 一个项目怎么做得可信

先给简单 baseline，再固定数据切分和随机性，报告多个有意义指标与失败样例；最后明确“在哪些条件下不如简单方法”。这比只放一个最好准确率更接近真实算法工作。
