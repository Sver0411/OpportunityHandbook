# 后端工程师

用一句话概括：让系统在真实流量与故障下**稳定地给出正确结果**。

## 日常与层级

| 层级 | 主要工作 |
| --- | --- |
| 初级 | 写接口、修缺陷、写测试、查日志 |
| 中级 | 模块设计、数据结构与索引、性能优化、参与容量评估 |
| 资深 | 系统设计、一致性与可用性取舍、跨团队方案、事故处理 |

真实工作里，「设计新功能」大概只占一半，其余是排查、优化、兼容与协作。

## 团队与相邻岗位

与前端、产品、测试、运维、数据协作。与运维/SRE 的边界：后端负责业务系统的正确与性能，SRE 负责基础设施、发布体系与整体稳定性。与数据工程的边界：在线事务系统属后端，离线管道与仓库属数据工程。

## 常见岗位名称

后端开发、服务端工程师、Java/Go 后端、业务后端、交易/支付/风控后端。

## 招聘与门槛

- 硬技能：语言 + 数据库（索引、事务）+ 缓存 + 网络基础 + 并发基础；
- 加分：消息队列、分布式基础、可观测性工具；
- 学历：校招初筛用，社招弱化。

## 项目与面试怎么准备

- 证据：接口性能数据（P95、并发）、一次故障处理记录、测试覆盖关键路径；
- 面试考法：编程题 + 数据库与并发知识 + 项目追问 + 系统设计（初中级可能不问）；
- 系统设计的答法：澄清需求 → 规模估算 → 数据模型 → 核心流程 → 瓶颈与取舍（见 [技术面试全流程](../job-search/技术面试.md)）。

## 第一份工作怎么看

优先选有真实流量、有线上值班（哪怕只跟不独立）、有评审文化的团队。

## 3–5 年出口

架构方向、SRE/平台方向、数据工程、技术管理、转产品（懂系统的产品有优势）。

## 常见误判

- 只写业务逻辑，不关心数据与容量；
- 认为「框架会用」等于「系统会设计」；
- 忽略日志与监控——排障能力是后端的分水岭。

## 低成本试法

用两周做一个带真实输入的小服务：加索引、压一次、记录 P95，再故意注入一次依赖超时看系统表现。
