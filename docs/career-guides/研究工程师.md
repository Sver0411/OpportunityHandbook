# Research Engineer

用一句话概括：**把研究想法变成可靠的系统**——既懂论文，也懂工程。

## 日常与层级

| 层级 | 主要工作 |
| --- | --- |
| 初级 | 复现论文方法、搭建实验与训练管道 |
| 中级 | 优化训练/推理效率、把方法集成进产品链路 |
| 资深 | 定义技术路线、评估新方向可行性、跨团队推动 |

与算法岗的区别：算法岗更关注指标与模型设计，研究工程师更关注**实现质量、效率、可复现与集成**。与研究岗的区别：研究岗以产出新知识为主（论文），研究工程师以产出可用系统为主。

## 团队与相邻岗位

多在企业研究院或工程团队，与研究员、算法、平台工程协作。

## 常见岗位名称

Research Engineer、机器学习工程师（偏工程）、Applied Scientist（部分公司）、研发工程师（研究院）。

## 招聘与门槛

- 硬技能：编程能力（不弱于软件工程师）、深度学习框架、分布式训练或推理优化基础；
- 加分：复现过论文、开源实现、性能优化案例；
- 学历：硕士为主，部分岗位接受优秀本科。

## 项目与面试怎么准备

- 证据：一次完整复现（含与原论文的差异说明）、一份性能优化记录（吞吐/延迟/成本）、可复现的代码仓库；
- 面试考法：编程题 + 系统/效率问题 + 论文或复现经历追问；
- 高频追问：「你复现时差了 1.2 个点，最后定位到什么？」——过程比结论重要。

## 第一份工作怎么看

看是否有真实规模的数据与算力、是否允许做实验性尝试。

## 3–5 年出口

研究员方向、模型与系统架构、创业（研究 + 工程的组合适合做产品）。

## 常见误判

- 以为「会跑实验」就够了（工程能力是硬门槛）；
- 只追新方法，不关心成本与稳定性；
- 忽视写作与表达（跨团队推动需要讲清楚）。

## 低成本试法

选一篇有开源数据的论文做完整复现，记录差距与原因，并写成一页报告。


## Research Engineer 真正站在“研究不确定性”和“工程确定性”的交界处

研究员可以接受“这个方向也许不成立”，产品工程却要求系统按时运行。Research Engineer 经常要把两种节奏接起来：一边快速验证论文想法，一边保证实验、数据和训练基础设施足够可靠。

## 一次研究工程工作怎么展开

常见链路是：

论文/idea → 复现 → 建立可信 baseline → 训练/推理管道 → 性能瓶颈 → 大规模实验 → 结果审计 → 工程化 → 给研究员新的反馈。

这里最有价值的能力是：**知道什么时候结果差是“研究问题”，什么时候只是“工程实现有 bug”。**

例如复现差 1 个点，不应该立刻调参。先检查数据版本、预处理、随机种子、实现差异和评估口径。

## 工程深度要到什么程度

不是只会 PyTorch。更接近岗位要求的能力包括：
- 能读 profiler；
- 能定位 GPU/CPU/IO 瓶颈；
- 能设计可复现实验配置；
- 能管理 checkpoint 与数据版本；
- 能把离线实验做成稳定 pipeline；
- 能在成本、吞吐、延迟之间做取舍。

## 什么项目最能证明能力

做一次“论文复现 + 工程化”：
- 跑出 baseline；
- 记录与论文差异；
- 找一个真实瓶颈；
- 做 profiling；
- 优化吞吐/显存/延迟；
- 加实验配置与自动化；
- 写一份复现与性能报告。

这比“训练过某模型”更贴近 Research Engineer。
