# 如何读官方文档

文档不是书，不能从头读到尾。它是一张地图，你按目的取用。

## 六类内容的用法

| 部分 | 回答什么 | 什么时候看 |
| --- | --- | --- |
| Quick Start | 怎么最快跑起来 | 第一次接触，先跑通 |
| Concepts / Guide | 为什么这样设计、核心概念关系 | 跑通之后，理解机制 |
| API / Reference | 每个参数与返回值的确切含义 | 写代码时逐个核对 |
| Examples / Cookbook | 常见用法的完整写法 | 卡住时找相似场景 |
| Changelog / Release Notes | 版本间变化、废弃项 | 升级、报错怀疑是版本问题 |
| Issues / Discussions | 别人的同类问题 | 官方文档查不到时 |

## 推荐的读法顺序

1. **Quick Start 跑通**：先获得一次成功体验，建立最小上下文；
2. **Concepts 画一张结构图**：把模块、数据、调用关系画下来（三五个方块就够）；
3. **只看你需要的 API**：不要通读 reference；
4. **抄一个 Example 再改**：改参数、改输入，看行为如何变化；
5. **遇错查 Changelog 与 Issues**：很多「文档没写」其实是版本变化。

## 遇到报错时的检索路径

1. 读完整错误信息（包括堆栈最底部的第一行原因）；
2. 复制错误里的**关键短语**（去掉路径与变量名）搜索；
3. 限定官方源：搜索时加 `site:` 官方域名，或直接在 Issues 里搜；
4. 确认版本：你的版本与示例的版本是否一致；
5. 构造最小复现：把出问题的代码缩到 10 行内，很多问题在这一步就暴露；
6. 查不到就提 issue：附版本、最小复现、期望与实际。

## 把文档变成清单

读文档的产出不是「读过了」，而是**一份可执行的清单**：这个库的正确初始化顺序是什么？必填参数有哪些？常见坑是什么？把它写进项目 README 的「Known Limitations」或内部笔记。

## 自检

- 我能不能画出这个库的结构图？
- 我遇到的报错，是否先确认过版本差异？
- 我有一个 10 行以内的最小复现吗？
