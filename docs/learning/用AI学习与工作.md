# 用 AI 学习与工作

AI 已经是默认工具，问题不再是「要不要用」，而是**哪些事交出去是杠杆，哪些交出去是自废**。

## 一条判断标准

**交出去之后，你还能不能自己判断结果对不对？**

能，就大胆交（检索、整理、起草、翻译、格式转换、写测试样例）。不能，就先自己走一遍再考虑用它——因为在关键处失去判断力，等于把风险转移给了未来的自己。

| 场景 | 建议 | 理由 |
| --- | --- | --- |
| 检索与整理资料 | 用，但要核对来源 | 快，但会把不存在的引用说得像真的 |
| 起草初稿（邮件、方案、报告） | 用，自己重写一遍 | 结构可借，事实与立场必须自己定 |
| 学新概念 | 用，但要求它给例题与反例 | 解释得越流畅，越容易被误当成已掌握 |
| 写代码 | 用，但必须能讲清每一行 | 看不懂的代码会成为未来的故障源 |
| 考试、面试、论文的核心产出 | 不用 | 这是你被评价的部分；代做终会在提问环节暴露（见 [避坑](../../book/15-避坑.md#trap-ai-shortcut)） |
| 涉及医疗、法律、财务的结论 | 只用来理解术语 | 它给不出个案判断，也承担不了责任 |

## 怎么问才有效

- **给背景与约束**：说明你的基础、目标、可用时间与已有材料，输出质量立刻不同；
- **要它先提问**：让它就你的情况提 5 个问题再给建议，比直接要答案更准；
- **分段推进**：一次只要一件事（先列框架，再逐节写），比一次要成品更可控；
- **要求给出处与不确定性**：明确说「不确定的地方标出来」，并把它标出的地方当作重点核实对象。

## 怎么验证

1. **交叉核对**：关键事实至少用两个独立来源确认（官方文件优先）；
2. **要求可证伪**：让它说清「什么情况下这个结论是错的」；
3. **算一遍**：涉及数字时自己复算，AI 的算术错误并不罕见；
4. **留痕**：把「我用的提示词、我改了什么」记下来，复现与复盘都靠它。

## 什么时候要谨慎

- 不要上传包含他人隐私、公司机密、未公开数据的内容到公开服务；先看单位的合规要求；
- 越是「说得圆满」的输出，越要问它依据是什么；流畅不等于正确；
- 长期只读它的总结，会缓慢削弱你读原始材料的能力——每周留一部分时间直接读原文；
- 本页不评价具体产品；工具会持续变化，方法比工具稳定。
