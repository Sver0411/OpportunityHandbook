# 从零学一项技术（三种类型）

技术学习失败通常不是因为难，而是因为**没有验收标准**。「学完了」这句话没有意义，有意义的是「我能独立做出 X」。

## 通用结构（三类都适用）

1. 用 20 小时做一次最小可用尝试，判断自己是否愿意继续；
2. 用一个**能演示的小项目**作为第一阶段的终点；
3. 每阶段都用「能不能独立复现」检验，而不是「看完了多少课」；
4. 卡住超过两小时就换路径：查文档、最小复现、问人。

## 类型一：编程语言 / 框架

- **路径**：语法（1 周）→ 官方教程跑通 → 改写教程示例 → 自己写一个 200 行的小工具；
- **最小可用项目**：读一个本地文件、处理后输出结果，带错误处理；
- **检验点**：关掉教程能写出核心流程；遇到报错能自己定位；
- **卡点**：一直看视频不写代码；一上来做「完整系统」；
- **跳出方式**：把目标缩小到「今天只完成一个函数」。

## 类型二：数据分析 / 统计

- **路径**：会用工具（表格/Notebook）→ 懂指标口径 → 会做一个完整分析（问题→数据→结论）；
- **最小可用项目**：用公开数据回答一个你自己关心的问题，写出结论与限制；
- **检验点**：能说清「这个数字怎么算出来的」「样本有哪些偏差」；
- **卡点**：沉迷工具与可视化，不定义问题；把相关性当因果；
- **跳出方式**：先写一句结论再找数据，避免无目的探索。

## 类型三：嵌入式 / 硬件

- **路径**：点亮 → 读传感器 → 通信 → 长时间运行 → 低功耗；
- **最小可用项目**：一块开发板 + 一个传感器 + 一次稳定上报，持续运行 24 小时；
- **检验点**：能解释每个引脚的接法；能自己排查「不亮/不连/重启」；
- **卡点**：只看文档不动手；一次接太多模块导致故障无法定位；
- **跳出方式**：每次只加一个新变量，出问题立刻回退到上一个可用状态。

## 三类共同的三个检验

- **独立复现**：关掉教程，从零做出同样的结果；
- **解释取舍**：为什么用这个方案而不是另一个；
- **说清边界**：这个方法在什么条件下会失效。

## 自检

- 我这一阶段的可演示产出是什么？
- 卡住时我的两小时规则用了吗？
- 我能不能向别人解释「为什么这么做」？
